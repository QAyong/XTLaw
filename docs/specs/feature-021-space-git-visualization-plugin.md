# Spec-021：当前空间 Git 可视化与基础操作插件

**日期：** 2026-10-05

**状态：** 草案，未实现、未验收；已确认迁移优先并保留基础 Git 操作

**归属：** 个人功能规格；本轮仅维护文档，不修改插件协议或运行代码。

## 1. 背景与目标

用户在 Lexora 中编写代码时，希望通过插件查看当前空间（或当前文件所属仓库）的 Git 信息，并完成基础 Git 操作，而不必切换到其他 Git 客户端。

**已确认方向：** 优先迁移许可证允许的现成 Git 面板，保留切换分支、合并、变基、重置、推送；Lexora 主要补宿主适配与必要防护，不默认重新实现提交图、界面和全部 Git 逻辑。Git Graph+ 是第一迁移候选，尚未证明能直接接入。只读链路是实施中的验证阶段，不是最终产品边界。

第一眼应能回答：

- 当前查看的是哪个仓库？
- 当前处于哪个分支，`HEAD`（当前检出的提交指针）指向哪个提交？
- 工作区是否有未提交修改？
- 最近提交之间如何分叉、合并？

“当前版本”不能仅用分支名表示，应同时展示当前提交及工作区修改状态。有未提交修改时，本机代码不完全等于该提交。标签是补充信息，不应把任意标签误认为当前版本。

## 2. 需求边界

### 第一版包含：Git 面板与基础操作

- 从当前空间上下文定位所属 Git 仓库。
- 显示仓库名称、当前分支、当前提交短哈希及直接指向该提交的标签。
- 显示未提交变更文件数量；统计口径明确区分暂存、未暂存、未跟踪，汇总时按路径去重。
- 展示最近最多 100 条提交，以及父子、分叉、合并关系；当前 HEAD 不在结果中时明确提示，不误标其他提交为当前版本。
- 默认纳入本地分支和本地已有的远端跟踪引用；浏览、刷新不隐式联网，不自动执行 fetch（获取远端数据）。
- 点击提交查看完整哈希、作者、时间、提交说明；选择提交本身不修改仓库。
- 保留用户确认的切换分支、合并、变基、重置、推送，通过明确操作入口执行。支持方式优先沿用迁移项目，经宿主适配后逐项验证，不以隐藏按钮代替宿主权限控制。
- 对变基/合并的冲突提供明确状态与继续/中止入口；不要求第一版自建完整冲突编辑器，可提示在现有编辑器处理冲突后继续。
- 推送由用户明确触发，显示远端、分支及普通/强制方式；认证优先兼容本机 Git 的凭据助手，不能依赖 VS Code 专属认证桥接而宣称已支持。
- 对高风险操作展示影响并确认；包括硬重置和强制推送。强制推送优先采用 `--force-with-lease`（检查远端预期状态），不默认裸 `--force`（无租约保护的强制推送）。
- 提供手动刷新、操作后刷新、切换空间加载，以及操作中、失败、冲突、超时等反馈。
- 明暗主题适配、窄分屏布局及明确的加载/失败/空状态。

### 独立后续交付：聊天引用

- 保留文字选区右键“引用到对话”和详情区“引用此提交”的需求，添加到既有引用附件区。
- 复用 Spec-013 的公共目标路由、引用卡片、发送和历史通路；通用插件引用桥接仍需补齐，不视为已有能力。
- 引用作为独立交付与验收项，不阻塞 Git 面板及基础操作第一版。桥接完成前不展示可用的引用入口，也不以剪贴板或宿主 DOM 穿透替代。

### 第一版不要求

- 暂存、提交、revert（生成反向提交）、cherry-pick（挑选提交）、stash（储藏修改）、Git Flow、LFS 等额外操作；不能仅因上游已有就自动扩大交付范围。
- 手动 fetch/pull（获取/拉取）的独立入口、定时自动获取、远端实时状态，以及自建凭据存储、认证代理或登录界面；其中推送认证兼容性仍属于第一版验证范围。
- 完整文件差异浏览、逐文件历史、提交比较或三方冲突编辑器。基础操作所需的影响说明和冲突状态不在此排除项内。
- 文件系统实时监听、无限滚动或完整历史分页。
- 将非 Git 目录自动初始化为仓库。
- 扫描整个空间寻找所有嵌套仓库；多仓库选择器留待后续定义。

引用交付仍不包含自动发送、自动生成问题、自动新建任务、抢占焦点、专属评论框、整份仓库状态/批量提交引用或自动附带 Diff（文件差异）/文件内容。长文本不拼入正文，不通过系统剪贴板中转引用。

当前文件所属仓库入口、变更文件列表、远端领先/落后数量作为后续扩展，不阻塞第一版。不得把任务对话的 `branchId`（对话分支标识）当作 Git 分支。

## 3. 当前插件机制的核对结果

以下结论来自本次对仓库公开插件类型与 Electron 运行实现的检查，不表示功能已接入。

| 能力 | 当前观察 | 对本需求的影响 |
| --- | --- | --- |
| 自定义插件视图 | 有 `render(context, container)` 入口 | 可绘制提交列表、SVG 关系图和详情区 |
| 工作台、侧栏、分屏挂载 | 有对应贡献与挂载能力 | 可承载独立 Git 面板 |
| 主题与可见性 | 有环境及可见性通知 | 可适配明暗主题并停止隐藏页面的工作 |
| 视图状态及私有存储 | 有公开接口 | 可保存筛选与选中状态；需按仓库隔离 |
| 手动选择本地目录 | 有受控资源选择与读取接口 | 可授权读取目录，但不等于自动获取当前空间路径 |
| 本机 Git 查询与操作 | 核对的公开 API 中没有专用接口 | 需要新增受控宿主桥接；查询、写入及网络能力分别授权 |
| 任意本机进程执行 | 插件运行窗口禁用 Node.js 集成并启用沙箱 | 不能在插件中直接运行 `simple-git` |
| 空间上下文 | 部分条件上下文有 `spaceId`，未见直接可调用的空间仓库查询契约 | 需要定义调用作用域与空间切换语义 |
| 工作台公共引用 | 有 `WorkbenchSelectionReferences`（内容捕获、目标解析及草稿追加服务）及资源引用卡片 | 可复用后半段通路；当前不等于隔离插件已有接入 |
| 通用插件引用 | Spec-013 仍列为待后续；核对的公开插件 API 没有引用入口，资源引用协议尚无插件来源 | 需扩展受控桥接与来源类型，不能伪造文件或聊天消息来源 |

核对依据：

- `apps/buddy/service/resources/skills/plugin-creator/references/api.d.ts`：随项目分发的插件公开类型。
- `apps/buddy/electron/main/extensions/SandboxedExtensionHost.ts`：隔离运行宿主，配置了 `sandbox: true`、`nodeIntegration: false`、`contextIsolation: true`。
- `apps/buddy/electron/main/extensions/registerExtensionIpc.ts`：插件服务与受控能力的 Electron 桥接入口。
- [Spec-013：工作台选区引用与多分屏目标](feature-013-workbench-selection-reference.md)：公共引用规则及分批实现边界，插件接入仍待后续。
- `apps/buddy/src/shared/ui/selection/workbenchSelectionReferences.ts`：已实现的内容捕获、来源/目标重验及最新草稿追加。
- `apps/buddy/shared/conversation/buddyUserContent.ts`：资源引用数据协议；本次核对支持文件、产出及浏览器来源，尚无插件来源。

结论：现有插件机制足以承载页面及交互，但不足以直接完成当前空间 Git 查询与操作。应以迁移项目实际需要的受控能力补齐宿主桥接，不推翻现有插件系统，也不开放任意命令执行。已有查询安全策略可参考 `apps/buddy/service/src/approvals/shell/inspectGitQuery.ts`（shell 审批中的 Git 检查），但该模块并非可直接调用的插件服务。

## 4. 页面设计建议

优先保留迁移项目的提交图、列表、详情和操作交互，只适配宿主主题、布局与连接方式；不要求先把 Svelte（Git Graph+ 使用的前端框架）重写为另一框架。以下是信息层级示意，不是要求从零重建页面；仓库、分支与哈希均为示例，并非实际状态。

```text
Git 版本                                  仓库：Lexora    [刷新]
───────────────────────────────────────────────────────────────
分支：master       HEAD：a83f291       标签：v0.8.0
有未提交修改：3 个文件
───────────────────────────────────────────────────────────────
提交关系          提交说明                       作者       时间
◌ ┊               未提交修改 · 3 个文件
● ┊ HEAD master   修复插件面板刷新               我         10 分钟前
│ ● feature/git   增加提交图                     我         30 分钟前
● │               调整侧栏入口                  我         1 小时前
●─╯               合并插件基础能力              我         昨天
```

- 顶部状态区优先呈现仓库、分支、当前提交及修改状态。
- 左侧彩色连线表达提交父子关系，不将每条图形轨道简单命名为某个长期固定分支。
- 分支和标签是附着在对应提交上的引用标签；当前 `HEAD` 行明确突出。
- 未提交修改用空心节点、虚线或独立状态行表示，不伪造真实提交。
- 选中提交只查看详情，不改变当前检出版本。
- 宽视图右侧显示详情，窄视图下方显示详情；准确宽度阈值在实际界面验证时确定。
- 采用宿主主题变量、紧凑列表和低对比度分隔，颜色之外也使用文本或形状表达状态。
- 第一版截断历史时明确提示“仅展示最近 100 条提交”；父提交不在当前结果中时画延续标记，不误画成仓库根提交。

建议以独立可打开的 Git 面板为主入口；具体导航贡献、挂载位置及打开/关闭恢复行为在实现前按正式宿主契约确定，不依赖父页面 DOM 或内部 IPC。

基础操作沿用上游合适的工具栏、分支/提交菜单及操作对话框。执行前显示仓库、当前分支和操作目标；高风险确认与执行参数一致，普通选中/双击行为不能意外触发写入。运行时防止重复提交，结果明确区分成功、失败、冲突和结果待核实，不自动执行另一种操作作为回退。

### 4.1 引用到聊天输入框（独立后续交付）

以下交互在通用插件引用桥接完成后接入，不作为 Git 基础操作第一版的前置依赖。

- **文字选区入口**：拖选提交说明、作者或分支/标签文字，在选区内右键，沿用 Spec-013 的“引用到对话”及多分屏目标菜单；不增加浮条或重复复制按钮，保留既有复制行为。
- **提交级入口**：选中提交后，详情区提供“引用此提交”。采集该提交的有界上下文，而不是截图或全部列表。明确关联单目标时直接添加；无关联且多目标时由宿主显示目标选择，不能凭另一输入框焦点猜测。
- 添加到现有引用附件区，普通聊天正文保持不变。用户自行补充问题并按原流程发送；不新增评论、确认发送或一键分析流程。

```text
提交详情：a83f291 · 修复插件面板刷新
[引用此提交]
        ↓
┌─────────────────────────────────────────┐
│ Git · Lexora · a83f291                 × │
│ 修复插件面板刷新                         │
└─────────────────────────────────────────┘
原有聊天输入框：帮我解释这次提交……
```

示意中的文字不是自动生成的问题。卡片沿用现有紧凑外观，支持完整快照预览、草稿移除、发送后历史展示；仅在来源可验证且支持时提供定位，不承诺自动重开已关闭的 Git 面板。

## 5. 建议技术方案：迁移优先，适配补缺口

```text
Git Graph+ 现有图布局、列表、详情与基础操作交互
                         ↓ 替换原宿主连接
              Lexora 插件消息与主题适配
                         ↓
       受控宿主桥接：空间绑定、权限、参数校验、确认
                         ↓
       复用/裁剪的 Git 服务：查询与已批准的基础操作
                         ↓
           本机 Git / 经验证的本机凭据助手
```

第一步是验证迁移，不是先建设通用 Git SDK。保留可独立使用的上游模块；只在宿主依赖、安全边界或明确功能缺口处修改。接口名字、文件拆分和布局位置由最小实验确定，不为可替换绘图库、全量快照或未来多仓库预先建设框架。

### 5.1 宿主职责

- 根据发起视图/分屏绑定的空间上下文确定授权目录，不能由插件提交任意绝对路径，也不能每次读取全局活动空间。
- 使用 Git 仓库发现机制处理空间是仓库子目录的情况，不能仅检查根目录的 `.git`。支持 `.git` 为文件的工作树布局；外置元数据访问不扩大插件任意文件访问权限。
- 查询、仓库写入及网络推送分别控制权限。只开放确定操作及结构化参数，不提供任意 shell、任意 Git 子命令或直接转发全部上游消息的入口。
- 校验分支、完整提交哈希、远端等参数，使用参数数组执行；禁止选项/命令注入。限制条数、输出、执行时间和并发；同一仓库的写操作防止重复及并行冲突，不先实现通用任务调度器。
- 失败返回结构化原因，不暴露凭据、含秘密的远端地址、完整配置或无关路径。
- 上下文失效时取消查询、撤销未执行操作；已启动写操作仍绑定原仓库，绝不能重定向到新空间。进程中断不等于回滚，结果核实见 5.6。
- 浏览与刷新不隐式联网，控制懒获取、签名验证、fsmonitor（文件系统监控辅助程序）等可能触发的额外执行。写操作涉及的钩子、凭据助手或编辑器调用需有明确策略，不把获准写入视为任意仓库脚本授权。

### 5.2 最小契约与作用域

以下是能力示意，**不是已有 API，也不是要求一次公开全部方法**：

```ts
// getSnapshot：宿主聚合一次面板刷新，绑定发起视图的授权上下文。
const snapshot = await context.git.getSnapshot({ limit: 100 })

// 写操作通过结构化动作请求进入宿主校验/确认流程。
// snapshot.scope 是宿主签发的作用域标识，不是插件提供的本机路径。
await context.git.requestOperation({
  scope: snapshot.scope,
  action: 'switchBranch',
  branch: 'feature/example',
})
```

先依据迁移项目消息契约验证聚合读取与必要动作。日志已含完整说明时不必另增详情查询。是否公开仓库代理、仓库句柄或更多分项 API 留给实际调用需求，不先固定 `resolveRepository()` 等接口。

最低数据要求：

- 仓库：不透明仓库/工作树标识、展示名称、当前分支和提交（均可为空）、去重后的修改数量。
- 引用：完整引用名、类型及目标提交；带注释标签解析到提交目标。
- 提交：完整哈希、全部父提交、作者、时间、完整说明；适合绘图的拓扑顺序。标签来自结构化数据，不靠解析装饰文本猜测。
- 刷新：作用域修订、请求批次及查询时间；不代表原子快照。
- 操作：动作、目标、执行状态及安全的结果/错误；至少区分拒绝、过期、忙碌、冲突、认证失败、远端拒绝、超时和结果待核实。
- 通用错误：无空间、非仓库、权限不足、作用域失效、Git 不可用、查询失败。

授权约束：

- 宿主绑定插件身份、视图实例、空间修订及真实仓库；每次调用重验，不信任插件自报身份、路径或授权。
- 空间切换、权限撤销、视图销毁、插件禁用后，旧作用域不能发起新查询/操作，不悄悄转投另一仓库。
- 若使用仓库句柄，它不跨插件共享，不持久化后当作永久授权；这可由已有生命周期机制承载，不要求新建一套通用句柄框架。
- 操作确认绑定动作、仓库、目标及危险参数；执行前检查关键状态是否改变，改变则重新选择或确认，不静默替换目标，也不承诺跨外部进程原子锁定。

宿主与插件之间尽量传输 Git 语义数据，不把上游 `simple-git` 内部类型或绘图坐标固化为公共契约。Git Graph+ 的布局目前位于后端源码目录，可将可独立运行的 TypeScript 模块复用到插件图形侧；是否需要调整位置先通过实验确定，不重写算法，也不为多绘图库另造抽象体系。

### 5.3 插件职责

- 保留上游适用的界面、布局与操作交互，替换 VS Code 消息、主题和状态保存连接；不直接访问本机进程或宿主内部对象。
- 按仓库/工作树隔离选中状态；显示操作影响，禁用重复执行，处理冲突/认证/失败反馈，操作结束后刷新。
- 移除或不注册本版未支持的功能；宿主白名单仍须独立拒绝它们，不仅隐藏按钮。
- 提交说明、作者、引用名按不可信文本处理。上游 Markdown、链接、网络头像等行为不自动照搬；未经安全验证的内容按纯文本展示。
- 清理监听和请求，隐藏时不做不必要的后台轮询；不启用定时 fetch 或未经授权的外部网络请求。
- 刷新失败可保留旧结果，但明确标注过期；不能把写操作结果待核实显示成成功或已回滚。

### 5.4 模块职责与复用边界

| 模块 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| 现有空间上下文与授权 | 确定发起视图的仓库作用域与失效规则 | 不处理图布局，不以全局焦点猜测仓库 |
| 受控宿主桥接 | 身份、权限、参数限额及操作确认 | 不直接放行上游全部消息或任意命令 |
| 复用/裁剪的 Git 服务 | 仓库发现、固定查询、基础操作及解析 | 不依赖聊天草稿、插件 DOM 或全局活动空间 |
| 上游布局与插件界面 | 提交图、详情、基础操作交互及宿主适配 | 不自行获得进程权限，不绕过确认 |

职责分开不等于每项都新增一个类或服务。`registerExtensionIpc.ts`（插件注册入口）主要负责接线，Git 执行与解析保留在可测试模块中。优先保留上游可用封装；只有它无法满足权限、进程控制或构建要求时，再考虑现有进程封装或 `simple-git`，不同时维护两套 Git 实现。

Git 服务可用临时真实仓库测试，布局可用固定提交样例测试；完整 UI 仍需实际隔离插件验收。聊天引用另走公共能力，不进入 Git 执行模块。

### 5.5 刷新协调与一致性

第一版不要求完整的分支/标签前后核对与自动重试体系，不承诺跨进程原子快照：

1. 一次刷新由宿主聚合状态、引用及日志，绑定同一仓库作用域和请求批次，不拼接不同轮次结果。
2. 尽量把日志起点解析为固定提交哈希；展示查询时间，修改数量视为查询期间观察值。
3. 必须防止旧响应覆盖新刷新、旧空间结果进入新空间。查询前后 HEAD/符号引用改变时提示重新刷新，不宣称该批数据是已确认的当前状态。
4. 本插件写操作启动后使先前刷新批次失效，操作结束后获取新结果；失败或冲突也需核对真实状态，不仅刷新成功操作。

批次编号解决异步覆盖，不证明 Git 数据同一时刻一致。外部工具仍可能改变其他引用或工作区；不为查询锁定用户仓库。全面引用核对、有限自动重试或更严格快照，在出现实际需求后另行评估。

### 5.6 基础操作与风险边界

| 操作 | 第一版行为与必要防护 |
| --- | --- |
| 切换分支 | 用户明确选择目标；工作区不允许安全切换时显示 Git 拒绝原因，不自动丢弃修改、硬重置或储藏修改 |
| 合并 | 显示当前分支及被合并目标；沿用经验证的上游选项，冲突时停止并提供状态、继续/中止入口，不自动挑选冲突结果 |
| 变基 | 明确被改写的当前分支和目标基点，提示历史改写影响；冲突时可继续/中止，不因失败自动硬重置 |
| 重置 | 明确提交、模式及对分支/索引/工作区的影响；硬重置须危险确认，不把 soft/mixed/hard（软/混合/硬重置）混为同一操作 |
| 推送 | 确定远端及目标分支后联网；普通推送与强制推送区分，远端拒绝不得自动升级为强推；强推需确认，优先租约保护，租约信息不足时不静默放宽 |

- 优先复用现有凭据助手，不自行存储密码/token，不把凭据回传插件。VS Code 专属认证依赖须替换；认证弹窗、取消与非交互失败在 Windows 真机验证，未验证时注明限制。
- 查询默认不运行仓库脚本；基础操作可能调用钩子、编辑器或凭据程序，需明确禁用、受控兼容或授权方式。不因为上游默认调用就直接放行，不另建完整脚本运行平台。
- 操作中显示进度/忙碌状态，防止重复写入；超时、取消、视图关闭或空间切换不能被解释为事务回滚。已启动操作始终针对原仓库，结果不能回写新空间面板。
- 中断后可能留下冲突/变基状态，推送超时也可能已改变远端。返回结果待核实并提示检查，不自动重试写操作、不自动重置仓库、不悄悄执行 fetch 验证远端。
- 完整冲突编辑器不作为前置工程，但冲突检测、用户处理后继续/中止及错误反馈必须有完整闭环。

### 5.7 通用插件引用接入与 Git 内容适配（独立后续交付）

引用与 Git 查询/操作分别实现；以下要求只约束引用交付，不阻塞 Git 面板第一版：

```text
受控 Git 查询服务 → Git 插件视图
                         ↓ 用户拖选文字 / 点击引用此提交
                 插件内容快照适配器
                         ↓
           通用插件引用桥接（待实现）
                         ↓
     既有工作台目标解析、来源/草稿身份校验
                         ↓
       引用卡片 → 手动发送 → 模型上下文与历史
```

**职责约束：** Git 查询服务不依赖聊天草稿；公共引用服务不依赖 Git 命令或绘图库。插件仅提交有界快照和可校验的来源定位信息；由宿主认证插件/视图身份、呈现添加操作并决定目标。不提供 Git 专属的任意聊天写入 API，也不让插件枚举其他任务、读取草稿正文或自行指定会话。

**两类内容快照：**

- 文字选区：保存实际选中的文字，附仓库展示名称、来源内容标题及可用提交哈希。不能准确映射位置时不编造行号；上下文不自动扩展成整个提交说明或整份仓库。
- 引用此提交：保存仓库展示名称、完整提交哈希、作者、时间、提交说明，以及采集时指向该提交的分支/标签。明确这是采集时的引用状态，不保证发送时仍成立。不自动带 Diff、文件内容或仓库路径授权。

宿主负责认证的来源至少绑定插件身份、视图实例、仓库/工作树标识、空间作用域修订及采集时的内容版本。Git 语义元数据由插件适配器提供，不能因此被当作宿主已验证的可信指令。公开引用类型、可选 Git 定位元数据及接口签名在通用插件契约中确定，不伪造成现有文件、产出或聊天消息引用。

**目标与生命周期：**

- 全面复用 Spec-013 的明确关联、多目标选择、真实草稿去重和写入前重验；一次操作只添加到一个确定草稿。
- 打开菜单或点击提交级入口时冻结来源内容与候选目标。空间/仓库、来源视图、目标会话/分支或草稿身份变化后旧操作失效。单纯刷新或改变选中项不替换已冻结内容；同一有效来源下仍添加原快照，内容尚未冻结或来源身份已变时拒绝，不悄悄改成另一份提交。
- 正文编辑不使引用失效；添加时保留最新正文，不使用采集时的旧正文覆盖。
- 已成功添加的快照不因切分支、内容刷新、关闭面板或插件禁用而丢失。发送时使用冻结内容，不重新读取仓库。历史中的引用不能依赖已失效仓库句柄才能展示。

**限制、安全与反馈：**

- 沿用公共引用数量与长度上限、去重、超限和目标不可用反馈；本次核对 Spec-013 记录为合计 16 条、单条 32,768、总长度 131,072，按 JavaScript 字符串长度计，不是 token 数。实现时以公共定义为准，不在 Git 插件另建一套数值。
- 提交级去重至少区分仓库/工作树、完整提交哈希、快照内容与采集时引用信息；文字选区还区分来源位置。不能只按短哈希、标题或摘要去重。
- 元数据计入有效载荷限制；超限拒绝并提示，不静默截断长提交说明，不绕过限制自动拆成多个引用。
- 引用及预览按不可信内容处理，不执行提交说明中的 HTML 或指令；引用不自动授予文件读取、额外 Git 查询或网络权限。
- 添加成功带目标名称反馈，不自动发送、不切换任务、不抢焦点。没有目标时提示先打开可接收引用的对话，不自动创建。
- 不经过系统剪贴板，引用能力缺失时明确提示；不能用模拟粘贴或直接操作宿主输入框 DOM 作为回退。

此桥接依赖补齐后才能宣称引用交付完成；Git 面板及基础操作可独立完成验收。通用插件来源需覆盖协议解析、草稿持久化、卡片预览、模型投影、发送和历史兼容，不能仅增加一个按钮。

## 7. 分阶段实施建议

1. **最小迁移实验**：固定候选版本，用 Git Graph+ 现有图/列表在真实 Lexora 插件容器显示一个真实仓库，验证 Svelte 构建、资源、沙箱与替换宿主消息的成本。此时只读是验证顺序，不是最终范围。
2. **必要宿主适配**：基于实验定义最小查询/动作契约，补空间绑定、权限、限额、状态与旧响应隔离；复用上游解析/布局，不先建设完整通用 SDK 或多绘图库框架。
3. **基础操作接入**：逐项接入切分支、合并、变基、重置、推送，以及冲突继续/中止、危险确认和本机认证兼容；在临时仓库与受控远端中验证，不在用户工作仓库试验破坏性操作。
4. **Git 第一版验收**：在真实宿主完成安装、打开/关闭、状态/关系图/详情、手动与操作后刷新、空间切换、主题和窄屏测试，分别记录编译与运行证据。不能仅交付只读链路就宣称第一版完成。
5. **引用独立交付**：按 Spec-013 补通用插件引用桥接及来源协议，再接入文字选区和“引用此提交”，复用目标路由、卡片、限制、持久化、模型投影和历史，单独验收。此阶段不阻塞第 4 步。

独立 HTML 模拟页不能替代实际插件验收；迁移阻塞时先记录证据并比较备选，不默认推倒重写。

## 8. 验收标准

Git 第一版包括下列数据、界面、基础操作、作用域及权限验收；聊天引用按独立交付验收。所有项目目前均未完成。

### 数据与作用域

- [ ] 普通仓库正确显示分支、当前提交、直接指向当前提交的标签及变更数量。
- [ ] 空间为仓库子目录时能识别所属仓库；向父目录发现的授权边界有明确定义。
- [ ] 非仓库目录显示明确提示，不初始化、不修改目录。
- [ ] 新建但无提交的仓库显示未诞生分支状态，不报成一般查询失败。
- [ ] 游离检出状态明确显示“未处于分支”，保留当前提交。
- [ ] Git worktree 能正确读取状态和提交，或在未支持时明确说明限制。
- [ ] 快速切换空间或刷新时，旧查询不能覆盖新上下文结果。
- [ ] Git 不可用、权限不足和超时均有可理解的错误及重试入口。

### 图形与交互

- [ ] 线性提交、分叉、合并及多父关系正确显示。
- [ ] 历史截断时显示延续关系，不将结果边界误画为根提交。
- [ ] 当前提交标记、分支引用与标签指向准确；HEAD 不在 100 条结果中时有明确提示。
- [ ] 点击提交仅更新详情，不执行检出或修改仓库；基础操作通过明确入口发起。
- [ ] 提交说明及引用名包含 HTML 特殊字符时按文本安全显示。
- [ ] 明暗主题、窄分屏、长分支名和长提交说明可正常使用。
- [ ] 关闭、禁用插件后释放监听、取消查询及未启动操作；已启动写操作按 5.6 收尾，不把关闭面板当作回滚。

### 基础操作

- [ ] 切换分支成功后状态与 HEAD 更新；未提交修改阻碍切换时明确拒绝，不自动强制或丢弃修改。
- [ ] 合并的当前分支、目标和选项明确；成功、失败及冲突有正确反馈。
- [ ] 变基提示历史改写影响；冲突可在外部处理后继续或中止，不静默硬重置。
- [ ] 重置目标与模式明确；软/混合/硬重置影响正确，硬重置需绑定目标的危险确认。
- [ ] 推送显示远端及目标分支；普通推送被拒绝时不自动强推，租约保护强推及确认分别测试。
- [ ] 本机认证的成功、取消、失败/不可用均有反馈，不泄漏凭据，不依赖未迁移的 VS Code 专属桥接。
- [ ] 重复点击或同仓库并行写入被控制；确认后目标或关键状态变化时不按旧确认执行另一目标。
- [ ] 写操作后刷新真实状态，包括失败和冲突；超时/取消不宣称已回滚，不自动重试可能已生效的操作。
- [ ] 空间切换、面板关闭或插件禁用期间，已启动操作不转投新仓库，结果不会覆盖另一空间。
- [ ] 基础操作、冲突与中断测试使用临时仓库；推送测试使用本地 bare（裸）仓库或明确授权的测试远端，不修改用户工作历史。

### 迁移、作用域与一致性

- [ ] Git Graph+ 真实隔离插件构建与运行有证据；若未采用，记录阻塞原因及备选评估，不能把 README 阅读当迁移完成。
- [ ] 尽量复用上游图、界面与基础操作逻辑；迁移模块、宿主替换点及保留的许可声明可追踪。
- [ ] 多分屏查询和操作绑定发起视图的空间，其他分屏活动状态不改变目标。
- [ ] 空间切换、权限撤销、视图销毁或插件禁用后旧作用域不能发起新请求；若有句柄，不跨插件或持久化绕过授权。
- [ ] 公共契约不固化绘图库专有类型；布局复用不要求自建多绘图库适配框架。
- [ ] Git 服务不依赖聊天组件或全局当前空间；桥接入口不堆积执行与解析算法。
- [ ] Git 服务可独立测试，图布局可用固定提交样例测试。
- [ ] 刷新不拼接不同批次；HEAD/符号引用变化有反馈，操作启动使旧批次失效，结束后刷新。
- [ ] 旧响应不会覆盖新刷新或新空间；查询时间与过期状态明确，不宣称工作区原子快照。

### 聊天引用（独立后续交付）

- [ ] 文字选区在选区内右键提供公共引用菜单；空选区不误触发，无浮条或重复复制按钮。
- [ ] “引用此提交”包含完整哈希及约定元数据，不自动附加 Diff、文件内容或整个提交列表。
- [ ] 单关联目标和多分屏显式选择沿用 Spec-013，一次只写入一个真实草稿，不按全局焦点猜测。
- [ ] 引用进入已有附件区，可预览与移除；最新聊天正文保持不变，不自动发送、创建任务或抢焦点。
- [ ] 菜单/选择期间来源身份或目标切换、草稿发送/重置时旧添加请求失效，不转投其他对话；同一有效来源的刷新/选中变化不替换已冻结快照。
- [ ] 去重、单条/总长/数量限制包含元数据，超限明确拒绝，不静默截断。
- [ ] 关闭面板、切分支或禁用插件后已添加和已发送的快照仍保留，不在发送时重读仓库。
- [ ] 插件不能读取草稿、枚举任务、伪造来源身份或任意指定写入目标，引用不授予额外读取权限。
- [ ] 通用插件引用协议、草稿恢复、卡片、模型投影、发送及历史有兼容性测试，保留旧文件/产出/浏览器引用。
- [ ] Git 查询模块不依赖聊天组件；引用不经过剪贴板或宿主 DOM 穿透。
- [ ] 真实隔离插件到聊天的引用、首次发送和多分屏不串写分别验证；测试模型与真实模型服务证据分开记录。

### 权限与验证

- [ ] 查询、写入及推送网络能力分别授权；未获准的操作即使通过伪造上游消息请求也被拒绝。
- [ ] 插件不能通过路径、哈希、分支、远端或参数注入执行任意命令或越界访问。
- [ ] 查询与操作设置合理超时、输出及并发限制，查询另有条数上限，相关边界有测试。
- [ ] 浏览/刷新不修改工作树、索引、历史或远端，不隐式联网；写操作仅产生确认范围内的预期影响。
- [ ] 仓库钩子、签名程序、凭据助手及编辑器调用有明确策略；上游网络头像、自动 fetch 等非目标行为未被默认带入。
- [ ] 高风险确认由宿主绑定身份与参数，插件不能伪造已获准结果；拒绝后不提供绕过路径。
- [ ] 编译通过与运行验收分别记录；真实界面未测试时明确列为待验证。

## 9. 未决事项

- Git Graph+ 固定版本、完整依赖审计、Svelte 编译与资源/CSP 兼容性、裁剪范围和真实迁移成本；失败后才比较备选。
- 上游 Git 服务与 VS Code 的实际耦合、消息契约替换点、布局放置方式；是否能直接保留执行封装，而非另引 `simple-git`。
- 受控 Git API 的准确位置，查询/写入/推送权限字段、确认流程及是否需要提升插件 API 版本；仓库代理/句柄仅在实际需求明确后确定。
- 发起视图的空间绑定、作用域修订及失效通知如何复用；仓库根目录在空间之外、worktree 共享元数据时的授权范围。
- 聚合刷新签名、HEAD 核对、输出及超时预算；采用 5.5 的观察值与非原子边界，不把全面引用核对作为前置工程。
- 合并/变基的最小选项、冲突继续/中止接入，以及需调用编辑器/钩子时的受控策略。
- 重置模式与危险确认文案、租约保护推送的预期远端状态来源；不新增隐式 fetch 或默认放宽租约。
- 本机凭据助手在 Windows 真机中的交互兼容、认证取消与超时处理；不自建凭据存储。
- 已启动写操作在视图销毁/插件禁用后的收尾、原仓库状态核实与用户反馈；不把进程取消当回滚。
- 第一版面板的正式导航/挂载入口与关闭后再次打开方式。
- 独立引用交付中的通用插件桥接权限、可信用户操作、来源类型、来源/目标绑定和卡片/历史兼容；不作为 Git 第一版前置依赖。
- 后续暂存/提交、fetch/pull、Diff、当前文件入口、多仓库、远端比较及整块状态引用的优先级；上游具备不等于本版自动包含。

## 10. 文件与术语说明

| 原名称 | 中文含义 | 用途 |
| --- | --- | --- |
| `HEAD` | 当前检出的提交指针 | 定位本机代码所基于的提交 |
| Git worktree | 同一仓库的独立工作树 | 解释 `.git` 文件和外置仓库元数据布局 |
| `spaceId` | Lexora 空间标识 | 绑定授权与查询作用域，不等于本机路径 |
| `branchId` | 任务对话分支标识 | 与 Git 分支无关，不得混用 |
| Git Graph+ | 第一迁移候选的 VS Code Git 面板 | 复用图、界面和基础操作，非已接入功能 |
| Svelte / Webview | 上游前端框架 / 隔离网页视图 | 说明界面构建与宿主消息适配位置 |
| `simple-git` | 本机 Git 命令封装库 | 上游封装不适用时的备选，不预先引入 |
| `render(context, container)` | 插件视图渲染入口 | 在隔离容器中构建页面 |
| `getSnapshot()` | 聚合面板查询的示意接口 | 说明最小查询能力，名称与签名未定 |
| `requestOperation()` | 结构化动作请求的示意接口 | 进入宿主校验/确认，非任意命令入口 |
| 仓库句柄 / 作用域 | 宿主认证的仓库访问标识 | 绑定身份与上下文，不能当作永久授权 |
| `--force-with-lease` | 带远端预期状态检查的强制推送 | 降低覆盖他人远端更新的风险，不等于无风险 |
| CSP | 网页内容安全策略 | 验证迁移界面的脚本与资源加载边界 |
| `WorkbenchSelectionReferences` | 工作台公共引用服务 | 捕获来源与目标身份，重验并追加到最新草稿 |
| `resourceQuotes` | 现有资源引用记录集合 | 承载快照、来源、发送与历史；插件来源仍需扩展 |
| Spec-013 | 工作台选区引用与多分屏目标规格 | 本插件引用交互与安全规则的共同依据 |
