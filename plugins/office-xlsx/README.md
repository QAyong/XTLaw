## 当前状态

- 点击文件管理器中的 XLSX，在 context 面板用 GenOffice Sheets 的原界面（Univer 表格 + 功能区）打开，显示全部工作表、样式、合并单元格、冻结窗格、数字格式；条件格式、图片与图表由上游界面支持，本版没有逐项验证。
- 计算引擎是上游的 Rust 引擎（calamine + IronCalc）编译成 WebAssembly，在页内 Worker 里运行。首次打开后只按可见范围读取单元格，大表滚动流畅。
- 编辑：单元格、样式、行列、工作表、条件格式、数据验证、表、透视等上游编辑能力都在页内执行（上游主进程处理器直接运行），宿主不参与；公式实时重算。
- 保存：保存按钮和 Ctrl+S 经 `selectedResourceWrite` 写回当前 XLSX，宿主检查文件版本、目录授权和内容哈希；外部修改会拒绝覆盖，编辑器保留未保存状态并提示"文件已被其他程序修改"。保存前对生成的包再做一次有界 ZIP 校验。
- 保真：沿用上游的"只重写被编辑的工作表条目"逻辑，其余条目逐字节保持不变，并校验未改动条目的清单；工作簿设置 `fullCalcOnLoad`，所以 Excel 打开时会重算，保存文件里公式单元格的缓存值不会随编辑更新（上游行为）。
- 另存为（Ctrl+Shift+S 或另存为按钮）：导出一份副本，经 `resourceExport` 打开系统保存窗口；当前文档仍绑定原文件，修改状态不变（之后 Ctrl+S 仍写回原文件），保存成功后状态栏提示"已另存为副本，当前文档仍是原文件。"。副本用的是保存同一条管线（只重写被编辑的工作表条目、其余条目逐字节保持、未改动条目清单校验），交给宿主前再做一次有界 ZIP 校验；没有"文件"标签，与 DOCX 一致。在保存窗口里取消不改变任何状态，状态栏显示上游的"保存已取消"。
- 引用到聊天：在表格区（单元格、行列标题）右键，原菜单末尾出现唯一一项"引用到聊天"（多个聊天窗格时展开目标子菜单），不触发保存、不替换输入框正文、不发送消息。引用内容见下文"选区引用"。
- 定位来源：点聊天里引用卡片的“定位来源”，宿主打开这份 XLSX 后，插件切到引用的工作表并选中区域（滚动到该单元格），再用引用时同样的方式读出显示值，与引用文字（忽略空白）比较，一致才算定位。工作表被改名时按引用时的工作表序号找同一位置的工作表；大表里单元格还没加载好会等到加载完。区域超出数据、单元格内容变了、区域格式不对都返回未找到，宿主提示“已打开文件，但没能定位到原来的位置”。
- 自动保存：默认开启（每 30 秒及窗口失焦时按保存路径写回，同样检查文件版本与内容哈希），可在左上角开关关闭，选择按文件视图记住。
- 不支持：新建工作簿、导出为 CSV/PDF、异常退出的草稿恢复。
- 已隐藏 Genspark AI 助手入口（`sheets-overrides.css`，不改上游代码）。AI、云、账号、PDF 导出与打印、屏幕捕获、MCP、项目存储均未接入。
- 读取前做有界 ZIP 校验（`xlsx.js`）：文件最大 64 MiB（宿主选中文件 API 的上限），解压合计最大 256 MiB（与上游一致），条目不超过 10000，不支持 ZIP64 或加密文件，必须含 `xl/workbook.xml`。只接受 `.xlsx`，不含 `.xls`、`.csv`、`.ods`、`.xlsm`。

## 权限

清单声明 `selectedResource: read`、`selectedResourceWrite: true`（保存当前文件）、`composerReference: true`（选区引用到聊天，要求 apiVersion ≥ 4 与 `selectedResource: read`）、`resourceExport: true`（另存为副本）和 `webAssembly: true`。后者是宿主新增的按插件开放的权限：视图页 CSP 加 `'wasm-unsafe-eval'`（只允许编译随包的 `.wasm`，仍禁止 JS eval）和 `worker-src`（插件包路径加 `blob:`：沙箱页是不透明源，Worker 脚本不能按 URL 加载，页面把脚本取回后从 blob 启动；Worker 起不来时引擎退回页内运行）；安装确认里会单独提示。

## 选区引用

- 读取方式：构建期把上游渲染层的 `control` 模块换成 `shims/control-fix.ts`，保留上游的 `genoffice selection` 钩子，另加 `lexora-selection-text` 请求（上游的 `__univerAPI` 只在开发模式存在，不能用）。它通过 Univer 的 `getDisplayValues()` 读当前选中的区域。`vite.config.mjs` 里一个小的源码转换让 `App.tsx` 的钩子多收到懒加载工作簿状态（转换不匹配时构建失败）。
- 取值：**显示值**（单元格里看到的文字，含数字格式、公式的计算结果；公式视图下是公式文本），不是原始值。行内用制表符分隔，行间用换行；单元格内的制表符和换行换成空格；末尾的空行空列去掉。包含隐藏行列的内容；合并单元格只在左上角有值。
- 只引用单个连续区域：多重选区（Ctrl 点选多段）时菜单项置灰并提示。整行、整列选区只读到工作表的已用范围。
- 大表：流式载入的大工作簿只载入屏幕附近的行，选区必须完整落在已载入范围内，否则置灰并提示"选区超出已载入的范围"（没有这个检查，未载入的单元格会读成空，被当成真实内容）。完整载入后的工作簿没有这个限制。
- 限制：单次最多 20000 个 UTF-16 字符，选区超过 10 万格也按超限处理，置灰并提示；沿用宿主的引用数量与总长度限制。空选区不出现菜单项。
- 记录：来源 XLSX、工作表序号与名称、选区 A1 地址（用户选中的区域，不是裁剪后的区域）、打开时读到的文件内容哈希。引用文本是屏幕上的当前内容，**含未保存的修改**，哈希对应打开时的文件。引用提示给模型的内容包括文件路径、工作表名、区域和文本。点击引用卡片会重新打开源文件，不会跳到具体单元格。
- 菜单：Univer 的右键菜单是 React 渲染的，菜单项克隆自菜单里已有的项以保持外观与深浅色；关闭菜单时 Univer 只给弹层加退出类，动画结束才移除，所以插件用"弹层带 exit 类"判断菜单已关闭。菜单精简后（见上）一般不再需要滚动；窗口特别矮时末尾这一项仍需滚动才能看到。

## 已安装版本的升级

宿主的启动预装只对"从未预装过的插件 ID"生效：已经装过的 XLSX 插件（包括 0.2.3）不会被启动预装替换，也不会因为这次新增权限被改动。升级需要走正常的插件更新或重新安装流程，安装确认里会单独列出新增的 `composerReference` 与 `resourceExport` 权限；更新后需按提示重启插件。未做桌面实机验证。卸载后重新安装会使用随应用携带的 0.3.0。

## 实现方式

上游 Sheets 的文档逻辑在 Electron 主进程（约 50 个 IPC 处理器）。与 Office PPTX 插件相同，插件不重写它，而是把上游的 preload、`sheets-main.ts` 和渲染层打进同一个浏览器 bundle，`electron` 模块换成页内垫片，`node:fs` 换成内存文件。垫片和空桩在 `apps/buddy/extensions/office-xlsx/lexora-build/`，上游源码不改。

和 PPTX 插件不同的是引擎：

- 上游 `XlsxSidecarClient`（子进程 + stdio 行协议）换成 `shims/wasm-client.ts`，同样的接口，命令改为发给 Worker（`shims/engine.worker.ts`）。Worker 里的 wasm 用一个内存 WASI 文件系统（`@bjorn3/browser_wasi_shim`），宿主交来的 xlsx 字节放在 `/data`，引擎的缓存放在 `/tmp`。
- 引擎本身几乎不改：`wasm/wasm_api.rs`（约 50 行）暴露 `xlsx_alloc`、`xlsx_free`、`xlsx_handle`，内部调用上游现成的 `Engine::handle_line`。另外把 IronCalc 的 zip 依赖关掉 bzip2/zstd（C 代码，没有 wasm 的 C 工具链），并让 `NOW()`/`RAND()` 在 WASI 上走标准库而不是 js-sys。细节见 `build-wasm.mjs` 顶部注释。
- 浏览器没有跨源隔离，wasm 只能无线程运行：每个工作表在第一次读取时同步建完索引。放在 Worker 里，界面不会冻结，但大表首屏要等索引。
- Wasm 没有 panic 展开：引擎内部 panic 会让实例作废。`wasm-client.ts` 会丢弃 Worker 并通知上游的"引擎崩溃"流程，由渲染层重新打开文件。

## 构建

产物（`xlsx/`，含 wasm）已入库，来源与哈希见 `provenance.json`。重新生成需要 GenOffice 检出（锁定提交见 `build.mjs`，不符会失败）、Rust 工具链（带 `wasm32-wasip1` 目标）和可选的 Binaryen `wasm-opt`：

```powershell
git clone https://github.com/genspark-ai/genoffice.git; cd genoffice; git checkout 58dfd0b5b5eb3710efac0029b0452c61dba69035
npm ci --ignore-scripts
npm i --no-save --ignore-scripts path-browserify buffer @bjorn3/browser_wasi_shim
cd <Lexora>
node apps/buddy/extensions/office-xlsx/build-wasm.mjs <genoffice 路径> <输出>/xlsx_engine.wasm [wasm-opt 路径]
node apps/buddy/extensions/office-xlsx/build.mjs <genoffice 路径> <输出>/xlsx_engine.wasm plugins/office-xlsx
```

不给 Lexora 仓库加依赖。升级上游提交前必须重新审核垫片、空桩和引擎改动。wasm 产物不保证逐字节可复现（编译路径会进二进制），以 `provenance.json` 里的哈希为准。

## 限制与风险

- 在浏览器里用模拟扩展 CSP（含 `'wasm-unsafe-eval'` 与包内 `worker-src`）的页面验证过：自建中文样例（合并、公式、冻结、日期格式、两个工作表）、100 万格 5 MB 文件、500 万格 25 MB 文件都能打开并显示。未在 Lexora 桌面实机验收；内置浏览器会拦截 `sandbox` 文档的子资源，所以模拟页没有带 `sandbox` 指令。
- 大文件：500 万格的合成样例首屏约 10 秒以上（引擎线程里建索引，界面可操作）；100 万格 5 MB 文件改一个单元格后保存约 30 到 50 秒（页内改写 36 MB 的工作表 XML），小文件保存在一秒内。
- 另存为的实现：`entry.ts` 包住上游的 `workbook:save` 处理器。`save-as` 模式时改走上游"崩溃恢复副本"处理器（同一条保存管线，不弹窗、不切换会话），从内存文件里取出写出的包，校验后经 `resourceExport` 导出，再向渲染层返回"已取消"，渲染层因此不改变编辑状态与文件绑定。副作用：渲染层随后会写一句"保存已取消"，`shims/locale-fix.ts` 在副本写出后把这一句换成"已另存为副本…"。自动保存机制与"保存"路径没有改动。限制：本会话里新增、需要分两阶段保存的表格/透视表（上游先写主体再补这些对象）不会进入副本；工作表 XML 超过 64 MiB 的大文件上游不允许生成恢复副本，另存为会失败；导出为 CSV 仍不支持（提示"暂不支持导出为 CSV"）。
- 右键带超链接的单元格不再弹出状态栏的统计项菜单：上游曾把表格区外层容器也当成状态栏，本插件为此替换过判断；上游 #2083 已改为只认带标签栏的页脚，`sheet-context-menu-fix.ts` 垫片随 0.3.13 删除。该行为未在应用里重新验证。
- 页面里每次加载 zod 会尝试 `new Function` 探测 eval，被 CSP 拒绝并在控制台留一条违规报告，不影响功能。
- 另存为与引用到聊天在浏览器里用模拟扩展 CSP 的页面验证过（自建中文样例、100 万格大表）；未在 Lexora 桌面实机验收，系统保存窗口和聊天草稿目标选择由宿主完成，这里用桩代替。
- 未验证：真实业务工作簿、图表与图片的显示细节、透视表、数据验证和条件格式的渲染细节、`.ods/.xls/.csv` 导入、复制粘贴到系统剪贴板、打印。
- 没有"文件"标签的行为定义：打开、PDF 导出、打印没有宿主实现。
