# 类案检索

用户给出一组具体案情，要找相似的案件，并看它们怎么判。以案情为中心：实务检索看一批案例的共性、提炼规则，类案检索看每个案例和本案的异同、逐案对比。

适用民事、刑事、行政。检索范围和报告要素参照最高人民法院《关于统一法律适用加强类案检索的指导意见（试行）》（法发〔2020〕24 号）；用户是法官，或要按该意见出具类案检索报告时，严格按其范围顺序和要素。

按"立命题 → 检索 → 核对 → 对比作答"走，中间可以回头：

- 案情或命题不明确，先向用户提问，问清再往下。
- 检索中发现新的争议焦点，回到命题，拆开再检索。
- 核对不过的不放进报告；缺的回到检索补；换过关键词和渠道仍没有新增结果，就写进"注意"，不重复同样的搜索。
- 已检得的案例足以说明问题，就停；用户有立场时，先做完反向核查。

案例的检索与阅读一律委派给子代理，见 [委派读取](delegation.md)。

## 立命题

命题明确了才检索，不明确先向用户提问，不动手。

- 命题明确度分三级：无命题（只讲了一件事，没提要求）；不明确（太宽泛，如"怎么要回钱"）；明确（有具体事实和具体问题）。前两级先问，让用户明确诉求，再一步步补全信息。
- 提问规则同实务检索：一次问完，只问决定检索方向的关键事实，不超过三个，能列选项就列选项，问清之前不检索。
- 命题必须用法言法语表述，不能只用事实表述。
- 一份报告最多解决一到两个法律问题。案件有更多问题，拆成多份检索，不要塞进一份。
- 命题里的案由是为了检索；写进报告时，开头只写检索目的，不写案由和案件背景。

**命题表述：** 案件类型 + 案由 + 问题 + 关键词 + 适用法律。

> 案件类型：民事
> 案由：机动车交通事故责任纠纷
> 问题：鉴定结论的误工期超出受伤之日至定残之日的前一天，法院如何确定误工期？
> 关键词：鉴定、误工期、定残之日
> 适用法律：《最高人民法院关于审理人身损害赔偿案件适用法律若干问题的解释》第七条

- **案由要核对。** 民事以《民事案件案由规定》为准，刑事是罪名，行政是行政行为。案由错了会一直检索不到：把被继承人债务清偿纠纷当成买卖合同纠纷，就搜不到。检索不到时，先怀疑案由。
- **适用法律是大前提。** 不知道适用什么法律时，先按 [法条检索](law-search.md) 找，再写入命题。
- 问题的类型（是否 / 是什么 / 为什么 / 怎么办 / 什么时候 / 什么地点 / 谁 / 多少）决定切入点，写法见实务检索的"作答"。

**分解：** 复杂命题要拆到具体的问题，每个焦点单独检索。拆的方法是"分析 + 表述"：先分析案件，找出争议焦点，再把每个焦点用法言法语表述成可检索的问题。用法官审理案件的思路来拆：

| 案件类型 | 分解思路 |
|---|---|
| 民事 | 请求权方法。诉讼请求 → 请求权基础规范 → 构成要件 → 被告抗辩（成立、消灭、行使阶段）→ 争议焦点（双方在哪个要件上有分歧）。请求权检视顺序：合同上请求权，类似合同关系（无权代理）上请求权，无因管理，物权关系上请求权，不当得利，侵权损害赔偿，其他。 |
| 刑事 | 先看构成要件，逐项审查有无争议；有无违法阻却、责任阻却；量刑看法定情节、酌定情节和量刑幅度。所用体系（四要件或阶层）以用户的为准。 |
| 行政 | 被诉行政行为是否合法：主体和职权、事实和证据、适用法律、程序、裁量是否适当；处罚类再看情节档次。 |

有立场的，每个焦点写明要证明的观点和它在本案中的作用。

## 检索范围与顺序

指导意见的检索范围，按顺序：

1. 最高人民法院发布的指导性案例；
2. 最高人民法院发布的典型案例及裁判生效的案件；
3. 本省（自治区、直辖市）高级人民法院发布的参考性案例及裁判生效的案件；
4. 上一级人民法院及本院裁判生效的案件。

除指导性案例外，优先检索近三年的案例；前一顺位已检得类案的，可以不再向后检索。

对应法宝筛选：`search_case` 的 `case_grade`（指导性案例、公报案例、典型案例、参考案例、权威案例、普通案例）、`courthouse_province`、`courthouse_name`、`decision_date_start`；`get_case_list` 的 `caseGrade`、`court`、`startLastInstanceDate`。`权威案例`是四类高参照级别的合集。

- 用户不是法官，也没要求按该意见出报告时，时间优先近五年；地域优先用户所在地，不足再扩展到全国。
- 人民法院案例库入库案例归在哪个参照级别下，需要用真实案例确认。

## 筛选条件与裁判文书要素

| 要素 | 怎么用 |
|---|---|
| 文书种类 | 可筛选（`documentAttr` / `doc_type`）。管辖等程序问题，限定裁定书 |
| 案件类型、审级 | 可筛选（`caseClassName`、`case_type`），如"民事二审" |
| 参照级别 | 可筛选，见上 |
| 法院层级、名称、省份 | 可筛选 |
| 审结日期 | 可筛选 |
| 案号 | 没有案号参数。必须列出，用 `anhao_recognition` 核验 |
| 案由 | 放进检索词，不是独立参数 |
| 当事人主张、争议焦点 | 返回里可能带（`get_case_list` 的相关字段，可能为空），不能用来检索 |
| 法律适用（"本院认为"） | **不能限定在这一部分检索**；用法条内容作关键词，读返回结果里的"本院认为" |
| 裁判结果 | **不能筛选**；要找某种结果（如败诉案例），先检索，再读返回的裁判结果 |
| 审判人员 | 不支持 |

## 检索与核对

先法后案。先确定本案适用的法条（读原文，方法见 [法条检索](law-search.md)），再找案例。关键词的组织见 [关键词](keywords.md)。

### 案例线索

网页搜索和搜狗微信都要完成"检索 — 筛查 — 必要时读取"，可同时进行，不能以发起搜索代替完成检索。搜索结果只用来找线索。

| 渠道 | 工具 | 关键词 |
|---|---|---|
| 网页搜索 | `lexora_web_search` | 加 `site:gov.cn`、`site:court.gov.cn` 等限定政府和法院站点；限定后搜不到，去掉限定再搜一次 |
| 搜狗微信 | `lexora_web_search`，`provider` 为 `sogou-weixin` | 加"法院""检察院""典型案例"等词 |

已经有案号或案名的，直接查，不用搜。不能因首轮结果不够贴合就跳过微信渠道。

### 法宝案例

法宝只当数据库，用来精确查和核验。工具是延迟加载的，用 `lexora_tool_search` 一次只搜一个确切的英文工具名（如 `get_case_list`），`limit` 设为 1；用中文描述搜不到，批量搜会带回完整类型声明，很长。

- 先关键词：`get_case_list`。
- 关键词查两轮仍没有合适案例，才用 `search_case`（语义），输入用一段完整的案情描述，带 `size` 和筛选条件。
- 行政处罚决定用 `search_enforcement`，检察文书用 `search_procuratorate`。

### 收敛

- 首轮没有贴合结果时，换角度再搜：先去掉非必要的地域限制，改搜全国同类案件，再扩展同义词、换法言法语表述。
- 检索不设次数上限，以收敛为止：新的检索不再带来新的贴合结果，也不改变已有判断。每一轮都要换新的关键词或角度，不重复同一搜索。
- 仍无合适结果，在"注意"里写明检索范围和不足。
- 同一个检索词加同一组筛选条件，不重复调用；语义检索每次约 125 分。
- 找不到同值或同情节的案例时，可用 [关键词](keywords.md) 里的"举重以明轻"，沿程度搜相邻的值，标明是类推。

### 读取与筛选

- 放进报告的案例，必须读取正文再判断；搜索摘要只作线索，未读取正文的不放进报告。
- 按相关度从高到低读取，直到新读的几篇不再改变判断为止，不机械打开所有结果。
- 只留裁判观点与焦点直接相关的案例。
- 官网或公众号上的案例，用 `lexora_web_fetch` 读取原文，确认发布主体，并核对案号（未披露的除外）后，才能放进报告。公众号链接是临时的，失效就重新搜。
- 排序：相似度高的在前；其次案例层级和审级；其次与用户所在地或审理法院同地域；其次近年。

### 反向核查

用户有立场，或已检得的案例集中在一方时，针对相反结果补做一次定向检索，找对我方不利或裁判方向相反的案例，单独列出。

- 法宝不能按裁判结果筛选，关键词区分不了结果方向，可以直接用一次语义检索（`search_case`，`size` 不超过 5），在检索描述里写明要找的相反结果，如"法院未予调整，全额支持"。

- 比较结果差异是否来自当事人同意与否、形成时间、证据、实际后果和程序路径。
- 未检得相反案例不等于不存在，在"注意"里写明；不为形式平衡引用不相似的案件。

### 渠道受阻

- 搜狗微信遇到 `WEB_CHALLENGE` 立即停，不重试，也不换方式绕过。该渠道记为未完成：在"注意"里写明"微信渠道未能检索"，不能当作已检索过。
- 公众号正文读不出来、链接失效重搜仍不行的，同样记为未核验。
- 法宝没配置或不可用时，明说未能核验，提示去"设置 → 网络 → 服务配置"；因额度失败时，把返回的网址原样给用户。

## 检索记录

按轮次记录，类案检索必须有，供回溯、排查遗漏，也是报告里"检索方法"的来源。

```
信息整合：法律法规 / 案件 / 文章（随检索随时补充）

周期一
- 检索命题：
- 想法：打算用什么渠道和工具
- 关键词：
- 平台：
- 结果：命中数、新增贴合数、可疑点
```

委派给子代理时，要求它回传同样的记录（见 [委派读取](delegation.md)），汇总到这里。

## 复核

放进终稿前，逐个案例核对：

1. **真实性：** 用 `anhao_recognition` 核对案号，确认标准案号、标题、法院、审结日期。核不出的，按"未检得"处理，不引用。
2. **交叉：** 同一个案例在法宝和法院、检察院官网或公众号能互相印证的更可靠；只在一处出现的，在报告里注明。
3. **改判：** 案例可能被二审、再审改判。返回里有审级或后续审理信息的，核对；没有的，提示用户自行核对。
4. **法律是否修改：** 案例适用的法条之后是否修订、废止；报道中引用的旧法条，另行核对现行规定。
5. **日期：** 报告版写明检索日期，简版不写。

## 作答前自检

- 关键线索：放进报告的案例，都读过正文了吗？
- 真实性：每个案号都核验过了吗？
- 反向核查：有立场或案例集中一方时，做过相反方向的检索了吗？
- 渠道：网页和微信都完成了检索吗？没完成的写进"注意"了吗？
- 边界：没查到的、只有报道没有文书的、地域不同的、未读取正文的、类推得出的，都在"注意"或措辞里体现了吗？

任何一项没做到，先补；补不了就如实写明，不用措辞掩盖。

## 作答

用户没要求报告时，给简版，直接写在回复里。用户要求检索报告时，出报告版。篇幅随命题而定，可以是几行，也可以是几页。

**报告首先是给用户自己看的个人版，用户在它的基础上修改。** 所以：

- 报告写成 Markdown 文件，放进当前对话的工作区，用 `lexora_output` 的 `present` 交给用户，方便用户直接编辑，也可以选中某段让你修改。回复里只写结论，加文件位置。用户之后要 Word 时再转换，不预先生成。
- 个人版要全面：无效检索、全部支持和不支持的案例、完整检索记录都保留，不按对象删减。用户自己决定删什么。
- 不要一开始就问报告给谁看，也不按对象改写。
- 用户之后说要给法官、客户或团队看的，再在个人版的基础上，按下面的"按呈报对象取舍"另存一份新文件，不覆盖个人版。

**简版**

```
**结论**：一两句话，说明这批案例整体怎么判、对本案意味着什么。

**焦点一：<要回答或证明的观点>**
检得 N 个：支持 M 个，不支持 K 个。

支持
- （案号或"官方案例报道，未披露案号"），法院（地域），日期，文书类型　[法宝](链接)
  相同：与本案一致的关键事实。
  不同：影响结果的差异。
  结果：判决 / 裁定 / 调解 / 执行结果，及一句话理由。

不支持
- （格式同上；没有则写"未检得"，并说明检索范围）

**焦点二：<…>**
（同上）

**注意**：最关键的前提或例外，没查到的，渠道未完成的，案例是否改判需自行核对。
```

"支持""不支持"指对该焦点所设观点的态度。观点用肯定句表述，如"约定违约金每日千分之三应予支持"。用户有立场的，观点取我方主张；"不支持"一组就是对我方不利的案例，由反向核查得来。

**报告版格式**

参照无讼《如何写出清晰完美的法律检索报告》的范本，覆盖检索问题、工具、方法、结果、分析、结论、日期七项要素。

- 一份报告最多解决一到两个法律问题。开头只写检索目的，直指要解决的问题；不写案由，不交代案件背景，也不是分析案件、得出代理思路的文书。
- 检索分析力求中立，不以结论倒推分析。

```
1. 检索目的
   1-1 <法律问题一，法言法语>
   1-2 <法律问题二，没有则省略>

2. 检索工具
   <法宝、网页搜索、搜狗微信等>

3. 检索关键词
   <按轮次，取自检索记录；含筛选条件和范围顺序>

4. 检索法规及其他文件
   4-1 无效检索
       <检索过但与问题无关的规范，只列名称。个人版保留；对外版除非要说明立法倾向，否则删>
   4-2 有效检索，按位阶排序
       4-2-1 法律
             《全称》第X条：<原文>　[法宝](链接)
       4-2-2 行政法规、司法解释、部门规章、地方性法规
       4-2-3 其他规范性文件

5. 检索案例（每个案例带链接）
   5-1 支持<某观点>的案例
   5-2 不支持<某观点>的案例
   案例按审判机关高低排列；对某一地区司法实践有特殊需要的，单独列出。
   【案例 ① <标题>】
   案号：<…>，审理法院：<…>，审结日期：<…>，文书类型：<…>，参照级别：<…>
   裁判要旨：<原文摘引，保持法院表述，不改写>

6. 检索分析
   6-1 法律分析：立法层面，规定了什么、没规定什么、位阶与适用上的问题。
   6-2 案例分析：司法层面。
       支持与不支持各占多少（检得 N 个，其中 M 个……）。
       驳回的路径，逐条归类，标注案例编号。
       支持的原因、请求权基础、赔偿计算方法。
       裁判倾向可用图表表示。

7. 检索结论
   <短句，直接回答检索目的中的问题>

8. 注意
   <没查到的、渠道未完成的、类推得出的、案例是否改判需自行核对>

9. 检索日期

附：检索记录
   <各轮的命题、想法、关键词、平台、结果；个人版保留，对外版可删>
```

范本里的"检索用时"不写：模型无法如实计量工作量。个人版里 4-1 无效检索保留，不是可选。

**按呈报对象取舍**（用户要求改成给某对象的版本时才用，从个人版派生）：

| 对象 | 着重 |
|---|---|
| 法官 | 案件事实的相似性；法律适用的权威性（上级法院、指导性案例优先）；案号必须完整，便于溯源。去掉无效检索和检索记录 |
| 客户 | 类案的结果分布和各种可能；据此提示策略。检索量有限，不是统计意义上的比例，只写"检得 N 个，其中 M 个……" |
| 团队 | 有利和不利的案例都列，对抗性思维：有利的怎么用，不利的怎么规避 |

写法：

- 案例只放本次工具返回的内容，链接用工具给的。没查到的写进"注意"，不用相近的顶替。
- 案例要标明法院所在地域。与用户所在地不同的，在"注意"里说明各地口径可能不同。
- 结论措辞随证据强度走：有裁判文书或指导性、公报案例支撑的，可以直接给倾向；只有官方案例报道（未披露案号）或律师观点的，写成"有报道显示……，尚无裁判文书印证"；类推得出的，标明是类推；渠道未完成或正文未读的，不据此下结论。
- 链接文字写出处：`法宝`、`某某法院官网`、`某某法院公众号`、`律师·作者`。律师文章只作实务观点，标明作者和日期；其他自媒体只作检索方向，不引用。
