# 委派读取

案例、文章的检索和阅读会返回大量文本，直接在主对话里做，上下文很快耗尽。把这部分交给检索员（子代理）：它检索、阅读、判断相关性，只把结构化摘要交回来。

## 何时委派

案例的检索和阅读属于需要隔离的大量研究，按本节规则委派，优先于"有界任务默认自己做"。

- 类案检索：一律委派。
- 实务检索：预计要读超过 3 个案例或 2 篇文章，或需要第二轮检索时委派；否则自己做。
- 一般检索：不委派。
- 自己做时，每次只读最相关的段落（案例的"本院认为"和裁判结果），不通读全文。

## 分工

| 环节 | 谁做 |
|---|---|
| 命题、案情分解、检索策略、每轮是否继续 | 主代理 |
| 法条读取、沿革、效力 | 主代理（输出小） |
| 案例检索与阅读、网页和公众号的搜索与阅读 | 检索员 |
| 案号核验（`anhao_recognition`）、终稿引用核对 | 主代理（输出小，不信任检索员的结论） |
| 汇总、对比、成文 | 主代理 |

## 找检索员

先用 `lexora_agents` 的 `list` 看可用对象和它们的工具。

- 有带法宝案例工具（`search_case`、`get_case_list`）和网页工具的检索员：所有渠道都委派给它。
- 只有内置的研究员（只有网页搜索和读取工具）：网页和搜狗微信渠道的阅读委派给它；法宝案例这一路由自己做，`search_case` 的 `size` 不超过 5，只读最相关的段落，并在"注意"里写明。
- 都没有：全部自己做，并在"注意"里写明"未使用子代理，案例阅读受上下文限制"。

不要把法宝检索委派给没有法宝工具的对象。

## 任务单元与并行

- 一个任务单元 = 一个争议焦点 × 一个渠道（法宝案例 / 网页官方来源 / 搜狗微信）。
- **同一时刻最多 2 个检索员在跑，不是 5 个。** 代码模式的脚本全局只能同时跑 2 个，超出的脚本会被直接拒绝（报"Codemode worker limit reached"），请求根本没有发出，不是"没查到"。
- **分批派，不要一次全派。**
  - 第一批：法宝案例、网页官方来源，各派一个。
  - 两个都完成后（用 `wait` 等），再派第二批：搜狗微信、反向核查，各派一个。
  - 有多个争议焦点时，同一批也不超过 2 个，按焦点依次分批。
- 搜狗微信渠道只开一个，避免并发触发验证码。
- 反向核查单独开一个，只给它命题，不告诉它当前的倾向，也不给已找到的案例。
- 检索员在自己的单元内按原有规则自行收敛（换关键词、去地域、同义词，读到不再改变判断为止）。主代理只在发现缺口时再派。

委派后立即返回，不要轮询；先做自己的事（如读法条），再用 `wait` 等这一批完成，用 `result` 取报告，然后再派下一批。

## 任务单模板

发给检索员的 `text`，填入尖括号内容：

```
任务：围绕下面的焦点检索并阅读案例，回传结构化摘要。你只检索和阅读，不下结论，不做分析。

焦点：<法言法语表述的法律问题>
案情要点（已脱敏）：<与焦点相关的关键事实>
适用法条：<如有>
范围：渠道=<法宝案例 / 网页官方来源 / 搜狗微信>；参照级别=<…>；审结日期自 <…>；地域=<…>
关键词：重要=<…>；普通=<…>

规则：
1. 法宝案例先用 get_case_list 关键词查；两轮仍没有合适案例，才用 search_case（语义），size 不超过 10。
2. 放进回传的案例，必须读过正文，并摘引"本院认为"中最关键的一段原文（不超过 200 字）。没读正文的只列在"线索未读"。
3. 不设次数上限，直到新的检索不再带来新的贴合案例。每轮换新的关键词或角度，不重复，并记入检索记录。
4. 微信遇到 WEB_CHALLENGE 立即停，不重试，写入渠道状态。
5. 不得编造案号、法院、日期。没查到就写没查到。
6. 回传不超过 <N> 字，按下面的格式。
7. 回传第一行必须写状态，如实写，不夸大：完成 / 部分完成 / 失败 / 渠道受阻，后面加一句原因。遇到"Codemode worker limit reached"，说明脚本没有执行，等一会儿再试，不要当成没查到；重试仍失败，才写渠道受阻。

回传格式：
【状态】完成 / 部分完成 / 失败 / 渠道受阻：<一句原因>
【检索记录】轮次｜渠道｜关键词或描述｜命中数｜新增贴合数
【渠道状态】法宝：正常/不可用/额度不足；网页：…；微信：正常/已停（WEB_CHALLENGE）
【案例】按相关度从高到低
1. 案号｜法院（省份）｜审结日期｜文书类型｜参照级别｜链接
   与焦点：相同……；不同……
   裁判结果：……
   原文摘引："……"
   正文：已读
   可疑：……（没有则省略）
【线索未读】……
【没查到】……
```

反向核查的任务单把"焦点"改成"找裁判方向相反或对该观点不利的案例"，其余相同。法宝不能按裁判结果筛选，反向核查可以直接用一次语义检索（`size` 不超过 5），检索描述里写明要找的相反结果，不受规则 1 的限制。

## 收到报告后

- 先看第一行状态：
  - 完成：往下处理。
  - 部分完成、失败、渠道受阻：不据此下结论；原因写进"注意"；这一单元可在下一批重派一次，仍然不行就如实写明。
- 抽查：对放进终稿的案例，核对原文摘引与结论是否相符。没有原文摘引的案例，不计入。
- 核验：每个案号用 `anhao_recognition` 核对；核不出的，按"未检得"处理，不引用。
- 收敛：看检索记录里"新增贴合"。最近一轮都是零，才算收敛；否则补派。
- 渠道状态：检索员报告渠道受阻、额度不足的，原样写进"注意"。
- 检索员没读的线索，不当作已检索过。
- 不转述检索员没有给出依据的判断。

## 降级

没有检索员，或者问题简单：自己做。限制每次检索的返回条数（`search_case` 的 `size` 不超过 5），只读最相关的段落，宁可分多轮，也不一次读很多。
