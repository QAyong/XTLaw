# 随插件提供 MCP 连接

API 4 的 `contributes.mcpConnectors` 独立声明远端 MCP 连接，不需要其他贡献、`entry` 或额外插件权限。安装声明不等于连接已启用、认证已完成或远端调用已获授权。

通过 `engines.lexora` 限定实际支持此字段的宿主版本，不能仅凭 `apiVersion: 4` 宣称兼容所有 API 4 宿主。以下片段并入[插件清单](protocol.md)；保留插件身份，兼容范围填写目标宿主已确认的支持版本，不照搬其他能力的示例版本。

```json
{
  "apiVersion": 4,
  "contributes": {
    "mcpConnectors": [
      {
        "id": "legal-search",
        "name": "法规检索",
        "transport": "streamable-http",
        "url": "https://legal.example.com/mcp",
        "authentication": "bearer"
      }
    ]
  }
}
```

将示例地址替换为实际服务地址；此示例只声明连接及认证需求，不包含凭据。

## 声明约束

- 必填 `id`、`name`、`transport`、`url`、`authentication`，最多 16 个连接。`id` 为 1–64 个小写字母、数字、`-`、`_`，首字符只能是字母或数字，同包的 MCP 连接内不得重复；`name` 为 1–128 字符。
- `id` 是包内局部 ID，**不加插件 ID 前缀**，不是用户连接 ID。命令、视图、Skills 等贡献的前缀规则不适用于这里。宿主按插件来源区分连接；作者不拼接宿主内部 ID，也不能接管用户或其他包的连接。
- 只支持 `transport: "streamable-http"`。URL 最长 2048 字符，必须是 HTTPS 且不含 userinfo；不支持本机命令启动的 `stdio`。不要把 Token、密码、API Key 或其他秘密放在 URL、清单或包内资源中。
- `authentication` 必须显式提供，为 `none`、`bearer` 或 `oauth`，仅声明认证需求。凭据由用户在宿主中配置，不随插件分发；不允许请求头、凭据、`credential` 或 `deferred` 字段。声明 `oauth` 不代表任意目标宿主都支持完整登录流程，需核对实际支持。

## 配置与生命周期

连接名称、地址、传输与认证要求由插件来源管理，更新跟随来源。用户在宿主中管理凭据、启用状态和工具发现方式，这些不是清单字段。修改连接定义应更新插件；自建连接属于用户自己的配置，不会被同名插件贡献覆盖。

启用仍受来源状态与认证条件限制；安装不会自动连接或授予远端调用权限。远端工具的权限和副作用继续由宿主策略与用户授权约束，不能靠清单或提示词把它们变成只读操作。

停用、卸载插件或移除声明会使相应连接不可用。普通卸载保留用户配置，不把来源连接自动转换为用户自建连接；只有用户显式选择清理时才删除相应配置与凭据。

验收应覆盖认证配置、连接启停、真实工具发现与调用，以及更新和卸载后的不可用状态；清单解析成功不代表远端服务可用。
