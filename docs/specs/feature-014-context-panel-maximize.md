# Spec-014：资源面板最大化（收起聊天区）

**日期：** 2026-10-02
**状态：** 已实现；用户于 2026-10-03 在开发版预览后确认验收通过
**方案基线：** master（`ccfdda6c`，2026-10-02）
**实现基线：** master（`b5e14573`）
**更新日期：** 2026-10-03

> 本文档描述本次验收的最小实现：只新增最大化 / 还原按钮及必要状态接线，保留新建标签（+）、标签栏、标题栏和拖动布局的既有行为。原方案与实际实现的差异、验证范围及既有边界见下文。

## 1. 方案摘要

在资源面板头部最右端新增“最大化 / 还原”按钮；“新建标签（+）”仍跟在标签滚动区后，不移动到右侧按钮组。点击后收起聊天区，资源面板占满聊天区释放的空间；再次点击还原。

实现上不新造一套状态，而是把既有的“聊天区隐藏”升级为面板内可见的一等状态：布局层（`WorkbenchLayout.vue`）已经支持隐藏聊天区后让资源面板填满可用宽度、隐藏失效的分隔线、普通最大化 / 还原切换不把临时全宽写回宽度偏好（最大化中拖动任务侧栏的既有边界见第 10 节）；会话级记忆规则沿用 Spec-002 与 Spec-010。

已确认的取舍：

- 最大化时不收起任务侧栏（用户明确不需要）。
- 非任务页面（开启“跨页面联动”后资源面板跟随到设置、自动化等页面）允许最大化，页面导航不重置该状态。
- 不新增键盘快捷键或命令面板命令。
- 不改动标题栏既有按钮的语义（面板开合、交换位置）。
- 开发预览后，用户要求撤回额外调整，仅新增放大 / 还原入口；`+` 的位置、样式、显示条件与菜单逻辑不变。
- 保留既有“交换左右位置时还原聊天区”的行为，不实现原方案中的交换位置与最大化完全独立。

## 2. 背景与现状

用户需求原文：给资源区提供“展开（全屏）”按钮，点击后聊天窗口收起、资源面板最大化。

方案制定时的代码核查与本次实现：

- `apps/buddy/src/app/shell/DesktopShell.vue` 已持有 `chatPaneHidden`（聊天区隐藏）与 `contextOnLeft`（面板交换到左侧）两个视窗状态，并按会话/浏览模式恢复（`contextPanePlacement.ts`）。
- `apps/buddy/src/workbench/browser/layout/WorkbenchLayout.vue` 在 `workspaceVisible=false` 时让资源面板 `flex: 1 1 0%` 填满、隐藏面板分隔线、不写回宽度偏好；这部分能力已经存在且已验收（Spec-002）。
- 原缺口一：聊天区隐藏只有标题栏入口，且只在资源面板位于左侧时生效（`rightRegionIsChat`）。现新增 `toggleContextMaximize`，面板内按钮可在左右两侧切换同一个 `chatPaneHidden` 状态。
- 原缺口二：资源面板头部只有标签栏和“新建标签”按钮。现直接在既有 `NPopover` 后追加原生最大化按钮，不重组头部布局。
- `WorkbenchResourcePanel.vue` 是 workbench 层的通用容器组件，目前只被 `DesktopTaskContextPanel.vue` 使用，外加一个组件测试。改动必须保持向后兼容（不传新契约时不渲染新按钮）。

## 3. 需求边界

**包含：**

- 资源面板打开时，面板头部显示最大化按钮；按钮位于“新建标签”按钮同一区域（其右侧）。
- 点击后收起聊天区，资源面板占满聊天区释放的空间；再次点击还原聊天区。
- 资源面板位于左侧或右侧时都可以最大化；点击最大化不改变左右位置，交换位置则按既有逻辑还原聊天区。
- 最大化期间隐藏面板宽度拖动分隔线；普通最大化 / 还原切换复用既有布局宽度，不改写偏好。本次不修改拖动实现，其既有边界见第 10 节。
- 状态规则沿用现有会话级视窗状态：任务联动模式按会话分别记忆；独立浏览模式为全局临时状态；应用重启后恢复默认（不最大化）。
- 关闭资源面板时自动退出最大化（聊天区恢复显示）。
- 非任务页面（“跨页面联动”）允许最大化；页面导航保留当前状态。
- 按钮提供中英文名称与提示，并用可判读的按下状态表达当前是否最大化。
- 面板没有打开任何标签时，按钮仍然可用：最大化后显示面板空态。

**不包含：**

- 不收起任务侧栏（用户明确：不需要），任务侧栏仍使用自身的收起/展开控件。
- 不做“真·窗口全屏”：不改变窗口尺寸、不进入系统级全屏、不影响标题栏与窗口控件。
- 不新增快捷键、命令面板命令或设置项。
- 不改变标题栏既有按钮语义：面板开合按钮仍是“开/关面板”，交换位置按钮仍是左右换位。
- 不把该状态持久化到磁盘（与 Spec-002 / Spec-010 一致）。
- 不改变资源面板标签、目录树、浏览器、变更、制品等内容的既有行为。
- 不改变独立浏览模式与任务联动模式的资源选择语义。

## 4. 状态规则

| 场景 | 结果 |
|---|---|
| 新建会话，且没有历史布局记录（任务联动） | 聊天区显示，资源面板不最大化 |
| 切换到已记录的会话（任务联动） | 恢复该会话上次的资源面板开合、左右位置与最大化状态 |
| 当前会话点击最大化 / 还原 | 更新当前会话布局状态 |
| 独立浏览模式切换任务或页面 | 最大化状态作为全局临时状态保留，不重置 |
| 从独立浏览切回任务联动 | 恢复当前会话的布局；无记录则使用默认布局 |
| 关闭资源面板 | 清除最大化状态，聊天区恢复显示 |
| 资源面板位于左侧 / 右侧 | 两侧均可点击最大化 / 还原，点击不会改变左右位置 |
| 点击标题栏交换位置 | 交换左右位置，并按既有逻辑清除 `chatPaneHidden`、退出最大化 |
| 应用重启 | 恢复默认（聊天区显示、面板不最大化） |

## 5. 交互流程

### 正常流程

1. 用户打开资源面板。
2. 面板头部显示最大化按钮（图标为“展开”，提示「最大化资源面板」）。
3. 用户点击后，聊天区收起，资源面板占满聊天区释放的空间；按钮切换为“还原”图标与「还原资源面板」提示，按下状态为真。
4. 用户再次点击，聊天区恢复显示，资源面板恢复此前的可调宽度。

### 边界与失败

- 资源面板未打开时按钮不可见；面板容器可能仍挂载于隐藏的布局中，标题栏按钮语义保持现状。
- 面板为空（没有打开任何标签）时，按钮仍可用；最大化后显示面板原有空态启动器。
- 面板位于右侧时，点击标题栏开关关闭面板，并清除最大化状态；位于左侧时，该开关仍控制右侧聊天区，可直接还原聊天区。
- 最大化状态下收起/展开任务侧栏：互不影响，侧栏行为保持现状。
- 面板位于左侧且最大化时，标题栏“当前右侧区域”按钮的既有语义（开关聊天区）保持不变。

## 6. 界面设计

### 6.1 位置与结构

最大化按钮作为独立原生 `<button>` 放在面板 header 最右端，使用 `margin-left: auto` 与 `margin-right: 0.375rem`。不新增右侧按钮组，不移动或修改 `+`；`+` 仍紧随标签滚动区，且仅在有标签时显示。DOM 顺序仍为 `标签滚动区 → 新建标签 → 最大化`，无标签时只保留最大化按钮。

```
资源面板 header（默认）
┌──────────────────────────────────────────────────────────────┐
│ ┌文件┐ ┌变更┐ ┌浏览器┐ [+]                           [↗]      │
├──────────────────────────────────────────────────────────────┤
│ （可选）工具条                                                │
├──────────────────────────────────────────────────────────────┤
│  内容区（tree / 预览 / 差异 / 网页 …）                        │
└──────────────────────────────────────────────────────────────┘
   └──── tablist（可横向滚动）────┘ [+]              独立最大化按钮
```

### 6.2 整窗线框

**默认（面板在右）**

```
┌───────────────────────────────────────────────────────────────────────────┐
│ 标题栏                          [⇄交换] [▤面板]  [—] [□] [×]              │
├──────────────┬───────────────────────────────┬────────────────────────────┤
│ 任务侧栏      │ 聊天区                         │ 资源面板                    │
│              │                               │ ┌──────────────────────────┐│
│              │                               │ │[文件][变更] +      [↗]   ││
│              │                               │ ├──────────────────────────┤│
│              │                               │ │  预览 / 差异 / 网页       ││
└──────────────┴───────────────────────────────┴────────────────────────────┘
```

**最大化（点击后）**

```
┌───────────────────────────────────────────────────────────────────────────┐
│ 标题栏                          [⇄交换] [▤面板]  [—] [□] [×]              │
├──────────────┬────────────────────────────────────────────────────────────┤
│ 任务侧栏      │ 资源面板（占满聊天区释放的空间，分隔线隐藏、不可拖动）        │
│              │ ┌──────────────────────────────────────────────────────────┐│
│              │ │[文件][变更] +                                     [↙]   ││
│              │ ├──────────────────────────────────────────────────────────┤│
│              │ │  更宽的预览区（表格 / 代码行不再被挤压）                   ││
└──────────────┴────────────────────────────────────────────────────────────┘
```

- 只收起聊天区；任务侧栏不动（见第 1 节的已确认取舍）。
- 面板位于左侧时镜像处理：面板仍在左，聊天区在右被抽走。
- 普通最大化 / 还原切换不改写宽度偏好；本次未修改 `WorkbenchLayout.vue` 或拖动逻辑。

| 项目 | 取值 | 来源 |

按钮状态表：

| 状态 | 表现 |

| 已最大化 | 还原图标，`aria-pressed="true"` |

点击行为：切换「聊天区显示 / 收起」。不新增动画——与当前 `chatPaneHidden` 的既有行为保持一致；若后续需要过渡动画，另行提出。

### 6.5 键盘与无障碍

- Tab 顺序：`标签 → 标签关闭 → 新建标签 → 最大化`。
- `Enter` / `Space` 触发切换；按钮为原生 `<button>`。
- `aria-label` 随状态切换，`aria-pressed` 表达当前是否最大化；不使用图标作为唯一语义来源。
- 悬停提示使用原生 `title`，与 `aria-label` 同步切换；不引入 `NTooltip` 或额外提示状态。
- 按钮复用现有 `.desktop-task-context-panel__add` 样式，新加的 `.desktop-task-context-panel__maximize` 仅负责自身右对齐；不修改 `+` 的样式或布局。

### 6.6 设计取舍

- 放面板 header 而不是标题栏：入口与作用对象在同一个容器里，离视线更近；标题栏维持“开关面板 / 交换位置”两个语义不变。
- 复用 `chatPaneHidden`：Spec-002 与 Spec-010 已经定义了它的布局行为与会话级记忆规则，不新造状态，避免两套真相。
- 不做窗口全屏：本功能的目标是“把聊天区的空间让给资源面板”，不改变窗口本身。

## 7. 实现要点

状态链路沿用现有 props / emit 方式（与 `chat-pane-hidden` 同一条链路），不新增全局注入：

| 文件 | 中文说明 | 本次职责 |
|---|---|---|
| `apps/buddy/src/workbench/browser/WorkbenchResourcePanel.vue` | 资源面板容器（头部标签栏） | 新增可选的最大化契约（状态 + 事件）；未传入时不渲染按钮，保持向后兼容 |
| `apps/buddy/src/modules/tasks/widgets/context-panel/DesktopTaskContextPanel.vue` | 桌面资源面板封装 | 透传最大化状态与事件 |
| `apps/buddy/src/modules/tasks/widgets/context-panel/DesktopTaskResourcePanel.vue` | 任务资源面板装配 | 接收宿主状态并透传给面板容器 |
| `apps/buddy/src/app/workbench/DesktopWorkbenchArea.vue` | 桌面工作区区域 | 把最大化状态与切换动作接到资源面板 |
| `apps/buddy/src/app/shell/DesktopShell.vue` | 桌面外壳 | 把 `chatPaneHidden` 变为对资源面板可见的状态；移除“只有面板在左才能隐藏聊天区”的限制；保留关闭面板时清除、按会话记忆的既有行为 |
| `apps/buddy/src/app/shell/contextPanePlacement.ts` | 会话布局状态策略 | 复用现有规则；除非实现需要，不改变语义 |
| `apps/buddy/src/i18n/locales/zh-CN/tasks.ts`、`apps/buddy/src/i18n/locales/en-US/tasks.ts` | 文案 | 新增第 6 节的两个键 |
| `apps/buddy/src/workbench/browser/__tests__/WorkbenchResourcePanel.spec.ts` | 组件测试 | 覆盖按钮渲染、事件触发，以及未传契约时不渲染 |

补充说明：

- `WorkbenchResourcePanel.vue` 属于 workbench 通用层，不得直接依赖桌面外壳状态；状态通过 props / emit 传入传出。
- 标题栏按钮的既有分支逻辑（“当前右侧区域是聊天 → 切换聊天区”“否则开关面板”）保留；本次只是让同一状态在面板内也有入口。
- 三层面板组件使用可选 `maximized?: boolean`，并显式将默认值设为 `undefined`，避免 Vue 将未传入的 Boolean prop 转为 `false`；未提供契约时不渲染按钮。
- 新按钮的渲染条件为 `maximized !== undefined`，与标签数量无关；面板是否可见仍由既有布局控制。
- 状态事件链：`WorkbenchResourcePanel.toggleMaximize` → 两层任务面板透传 → `DesktopWorkbenchArea.toggleContextMaximize` → `DesktopShell.toggleContextMaximize`。宿主仅在资源面板打开时切换状态。

| `chatPaneHidden` | 聊天区隐藏状态 | 现有会话级视窗状态，本方案将其作为“资源面板最大化”的实现基础 |
| `contextPanePlacement.ts` | 会话级视窗状态策略 | 决定切换会话/模式时恢复哪一组布局状态（Spec-002、Spec-010） |
| `workspaceVisible` | 聊天区可见性 | `WorkbenchLayout.vue` 的布局入参，为假时资源面板填满、分隔线隐藏 |
| 最大化 | 资源面板填满聊天区释放的空间 | 本文档统一用词，不使用“全屏”，避免与窗口全屏混淆 |

## 10. 已知边界与后续风险

- 非任务页最大化后，页面正文会被资源面板替代（用户已确认允许）。若后续认为体验不佳，可在不改布局的前提下补一条“离开任务视图自动还原”的规则，属于可选后续项。
- 资源面板在非任务页显示依赖“跨页面联动”设置；该设置本身不在本次范围内。
- 本次只新增按钮和状态接线，保留 `chatPaneHidden` 不随页面导航重置的既有行为。未启用跨页面联动时，最大化后离开任务页面仍可能隐藏页面正文；本次没有加入“面板不可见时显示正文”的额外保护。
- `useWorkbenchPanelResize.beginResize` 仍会读取资源面板当前渲染宽度。最大化中拖动任务侧栏可能将临时全宽写入资源宽度偏好；相关保护在用户要求撤回额外改动后未纳入本次实现。普通按钮切换不涉及该写入，拖动场景需另行处理与验收。
- 原方案中的“左右交换不退出最大化”未纳入最终最小实现；现状仍为交换位置时还原聊天区。
