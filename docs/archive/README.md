# 归档目录说明

这里保存已完成、已验收或已被取代的文档。内容按原目录分成四个子目录，文件名和编号保持不变，只读参考；再次引用时按原文件名和编号引用。

## 子目录

| 子目录 | 内容 | 归档条件 |
| --- | --- | --- |
| `bugs/` | 缺陷记录 | 已修复并验收 |
| `specs/` | 功能规格与决定记录 | 状态为已验收或已被上游取代，且没有遗留待办 |
| `upstream/` | 手动上游集成记录 | 超过约一周 |
| `drafts/` | 文档草稿 | 已发布的发布说明 |

## 查阅

- 没有逐文件的索引，按文件名中的日期、编号或标题查找。
- 移动时已同步修正指向被移动文件的相对链接。在归档目录里写新引用时注意层级：`archive/specs/` 引用 `archive/upstream/` 用 `../upstream/`；引用仍在 `docs/specs/` 的活跃规格用 `../../specs/`。
- 追溯历史：`git log --follow -- <当前文件路径>`。
- 归档文档里的命令、构建输出位置和验证状态按当时的情况理解，不代表当前环境。

## 不归档的内容

- `docs/upstream/WORKFLOW.md`：长期有效的流程文档。
- `docs/upstream-baseline.json`、`docs/upstream-auto-*-integration.md`：自动化和人工流程读取或写入的固定路径。
- `docs/windows-dev-notes.md`：仍被 `AGENTS.md` 引用的当前排错说明。
- 仍未修复、未验收或未发布的缺陷、规格和草稿。
