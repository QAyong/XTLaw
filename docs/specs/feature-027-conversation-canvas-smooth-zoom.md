# 分支面板缩放流畅性优化方案

## 状态

已完成实现，用户开发预览验收通过。

B+C 已在源码中实现，画布相关的轻量单测及改动文件格式检查通过。已启动独立的 XTLaw Dev 桌面窗口供用户预览，用户确认“验收通过”。该确认记录整体交互验收结果，不等同于各项性能指标或所有规模场景均已量化验证；未录制性能数据，也未生成安装包。

## 为什么要做

聊天窗口的分支面板在放大、缩小过程中，用户观察到内容消失后重新出现，操作不够流畅。

通俗地说：用户正在缩放画面，程序却可能同时把一些卡片拆掉，再重新装回来；卡片中的文字、附件等内容也会增加渲染负担。

实施前读取 `apps/buddy/src/modules/tasks/widgets/canvas/useConversationCanvas.ts` 确认：

- 画布开启了 `virtual: true`。
- 缩放百分比随每次 `scale` 事件更新。
- 数据呈现更新没有按缩放、平移交互暂停。

引用会话曾分析 X6 虚拟渲染存在节点卸载、重新挂载的路径。这是重点排查方向，但是否构成用户机器上闪烁的全部原因，仍需实际复现确认。

## 推荐方案：B+C

一句话：**操作时别拆卡片，缩小时少画细节。**

### B：先解决“消失一下又出现”

用户放大、缩小或拖动画布时，尽量保持卡片挂载稳定；等操作停止后，再处理屏幕外不需要显示的内容。

配套处理：

- 将连续交互统一纳入一个交互状态控制器。
- 对中小规模画布，交互期间暂时关闭卸载式裁剪，结束后恢复。
- 工具栏百分比按动画帧合并更新，避免同一帧重复更新。
- 交互期间延后流式输出引起的画布呈现更新，结束后补上最新状态；聊天数据接收不暂停、不丢弃。
- 小地图只延后昂贵的内容刷新，表示当前视口的框仍跟随移动。
- 切换会话、隐藏面板、卸载时清理定时器和交互状态，正确处理待更新内容。

注意：关闭虚拟渲染可能一次性挂回所有节点，导致交互开始时卡顿。因此不能对所有规模无条件采用这一策略，需要规模保护，并观察首次操作的成本。

### C：再解决“卡片多了，缩放还是吃力”

卡片缩得很小时，许多细节已经看不清，没有必要继续完整绘制。

简略模式保留：

- 节点身份与状态。
- 一句简短的正文摘要。
- 选中状态和当前分支标识。

暂时隐藏附件预览、产物卡、引用区和详细统计，并减少阴影及装饰动画。放大后恢复完整内容。

这只是显示层降级，不删除消息、附件或产物。

关键约束：

1. 使用交互结束后的稳定缩放值，不在连续缩放期间逐帧切换模式。
2. 进入和退出简略模式使用不同阈值，避免边界附近反复切换。
3. 简略模式只减少内部显示内容，不改变卡片的布局尺寸、位置和连线锚点，避免整张分支图重新排布。

## 可选项：按钮缩放平滑过渡

点击“＋、－”突然跳到新比例，与节点消失再出现是两个问题。

如需改善按钮手感，可增加短时、可中断的平滑过渡，并遵循减少动态效果设置；Ctrl+滚轮保持直接响应。

不能只增加动画来掩盖节点卸载和重新挂载的问题。

## 当前参数（开发预览验收通过，规模边界仍待量化）

| 参数 | 初始建议 | 说明 |
| --- | --- | --- |
| 交互结束等待时间 | 约 160ms | 连续操作停止后再恢复裁剪和补更新 |
| 进入简略模式 | 缩放低于 0.55 | 初始试用值，按实际效果调整 |
| 恢复完整模式 | 缩放高于 0.65 | 与进入阈值错开，避免反复切换 |
| 稳定挂载规模保护 | 以 300 个节点为初始参考 | 不是已验证的安全界限，还需考虑卡片复杂度、边数量及首次挂载成本 |

## 实施顺序

1. 复现并记录修改前的闪烁、节点装卸和帧耗时情况。
2. 建立共用的交互状态控制器，先实现 B，确认闪烁和首次操作成本。
3. 在同一控制器上实现 C，独立观察低缩放减重收益。
4. 如仍需要改善按钮手感，再加入按钮缩放缓动。

B 和 C 可以在同一轮工作中完成，但应保持可分别验证、分别回退。

## 验收重点

- 在启用稳定挂载策略的规模范围内，连续缩放、平移期间不再反复卸载和重新挂载已有节点；单独观察交互开始时的挂载开销。
- 操作结束后正确恢复裁剪，并补上最新画布状态。
- 边缩放边接收流式输出时，聊天数据不丢失，画布停止操作后能追上最新状态。
- 简略模式与完整模式切换不会改变卡片布局或导致连线跳动。
- 在阈值附近来回缩放，不会频繁切换显示模式。
- 切会话、隐藏面板及卸载后，没有遗留定时器、禁用裁剪状态或错误的待更新内容。
- 对比同一长会话的修改前后帧耗时、长任务和低缩放渲染负担，确认有实际改善。
- 大规模画布不因全量挂载策略出现明显性能退化。

不承诺任何规模下绝对丝滑，也不将“绝对没有超过 50ms 的长任务”作为保证。实施时遵循仓库验证约定，不默认运行全量检查。

## 暂不选择的方案

- **永久关闭虚拟渲染**：可用作快速对照诊断，但不优先作为长期方案，以免超长会话负担过大。
- **仅扩大裁剪范围**：可能缓解，但仍保留卸载、重挂载机制，不能据此认定根因已解决。
- **更换 Canvas/WebGL 渲染后端**：改动范围大，目前没有足够证据说明需要推倒重做。

## 预期效果

**拖动和缩放时，卡片不反复闪现；缩得很小时，画面更轻；放大后，细节恢复。**

主修复是 B，配套减重是 C，按钮平滑过渡独立处理。

## 本次实施记录

### 已实现

- 新增纯交互控制器，共用约 160ms 的结束去抖；按住指针时不会因暂时停止移动而提前结束交互。
- 在滚轮、指针输入的捕获阶段及工具栏缩放调用之前进入交互状态，尽量避免先裁剪再恢复挂载。
- 1–300 个已存在节点的画布在交互期间暂停虚拟裁剪，超过预算时保留裁剪；此预算仍是待实测的保护参数。
- 交互期间暂停画布布局和数据呈现同步，保留待更新标记；结束后使用最新数据同步。聊天数据接收不受影响。
- 缩放百分比使用 rAF 合并更新。
- 小地图延后内容适配刷新，视口框继续跟随移动；结束时先排队画布更新，再排队小地图刷新。
- 稳定缩放值驱动简略模式：低于 0.55 进入，高于 0.65 恢复。简略模式不改变节点尺寸和连线锚点。
- 简略模式保留头部、状态和短摘要，移除正文资源区、页脚和快捷操作，关闭阴影及运行光带；仍可打开节点详情进行操作。
- 运行节点的耗时定时器在交互期间和简略模式下暂停，恢复显示后刷新时间；交互期间暂停运行光带动画。
- 延后呈现期间拖动节点，连线使用当前屏幕上的消息尺寸，避免与尚未呈现的新状态错位。
- 切会话、切方向、隐藏面板、窗口失焦及组件卸载时结束或清理交互。操作权限变化会提前结束延后呈现，不等待长时间按住指针。
- 修正面板重新激活且小地图关闭时未主动补同步的路径。
