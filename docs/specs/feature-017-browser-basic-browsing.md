## 1. 背景与目标

用户反馈：在 Lexora 内置浏览器打开 B 站后，点击视频无法进入视频页面。用户关心的是正常手动浏览，而不是增加 AI 自动化接口。

静态代码检查发现，新窗口请求、下载、文件选择和网站权限请求存在统一拦截，未充分区分用户主动操作与 AI 操作。这些策略可能让正常网页功能表现为“点了没有反应”。

本需求目标：

1. 用户主动打开链接、上传、下载等操作能完成；不能完成时说明原因和恢复方式。
2. 内置网页具备常用导航、查找、右键和快捷键体验。
3. B 站浏览与视频播放形成可验证的完整流程。
4. 保留 AI 审批、会话隔离和敏感数据保护，不通过全局放开权限解决兼容问题。

**事实边界：** B 站问题及其真实站点验收结果来自用户报告；助手以本地夹具复现并验证新窗口路由，没有独立完成 B 站实机流程，也未补齐具体视频网址与安装版本记录。2026-10-04 用户确认撤回加载动画后的开发预览没有问题，认可本期交付；该结论不替代未执行的系统窗口、全量预检或安装包验证。

### 2.5 本轮已实现的行为变化

| 需求 | 实现方式 |
|---|---|
| BR-01 链接与新标签 | `<webview>` 元素声明 `allowpopups`，使新窗口请求到达宿主；宿主始终 `deny` 原生窗口，再把合法 HTTP(S) 目标路由到内部受管标签，或把修饰键/后台意图交给系统浏览器。人工手势 1 秒内有效，且绑定文档版本、控制纪元、可见性与“无 AI 动作中” |
| BR-02 人工上传 | 文件选择框仍由调试协议拦截；人工控制且页面可见时由宿主弹出系统文件选择框，选择结果回填到被拦截的元素；取消不算失败；对话框打开期间页面重新加载则作废并提示 |
| BR-03 人工下载 | 人工点击后的下载不再取消，交由 Electron 默认保存对话框确认路径；下载中/完成/取消/失败写入会话状态并在面板展示，完成后可定位文件 |
| BR-04 拦截反馈 | 新窗口、文件选择、下载、权限拦截不再静默；面板顶部提示条显示可读原因，相同提示 3 秒内去重；页面失败、证书错误、进程退出提供显式重试入口 |
| BR-08 网页提示与确认 | 受限、沙箱化 Guest 预加载桥接 `alert/confirm`；来源由宿主生成，校验当前页面与控制权，限制连续请求；同步确认只回写一次，保持确定/取消语义。不扩展 Node、通用 IPC 或 AI 执行能力 |
| BR-10 DevTools 与响应式预览 | “更多”菜单提供网页 DevTools 和进入/退出响应式预览；预览支持设备尺寸、手动宽高、Fit、25%–200% 显示比例、拖边/角及键盘调整；维持同一个 Guest、网页缩放和未提交输入，不模拟手机系统或浏览器 |
| BR-11 标签与数据清理 | 同步安全的 favicon，导航清旧图标并在失败时回退；清缓存保留登录相关数据，清全部增加登出提醒；开发地址解析有回归用例 |

## 3. 需求边界与分期

### 3.1 本期包含

**M1：恢复关键浏览行为（优先级 P0）**

- 复现 B 站点击视频问题；支持用户主动新标签导航。
- 手动文件上传、下载的受控流程。
- 被拦截行为有明确反馈。
- 人工操作与 AI 操作的权限边界及回归测试。

**M2：对齐 ZCode 已确认的人工浏览体验（优先级 P1）**

- 网页开发者工具、响应式尺寸模式。

- 用户提示/确认框的来源展示、加载错误与页面故障恢复。
- 清缓存与清全部数据的不同语义及确认。
- B 站视频与全屏专项验收，修复实际复现的故障；这是用户场景要求，不是已证明的 ZCode 优势。

**条件需求：** BR-05、BR-06、BR-09 的完整右键菜单、快捷键/查找、网站权限管理先保留设计，不作为追平 ZCode 的本期硬性门槛。只有用户确认扩大范围，或基础场景实测证明它们阻断使用时，再纳入实现。BR-08 的提示/确认框优先对齐，输入框和离开确认先做兼容验证。

### 3.2 后续候选（优先级 P2，单独确认后实施）

- 地址栏关键词搜索及搜索引擎选择。
- 受控外部协议转交。
- Chrome 登录态导入（按平台评估，Windows 不以对方隐藏的底层实现作为交付基线）。
- 完整浏览历史、书签、关闭标签恢复。
- BR-05、BR-06、BR-09 的扩展范围，按实际兼容问题或用户确认排期。

上述候选不是本期验收的隐含前提；不得顺手实现凭据导入或扩展权限。

### 3.3 明确不包含

- 重写浏览器引擎、建设完整 Chrome 替代品。
- 增加 AI 任意脚本执行、录屏、通用坐标控制等高级自动化能力。
- 全局关闭网页安全、证书验证、沙箱或同源限制。
- 绕过验证码、登录风控、付费限制、数字版权保护。
- 自动读取系统浏览器密码、Cookie 或其他凭据。
- 把用户手动授权自动转换成 AI 的永久授权。
- 网页加载转圈、遮罩、淡出或顶部加载条：本轮曾试做，但用户反馈加载完成后闪屏，最终要求撤回；当前交付保留原有刷新/停止按钮及宿主加载状态，不含新增加载动画及其配套修补。

## 4. 功能需求

### BR-01：链接、新标签与弹窗（P0）

1. 用户主动点击同页链接保持当前标签导航；新标签型链接在所属资源面板创建受管理的浏览器标签。
2. 对齐 ZCode：普通新标签请求在内部打开；按住 `Ctrl/Meta` 或请求意图为后台标签时，合法 HTTP(S) 链接交给系统浏览器。中键的实际事件映射通过目标平台测试确认；不得未经测试宣称完全一致。该规则替换初稿的“内部后台标签”建议，人工与 AI 的审批边界仍适用。
3. 支持常见的 `target="_blank"`（链接声明新浏览上下文）与 `window.open()`（网页请求打开窗口）场景；禁止仅移除所有拦截后交给不受管理的原生窗口。
4. 新标签保留正确的任务/独立浏览归属及浏览数据分区；无痕来源不得转入普通分区。
5. 非用户触发、来源不明或超出限制的弹窗继续拦截，并显示来源、原因和明确的后续操作。仅在能够安全重放已验证 HTTP(S) 目标时提供“打开此链接”；其他情况引导用户重试，不伪造成功。
6. 同一请求只创建一个标签；标签数量达到限制时说明原因，不静默失败、不驱逐受保护标签。
7. 第三方登录涉及空白窗口后导航、窗口间通信等情况必须单独验证；不能承诺仅复制最终 URL 就与原窗口语义等价。
8. 页面提供的 `userGesture` 等自报字段不得作为可信授权。Electron 原生输入/导航证据也必须结合 AI 控制状态及执行来源判断，防止合成输入冒充人工操作。

### BR-02：人工上传文件（P0）

1. 用户主动点击文件输入控件后，打开系统文件选择框；支持单选、多选及网站声明的文件类型过滤。
2. 取消选择不上传、不修改已有文件，不把取消显示为系统故障。
3. 仅将用户明确选择的文件交给当前目标页面；不授予页面目录扫描权，不扩大 AI 的文件读取范围。
4. 文件选择期间页面导航、标签关闭或目标失效时不得将文件交给新页面。
5. AI 发起文件选择时不得借人工通道绕过审批；保留人工接管或现有授权流程。
6. 本期必验文件输入控件；目录上传、拖放文件、剪贴板图片上传作为兼容性记录项，不默认为已支持。

### BR-03：人工下载与导出（P0）

1. 用户主动下载附件或导出文件时，通过保存对话框确认路径；支持常见 HTTP(S) 下载与网页生成的下载文件。
2. 展示下载中、完成、取消、失败状态；完成后可定位文件，不自动执行下载内容。
3. 文件名必须安全处理；覆盖已有文件前确认；不得静默写入任意路径。
4. 取消后停止后续写入；未完成文件的保留或清理策略必须明确，不得清理用户原有文件。
5. 下载状态只展示在正确归属的界面；未知来源及 AI 发起下载不得套用人工授权。
6. 关闭标签或退出应用时，对仍在进行的下载给出明确处置，不产生无法追踪的后台下载。

### BR-04：拦截与错误反馈（P0）

1. 新窗口、文件选择、下载、权限、协议拦截均不得表现为无反馈的点击失败。
2. 提示包含行为、网站来源、原因和可行恢复方式；不暴露凭据、Cookie、完整敏感路径或带令牌的 URL。
3. 提示去重并限频，网页不能借连续请求刷屏；不得用“页面加载失败”覆盖仍可使用的整页。
4. 对网络失败、证书错误、页面进程退出分别给出可识别说明和显式重试入口；不得自动跳过证书验证。

### BR-05：网页右键菜单（P1）

按命中对象提供适当菜单：链接的新标签打开/复制地址；图片的保存/复制地址；选中文字复制；可编辑区域的剪切、复制、粘贴、全选。不可用操作置灰或隐藏。

菜单必须针对当前网页而非主应用编辑器；保存动作复用下载权限与路径确认；不得在密码输入框提供泄露密码的自定义操作。保留网站自定义交互的兼容性并实测。

### BR-06：快捷键与页内查找（P1）

- `Ctrl/Meta+L`：聚焦地址栏并选中网址。
- `Ctrl/Meta+F`：打开当前网页查找，显示匹配数，支持上一处、下一处与关闭。
- `Ctrl/Meta+R`、Windows 的 `F5`：刷新当前页面。
- Windows 的 `Alt+Left/Right`：前进、后退。
- 维持现有缩放快捷键，重置缩放不影响其他标签。

网页内部、输入框、地址栏和主聊天区分别测试焦点路由；不得把浏览器快捷键错误作用到聊天或编辑器。输入法组合输入不得被误截获。`Esc` 依据当前上下文退出查找、元素拾取或全屏，不得无条件关闭标签。

### BR-07：视频与全屏（P1）

1. B 站用户流程：进入首页或搜索页 → 点击视频 → 新标签打开 → 播放/暂停 → 拖动进度 → 调整音量 → 全屏 → 退出 → 切回列表。
2. 全屏作用于正确网页，不遗留遮罩或丢失输入焦点；Esc 与播放器按钮均能退出。
3. 切换标签或折叠面板不应无故中断用户正在播放的媒体；已有音频不冻结保护不得退化。
4. 静音视频、缓冲、暂停、恢复分别验证。若休眠策略必须限制某种情况，应给出可理解的规则，不用关闭所有休眠来掩盖问题。
5. 区分网站登录/清晰度限制、网络失败、编解码或版权限制与宿主浏览器缺陷，不保证绕过第三方限制。

### BR-08：网页对话框与离开确认（P1）

验证并补足 `alert`（提示）、`confirm`（确认）、`prompt`（输入）以及 `beforeunload`（离开页面前确认）行为。展示可信来源；用户取消必须返回取消语义，不伪造确认。切换标签、关闭页面和 AI 操作期间不得死锁或误提交；连续弹窗需要限频或抑制入口。

优先复用可正常工作的 Electron 默认行为，只有确有兼容问题或来源展示不足时才新增宿主适配。

### BR-09：网站权限（P1）

1. 对拟支持的麦克风、摄像头、定位等权限逐类评审，仅在明确的网站请求和用户确认后授予。
2. 展示顶层网站、请求来源和具体权限；跨来源子框架不得冒充顶层站点。
3. 默认使用短期或当前会话授权；允许用户拒绝及撤销。持久授权、通知、剪贴板读取、屏幕共享、设备访问等未完成设计的能力继续拒绝并明确提示。
4. 操作系统权限被拒绝时说明原因；无痕授权不得写入普通浏览配置。
5. AI 不因页面已获得网站权限而获得额外执行授权；用户接管与授权等待不应被后台 AI 请求抢占。

### BR-10：网页开发者工具与响应式尺寸（P1，对齐 ZCode）

1. 为人工用户提供当前网页的 DevTools 入口；目标必须是该网页 Guest，不是 Lexora 主应用。关闭或重建网页后入口状态正确。
2. 该入口不自动向 AI 开放任意页面脚本、CDP 连接或主应用调试权限。
3. 提供独立的响应式模式：设置宽高、显示比例和适配面板；退出后恢复自然尺寸。普通页面缩放与视口尺寸必须清楚区分。入口在“更多”菜单，活动时同一菜单项切换为“退出响应式预览”，不另占工具栏按钮。
4. 调整尺寸、切换面板不能重建页面而丢失输入/登录状态；AI 正在操作时遵循既有接管规则，禁用尺寸修改。
5. 画布居中，默认逻辑尺寸为 393×852；宽高在失焦或 Enter 时提交，Escape 恢复，非法草稿保留并提示。支持拖边/角和方向键调整，Shift 使用 10px 步长；显示比例有 Fit 及 25%、50%、75%、100%、125%、150%、200%。
6. 设备预设只改变 CSS 视口尺寸；选择后自动 Fit，手动修改或拖动至非预设尺寸时显示“自定义”。明确提示不模拟手机系统或浏览器，不更改用户代理、触摸能力或设备像素比例。CDP 保持 `mobile: false`，显示比例由宿主组合图层实现，不改变网页自身缩放。

### BR-11：标签状态、地址兼容与数据清理（P1，对齐 ZCode）

1. 页面标题和站点图标同步到所属标签；导航后不得残留旧站点图标，图标失败不阻断页面。
2. 标签切换、任务切换和面板折叠后，页面历史、滚动、未提交输入在正常存活期间保持。资源回收与进程故障时明确区分恢复能力，不保证所有网页状态可重建。
3. 对本机、私网、IPv6 回环及带端口的开发地址建立解析用例；公网域名默认 HTTPS。异常和不支持协议明确提示，不把关键词擅自当搜索请求。
4. 清缓存保留登录相关数据；清全部明确说明退出登录并确认。与正在进行的 AI 控制/维护互斥，不因清理造成跨分区误删。
5. 不因对齐 ZCode 而改变 Lexora 的重启恢复策略；跨进程恢复另行确认。

## 5. 人工与 AI 权限边界

| 行为来源 | 处理原则 |
|---|---|
| 宿主识别的用户主动操作 | 走人工浏览流程；涉及文件、设备等使用明确选择或确认 |
| AI 正在执行的动作 | 继续遵守现有审批、敏感输入保护与执行前目标校验 |
| 来源不明或证据过期 | 保守拦截并给出反馈，不降级为人工来源 |
| 网页脚本自报用户同意 | 不构成授权 |

约束：

- 仅依据 `controller === 'human'`（当前控制者状态）不足以证明每个请求均由人工触发；必须处理延迟请求、控制权切换和 AI 合成输入。
- 具体来源关联机制属于实现设计，需先验证 Electron 可提供的事件证据，不能凭假设增加信任字段。
- 所有待确认请求绑定来源、页面身份与有效期；导航、销毁、撤销后拒绝旧回调。
- 同一授权只覆盖对应行为，不跨任务、标签或隐私分区复用。
- 不修改现有普通浏览登录态共享语义；新增标签须遵循既有分区规则，控制归属不等于 Cookie 必须逐任务隔离。
- 不放开网页对宿主 Node.js、预加载接口或任意本地文件的访问。

## 6. 关键场景

### 6.1 B 站视频跳转

正常：用户点击视频卡片 → 宿主识别新标签意图 → 在正确归属下创建标签 → 加载视频并保留原列表。

异常：无法可信关联来源或达到标签上限 → 当前页面保留 → 显示具体原因和安全的恢复入口，不静默丢弃。

### 6.2 上传期间目标变化

用户打开附件选择框 → 页面导航或关闭 → 用户完成选择 → 校验发现目标过期 → 取消交付并提示重试；不得把文件上传给导航后的页面。

### 6.3 AI 控制期间用户接管

AI 操作页面 → 用户通过既有接管机制获得控制 → 旧 AI 操作失效 → 用户随后主动下载走人工确认流程；迟到的 AI 下载请求不得被当成人工请求。

## 8. 实施建议与风险

1. 先建立复现夹具，区分网页事件没触发、新窗口被拒绝、导航失败和媒体兼容问题。
2. 先设计人工来源识别及请求失效规则，再放开具体操作；不要直接删除统一拦截。
3. 复用现有标签、会话、控制权、分区和审批机制，避免另建不可见浏览器或不受管理的窗口。
4. 按 M1、M2 分批交付，每批同时加入正向与安全反例测试。
5. 本期先以用户当前 Windows 环境验收；快捷键、保存框和权限实现保持跨平台兼容，不以 Windows 实现推断其他平台已验收。

主要风险：AI 合成输入被误认为人工；登录弹窗窗口关系丢失；下载覆盖文件；导航竞态导致错误页面获得文件/权限；媒体全屏与面板布局冲突；错误提示泄露敏感 URL；放开权限后扩大攻击面。

## 9. 未决事项

以下区分当前交付决策和后续待确认项；未纳入的扩展不因本期验收通过而自动获批：

1. **新标签路由：** 当前按用户要求对齐 ZCode，普通请求内部打开，修饰键/后台意图外部打开。若改为传统浏览器的内部后台标签，应作为明确差异另行确认。
2. **下载位置：** 建议本期每次保存确认；固定下载目录和“始终允许”后续再设计。
3. **网站权限清单：** 建议先支持摄像头、麦克风、定位的短期授权；屏幕共享、通知、设备权限等另行评审。
4. **关闭中的下载：** 已确定为活动下载需确认；拒绝关闭则保持运行，确认关闭则取消并释放跟踪，销毁/退出同样停止。不新增失去归属的后台下载，不主动删除用户原有文件。
5. **静音视频休眠：** 需结合现有资源策略确定可可靠识别的活动条件和测试标准。
6. **后续范围：** 搜索、外部协议、登录态导入和条件需求需单独确认；DevTools 与响应式尺寸已纳入 P1 对齐范围。
