# Spec-013：工作台选区引用与多分屏目标

**日期：** 2026-10-02

**状态：** 文件/Markdown 第一批已获用户开发预览确认；浏览器主文档元素引用及本批反馈修正已获用户验收通过（2026-10-03）；插件接入等完整方案剩余范围仍待后续

## 1. 方案摘要

把“选定内容 → 添加到对话输入框”的后半段做成工作台公共能力，内置视图和插件视图通过各自采集适配器接入。区分两条入口，不强制统一采集交互：

- **文字选区：** 文件、Markdown、聊天等视图中拖选文字，再通过右键引用；第一版不做选区浮条。
- **浏览器元素拾取：** 点击浏览器的元素选择按钮，进入拾取模式，再点击网页元素；保留按钮入口，不改成文字选区右键。

统一的是目标路由、引用附件展示、预览与移除、发送与历史。以现有对话引用组件作为视觉与交互参考之一，不把长文本或元素上下文直接塞进输入框正文。

引用交互尽量与目前聊天窗口一致：选定内容后直接添加引用，不增加独立评论设置、评论字段、评论框或评论确认步骤。用户仍在原有聊天输入框中正常输入消息，沿用现有发送流程。

多分屏下，默认目标来自资源视图与对话的明确关联；右键菜单或元素拾取的添加环节明确展示目标名称。没有明确关联且有多个候选时，由用户选择。一次操作只能写入一个确定的草稿，不允许广播给所有输入框。

> 本文保留完整设计方案；用户已授权实施文件/Markdown 闭环，以及参考 ZCode 实现浏览器元素引用。实际范围与验证证据见第 12、13 节；插件接口、跨框架拾取及全方案验收清单不能视为已完成。

## 2. 背景与现状

设计开始时，聊天正文已有右键引用能力，输入框已有引用卡片，但还没有覆盖文件、Markdown、浏览器元素和插件内容的统一引用接收与目标路由通路。以下记录初始核查；文件/Markdown 与浏览器实现后的变化见第 12、13 节。

根据用户澄清，浏览器在本方案中的采集交互是“先点击按钮，再点击网页元素”，不是拖选网页文字。此要求与下述代码核查现状分别记录，不能把两种采集方式混为一谈。

代码核查得到的现状：

- 聊天选区只识别聊天正文及其消息来源，不能直接作为任意资源的选区读取器。
- 现有消息引用来源要求会话、分支、消息等信息，不适合给文件或网页伪造一组消息身份。
- 输入框已经有独立的会话引用、消息引用和资源附件区域，可作为接入基础；不意味着这些数据类型必须合并。
- 工作台菜单已有内容捕获与结果应用机制，但尚不等于本方案所需的跨视图目标路由服务。
- 资源面板已有任务联动和独立浏览两种模式，本方案不能改变它们的布局与资源选择语义。

用户要解决的是：阅读内容时，能把文字选区或拾取的网页元素上下文连同来源交给指定对话，并继续自行输入问题、确认发送。

## 3. 范围与非目标

### 包含

- 工作台公共内容快照、目标解析和引用添加能力，区分文字选区与网页元素上下文。
- 文字选区的右键入口，以及浏览器“按钮 → 点击元素”的独立拾取流程。
- 两种采集方式共用多分屏目标选择规则和引用接收通路。
- 参考现有对话引用卡片的紧凑展示、完整内容预览、移除和来源定位。
- 文件编辑、文本/Markdown 预览、浏览器元素拾取和插件视图的接入契约；具体实现按视图分批验证。
- 来源快照、引用和目标草稿之间的作用域隔离。
- 重复添加、长度限制、目标失效、来源失效等反馈。
- 发送后的历史引用展示和内容快照保留。

### 不包含

- 文字选区浮条、常驻的全局目标选择器、拖拽引用、快捷键或新面板。
- 强制将浏览器元素拾取改成右键文字引用，或把网页拖选文字作为浏览器接入的前置条件。
- “总结、翻译、解释”等一键动作，也不新增侧边对话。
- 引用专属的评论设置、独立评论字段、评论输入框、评论弹窗或必填评论步骤。普通聊天正文不属于引用评论。
- 自动发送、自动新建任务、自动切换任务或强制抢占输入焦点。
- 重做工作台布局、资源面板联动模式或全部附件视觉。
- 图片、音视频、扫描 PDF 的文字识别，以及任意跨框架或跨域内容的自动选区提取。
- 因添加引用而自动授予整份文件读取或网页访问权限，也不默认采集整页内容。
- 全仓库重命名现有引用类型，或直接复用聊天消息来源来表示文件、网页。

## 4. 两种采集入口

### 4.1 文字选区：右键引用

以下右键规则只适用于文字选区，不用于替代浏览器元素拾取。

1. 用户在支持文字选区的视图中选中非空文字。
2. 在该选区内右键，视图提供选区快照，工作台解析可用目标。
3. 菜单显示明确的添加入口；用户点击主项或选择子菜单目标。
4. 宿主重新校验目标，直接把引用添加到该目标的附件区域，不弹出评论输入或要求填写评论。
5. 用户可以继续阅读、继续添加引用，或在原有目标聊天输入框中正常输入消息并手动发送；不增加引用专属的填写或确认环节。

空选区、跨不支持边界的选区、右键位置不属于该选区时，不提供引用项。新增的引用菜单跟随目前聊天窗口的交互，不额外添加“复制”按钮或为它设置分隔线；不重做完整右键菜单。文件编辑器等视图原有的复制、编辑操作保持不变，不删除也不重复添加。既有复制快捷键（例如 `Ctrl+C`）继续可用；不要在应用根节点拦截所有右键菜单。

### 4.2 文字选区菜单示意

以下只展示本功能的引用操作。当前文件/Markdown 入口采用组件菜单承载原有适用的编辑操作和引用项，不替换其他视图的右键菜单。

未分屏且只有一个可用默认目标时：

```text
引用到对话
```

已经分屏且有明确默认目标时（即使只有一个可写目标也不使用“当前对话”）：

```text
引用到「修复登录问题」
引用到其他对话          ▸
```

没有其他可用目标时，只显示第一项。存在其他可用目标时才显示“引用到其他对话”。主菜单与子菜单复用现有 NDropdown、主题字体、圆角和行高；宽度复用菜单栏的 `12.5rem`，公共最大宽度为 `17.5rem`，并限制为不超过视口宽度减 `16px`。长标题单行省略，保留完整标签和无障碍名称，不弹出原生悬浮提示，目标身份不随显示截断变化。子菜单示意：

```text
左侧 · 修复登录问题      ✓
中间 · 阅读项目架构
```

没有明确关联且有多个可用目标时：

```text
引用到对话              ▸
```

没有可用目标时，引用项不可用，并显示“请先打开可接收引用的对话”；不擅自创建任务。

菜单支持键盘方向键、确认和 Esc 关闭；目标名称截断后仍可查看完整名称。未分屏的中文文案最终确认为“引用到对话”（`desktop.chat.quoteToCurrent`），只调整文字，目标选择逻辑和样式不变；英文保留 `Add to current conversation`。其他新增菜单和反馈文案均提供中英文。

### 4.3 浏览器：按钮进入元素拾取

```text
点击元素选择按钮
→ 进入拾取模式
→ 点击网页元素
→ 获得该元素的上下文快照
→ 明确添加目标
→ 添加到目标输入框的引用区域
```

- 保留浏览器的按钮入口，不要求先拖选文字，也不为此新增文字选区浮条或强制右键菜单。
- 拾取模式应清楚区分悬停元素和待选择元素；点击只用于拾取，不能同时触发该元素原本的链接跳转或表单提交。
- 按钮提示只显示“选择元素”，拾取中显示“取消选择（Esc）”；目标对话名称放在引用菜单或添加反馈中。没有关联且有多个候选时，在写入前由宿主让用户选择目标；不新增常驻的全局目标面板。
- 元素上下文可以包含有界的文字摘要、元素描述和定位信息，不要求它等同于一段非空拖选文字。具体载荷需结合现有浏览器能力核实，不默认采集完整页面或执行元素内容。
- Esc、再次关闭拾取按钮、离开页面或来源切换时取消未完成拾取；取消不新增引用，不改变已有草稿。
- 完成一次添加后退出本次拾取模式，使用公共引用反馈；不自动发送，不强制跳转到目标输入框。
- 浏览器主文档桥接、按钮入口和元素高亮已实现，实际载荷、支持边界与验证见第 13 节；本节的完整目标交互不等于所有网页框架均已支持。

## 5. 多分屏目标规则

### 5.1 默认目标优先级

下列规则同时适用于文字右键引用和浏览器元素拾取，不能由采集期间的鼠标焦点变化覆盖。表中的“选择入口”对文字是右键菜单，对浏览器是拾取结果的添加环节。

| 来源场景 | 默认行为 |
|---|---|
| 聊天正文 | 优先绑定该聊天视图自己的目标草稿，不由另一分屏的焦点覆盖 |
| 任务联动资源面板 | 使用该资源视图所属的对话目标，不按左右位置猜测 |
| 独立资源视图，无关联且只有一个可用目标 | 可以默认选它，但选择入口仍展示目标名称 |
| 独立资源视图，无关联且有多个可用目标 | 由用户通过选择入口指定目标，不猜默认值 |
| 已有关联，但关联目标不可用 | 不自动降级到另一对话；明确提示或由用户选择其他目标 |
| 没有可用目标 | 不添加，不自动打开或新建任务 |

“可用目标”指已打开、仍有效且能够接收草稿引用的对话目标，不是所有历史任务，也不以“输入框 DOM 当前有焦点”为唯一判据。目标被暂时隐藏时是否仍可接收，按其草稿接收器是否有效判断，不为了添加引用强制显示它。

### 5.2 名称与身份

- 菜单或元素拾取的目标选择入口用“分屏位置或分屏标签＋任务标题”帮助区分，标题相同时仍可辨认。
- 如同一任务存在不同分支或不同草稿，补充相应区分标签。
- 分屏位置仅供显示，不能作为写入目标的身份。
- 真正的目标需要绑定会话、分支及草稿身份；视图实例用于关联和校验。
- 两个视图如果映射到同一个真实草稿，应合并为一个候选；不同草稿不能仅因标题或任务相同而合并。
- 默认目标有标记，其他目标稳定排序，避免用户移动鼠标时列表重排。
- 用户选择其他目标只改变本次添加目标，不顺便改变资源面板的任务联动关系；两种采集入口都遵循此规则。

### 5.3 锁定与失效

文字引用在菜单打开时固定文字快照、来源身份和候选目标身份。浏览器在进入拾取时绑定来源页面与作用域，并保存明确默认目标（如有）；点击元素时生成元素上下文快照，没有明确目标则在写入前由用户选择并绑定目标。目标选择列表展示时固定候选身份，不能让后续焦点变化隐式改变目标。

两条通路提交时都重新校验，不临时读取一个全局“当前任务”。以下变化使旧操作失效：来源视图切换到另一资源、页面或作用域，目标分屏关闭或切换到另一会话或分支，草稿被发送或重置而更换身份。网页元素在完成快照前失效时取消本次拾取，不能悄悄改选另一个元素。

失效后提示“目标或来源已切换，请重新选择”，不转投到其他输入框。一般正文编辑不应令添加引用失效；添加必须保留用户最新正文，不能用操作开始时的正文覆盖它。

单纯调整分屏尺寸或位置不改变目标身份。关闭资源标签只关闭来源实例，不删除已经添加的引用快照；再次打开时按现有资源模式恢复关联，不使用最后一次全局鼠标焦点猜测。

## 6. 输入框与引用卡片

### 6.1 视觉参考与结构

以现有对话引用组件作为参考之一：沿用主题、边框、紧凑字号、两行摘要和移除按钮，不新建一套大卡片系统。引用卡片的主体只展示来源和内容摘要，保留移除操作，不提供独立评论输入。视觉复用不等于直接复用只允许消息来源的数据结构。

下面上方是引用附件，下方是原有聊天输入框，不是新增的评论框：

```text
┌─────────────────────────────────────┐
│ 文件  auth.ts · L24–38             × │
│ const token = await refreshToken…   │
└─────────────────────────────────────┘
┌─────────────────────────────────────┐
│ 在原有聊天输入框中输入消息…            │
│                                     │
│ 模型 / 权限                    发送 ↑ │
└─────────────────────────────────────┘
```

正文示意只是普通聊天输入位置，不是引用专属的必填内容。引用添加成功后即完成本次引用操作；是否补充问题由用户决定，发送仍遵循现有聊天规则，不新增评论校验。

| 来源 | 卡片标签示例 |
|---|---|
| 代码或文本文件 | 文件图标、`auth.ts`（示例文件名）、行号范围 |
| Markdown 预览 | 文档图标、文件名、“选中文本”；不能准确映射行号时不编造 |
| 网页元素 | 网页图标、页面标题、域名，补充“元素引用”或元素描述 |
| 插件 | 插件图标、插件名称、内容标题 |
| 聊天 | 引用图标、“助手消息”或“用户消息” |

摘要最多两行，保留文本内容和必要换行；网页元素没有合适的文字摘要时显示安全的元素描述，不伪造文字选区。长路径不占据主卡片，完整来源放在预览里。引用区有内容才显示；多个引用采用紧凑排列与溢出展开，不无限抬高输入框。第一版不重排无关的文件附件和会话引用区域。

### 6.2 卡片操作

- 点击卡片：按类型预览完整文字选区或已采集的元素上下文及来源，而不是直接跳走；元素预览不执行网页代码。
- 预览中的“定位来源”：返回原文件、网页元素或消息；只有可定位时提供，网页定位不触发元素本来的点击行为。
- 移除按钮：仅删除草稿中的这条引用，不改原文，也不卸载插件。
- 卡片与预览不提供“添加评论”或“编辑评论”操作；预览用于查看引用，不作为发送前的强制确认。
- 预览按纯文本或安全的代码展示处理，不能执行来自网页或插件的 HTML。
- 来源不支持定位时，仍可预览完整引用，不能暗示一定能回到准确位置。

### 6.3 添加反馈

- 成功提示“已引用到「任务标题」”，新卡片短暂高亮；尊重减少动画设置。
- 保留当前草稿正文，不自动发送、不自动切换分屏、不抢焦点。
- 相同来源、位置及内容的重复引用不新增卡片，提示“这段内容已添加”；元素引用按页面、元素定位和上下文快照判断，不能仅因摘要相同就合并不同元素。
- 数量、单条长度或总长度超限时明确提示，不静默截断。
- 目标暂不可写时提示原因，不丢弃其他既有引用；正在运行不自动等同于草稿不可编辑。

## 7. 发送与历史

- 引用跟随目标草稿发送，不进入其他任务的消息。
- 使用结构化引用记录区分并保存文字快照或元素上下文及其来源；给模型的上下文由宿主生成，不把特殊正文尾块当作唯一存储协议。
- 发送后的消息仍能展开查看完整引用内容和来源，不再显示草稿移除按钮。
- 原文件变化、网页关闭或插件禁用后，发送时的内容快照仍保留；元素引用不能只保存一个需要重读网页的定位标识。
- 定位失败显示“来源已不可用，引用内容仍保留”；不能为恢复来源而绕过权限。
- 历史聊天引用和旧消息继续兼容，新增资源来源不能破坏旧引用展示。

## 8. 工作台公共能力与安全边界

拟议职责分层：

```text
文件 / Markdown / 聊天 / 插件文字选区    浏览器元素拾取
              ↓                           ↓
       拖选文字 → 右键               点击按钮 → 点击元素
              ↓                           ↓
         文字快照适配器               元素上下文适配器
              └────────────┬──────────────┘
                           ↓
               工作台公共目标解析和校验
                           ↓
                    指定草稿接收引用
                           ↓
                引用卡片、发送和历史展示
```

统一接收不要求统一采集入口，也不要求把元素上下文降级成纯文字。公共引用协议保留来源类型差异，展示层采用相同的紧凑卡片语言。

公共数据至少区分：

| 数据 | 用途 |
|---|---|
| 内容类型及快照 | 区分文字选区与元素上下文，保存采集时实际内容，不依赖发送时重读来源 |
| 来源类型、标题与身份 | 标识原文件、网页元素、插件内容或聊天消息 |
| 可选定位信息 | 文件行列、网页元素定位或消息偏移；不同来源分别校验 |
| 来源视图及作用域 | 防止视图切换后旧操作引用错误资源 |
| 目标会话、分支和草稿身份 | 精确路由与提交校验，防止分屏串写 |
| 引用记录身份 | 移除、去重及历史展示 |

公共引用记录仅承载内容快照、来源、定位、路由和记录身份等必要信息，不新增独立评论字段；普通聊天正文继续由现有草稿管理。具体类型、文件位置和公开接口名在实现时确认，本文不宣称已有接口可直接使用。

内置 DOM（页面文档结构）文字、编辑器、浏览器元素拾取和插件框架分别提供适配器。`window.getSelection()`（读取当前文档文字选区的方法）不能替代元素拾取，也不能覆盖浏览器或插件的隔离边界。

浏览器适配器通过受控桥接提交元素上下文，不让网页直接写入草稿或指定任务。拾取点击属于宿主采集操作，不作为授权执行网页动作的凭据；页面导航或作用域切换时必须取消旧拾取。

插件通过受控 SDK（插件接入接口）提供自己的内容快照，由宿主呈现或确认添加操作并决定目标。插件不能借此枚举其他任务、读取输入框正文或任意写入指定任务；宿主认证插件和视图身份，不信任插件自行声称的来源身份。

文字和元素上下文均属于外部内容，不是系统指令。引用只表示用户愿意提交这份内容；文件路径和网址不是额外读取授权，来源定位仍遵守既有权限。

### 13.2 实际范围

- 浏览器工具栏新增元素选择按钮，沿用现有图标、尺寸、主题和焦点样式；按钮提示为“选择元素”，拾取中为“取消选择（Esc）”，不拼接目标名称。无需文字拖选、右键、评论或发送确认。

- 拾取开始冻结来源身份、默认目标及候选草稿身份。单个明确目标直接添加；多个候选在元素采集后用公共 NDropdown 展示默认入口和其他目标，独立视图不猜默认值。添加时复用公共重验与最新正文追加，不广播、不改资源联动、不自动发送或跳到输入框。

### 13.6 首次发送自动收起的原因与验收遗漏复盘（2026-10-03）

**原因不是浏览器或文件采集逻辑，而是公共资源面板把同一工作区的身份升级当成跨任务切换。** 首次发送将 `draft:<id>` 转为 `task:<conversationId>`；原实现迁移页签与选中项，却遗漏展开状态，新任务便回退为默认关闭。同时工作台采用正式对话时会短暂没有活动任务，投影到 workspace 并发出异步收起请求。目标任务恢复时旧请求尚未到达，渲染层仍显示展开，旧代码因此跳过恢复；收起结果稍后到达，面板便关闭。只补展开状态迁移不能解决第二条竞态，必须考虑在途状态请求。

历史核查区分两种“以前没有出现”：

- 早期文件管理器相关版本（`1467c3fe`，2026-09-18；目录树/文件联动调整 `8bb1d3c9`，2026-09-22）尚未包含这条按会话恢复面板可见性的 watcher。`f417510b`（2026-09-30，`follow workspace layout per session`）才新增 `openStates` 和作用域切换时的恢复逻辑。因此更早版本不会由这条新增逻辑触发自动收起；这不等于其所有状态转换都已验收。
- 文件/Markdown选区引用提交 `9eaff71c`（2026-10-02）时，该公共逻辑已经存在。真实 `selectionReferences.e2e.mjs` 只验证选区、右键、添加引用、编辑操作、正文保留及多分屏目标，不执行发送。原草稿迁移测试也未断言展开状态或模拟延迟 IPC，故未覆盖“引用进入草稿 → 首次发送 → 正式对话工作区保持连续”这条边界。按同一公共逻辑，文件页签在任务联动模式的新草稿首次发送场景也受影响，不是文件管理器天然不受影响。

复盘结论：首次发送是同一工作区的连续操作，不应重置资源页签、选中项或用户展开/收起意图；真正切换不同任务时仍各自恢复状态。引用进入草稿的验收不能替代发送后的工作区连续性验收。第 13.5 节新增通用状态迁移和延迟控制测试，以及浏览器引用的真实首次/后续发送回归；文件场景本轮真实回归仍主要覆盖采集与添加，不能冒称已经逐项覆盖所有资源类型的实际发送。
