# Feature-048：文字稿播放插件

**日期：** 2026-11-08
**状态：** 第一版已实现播放和字幕跳转（2026-11-08，`plugins/transcript-player/`）；搜索、引用、跨页签恢复和其余界面项未做
**范围：** 新建插件，源码放 `plugins/<name>/`。不改宿主的音视频预览、媒体协议和文件管理器。
**承接：** [Feature-033 文档插件契约](feature-033-document-plugin-contract.md)、[Feature-043 Office 文档引用的“定位来源”](feature-043-office-quote-locate.md)。内置音视频预览见已归档的 [Spec-036](../archive/specs/feature-036-media-preview.md)，那份规格明确不做字幕。

## 1. 背景

要的是飞书妙记那种用法：打开一段会议或课程的音视频，旁边是可阅读的文字稿，点一句就从那里播，播放时当前句跟着亮。用户来这里主要是读、找、引用，不是看画面。

内置预览已经能播音视频，用的是原生 `<video>` / `<audio>` 和受控的媒体地址，不解析字幕，也不提供文字稿。这件事不放进宿主播放器，做成插件。播放器用 [ArtPlayer](https://github.com/zhw2590582/ArtPlayer)，不改它的源码。

## 2. 已定

这些是 2026-11-08 对话里已经定下的，实现时不要另起一套界面。

1. **文字稿是主体，播放器是附件。** 不要做成“播放器加一张字幕列表”，也不要做成 ArtPlayer 的演示页。
2. **放在文件页签里。** 视图为 `location: "context"`、`resource: "selected-file"`。不要做工作台浮层，也不要做导航里的独立应用。宿主页签已经有标题和关闭，插件里不再画一套顶栏。
3. **音视频用同一个视图。** 纯音频时不要留黑屏，用文件名和时长盖住画面。波形以后再做。
4. **句子级就够。** 第一期不做逐词卡拉 OK。跳转精度靠句子，阅读节奏靠段落：同一说话人、间隔小于 1.5 秒的相邻句合成一段。没有说话人标签时不编造头像和色点。
5. **当前句用 2px 强调色竖条加浅底，不要反白。** 颜色跟主题走，不用 ArtPlayer 的默认皮肤。
6. **自动滚动必须能被打断。** 用户一滚就停，出现“回到当前”。暂停时保持高亮，但不滚。
7. **选区只有两项：复制、引用到对话。** 不做分享链接，桌面页签没有可分享的 URL。
8. **没有转写引擎之前，不放“开始转写”。** 字幕由用户手动加载。
9. **不改 ArtPlayer 源码。** 弹幕、截图、设置齿轮和它自带的底栏都不露出来。画面字幕默认关，文字稿就是字幕。

## 3. 目标与非目标

**目标**

- 打开音视频文件，进入文字稿页签。
- 加载 SRT、VTT 或 ASS 后，点句子跳转并播放，播放时高亮跟随。
- 在文字稿里搜索，并看到命中计数。
- 把选中的文字引用到聊天草稿；之后点“定位来源”能回到那一句。

**非目标**

- 不改宿主的 `DesktopMediaPreview`、媒体地址和 Range 读取。插件停用后，这些文件仍走内置预览。
- 不做转写、说话人分离、逐词高亮、笔记、协作、分享链接。
- 不编辑、不写回音视频原件。
- 第一期不做虚拟滚动。列表按“一行一个句子”写，以后卡了再换。
- 不发布到市场，不改 `.github/workflows`。市场同步另说。

## 4. 入口与文件

宿主一次只把当前文件交给页签，旁边的 `.srt` 它看不见，也不能按路径去翻同目录。

| 文件 | 怎么拿到 | 怎么读 |
| --- | --- | --- |
| 音视频 | 页签打开的 `context.resource` | `resources.getUrl(context.resource)`。这个地址支持 HEAD、Range 和 seek，交给 ArtPlayer。不要用 `readBytes` 把整段视频读进内存：文档读取整文件上限是 64 MiB，会议录像经常更大 |
| 字幕 | 用户点“加载 SRT、VTT 或 ASS”后，`resources.pickFiles` | 优先把选中的字幕也换成 `getUrl`，交给 ArtPlayer 的 `subtitle`。取消选择就保持当前状态 |

`readText` 只保证 1 MiB 的 UTF-8。更大的字幕，或 GBK 旧字幕，用分段 `readBytes` 加解码，不能假设一次 `readText` 够用。ArtPlayer 的 `subtitle.encoding` 能读 GBK，但只有把字幕地址交给它时才走得通。

空状态就写：“还没有文字稿。” 加载失败写失败原因，并给重试和重新选择。不要假设同目录字幕会自动出现。

页签状态用 `setState` 记：分隔比例、是否跟随、播放时间、已选字幕的资源 ID。不保存 `getUrl` 返回的地址，那是这一次视图的临时地址。字幕文件被移动或替换后，旧句柄会读失败，这时回到“加载失败”，不要卡在空白高亮上。

**待确认：** 这些扩展名是默认由本插件打开，还是只作为另一种打开方式，内置预览仍是默认。接管意味着文件管理器里点开 `mp4` 会进文字稿页，而不是现在的简单播放器。建议第一期接管，插件停用后自动回到内置预览；确认前不要把 `requestDefault` 写成 true。

扩展名先与内置预览对齐，不声称能播容器或编码不支持的文件：

| 类型 | 扩展名 |
| --- | --- |
| 视频 | `mp4`、`m4v`、`webm`、`mov`、`ogv` |
| 音频 | `mp3`、`wav`、`ogg`、`oga`、`opus`、`m4a`、`aac`、`flac` |

`mkv`、HEVC、ProRes 第一期不接。播不了时沿用“当前环境不能播放这个编码”的失败提示，不要自己转码。

## 5. 界面

插件视图铺满页签，没有宿主间距。颜色只用主题语义：`bg-surface`、`text-fg`、`text-muted`、`border-border`、`bg-selected`，进度条用 `var(--lexora-accent-solid)`。深色模式跟着应用走，插件自己不设主题开关。

- 默认左 38%、右 62%，分隔条可拖，比例记在这个页签里。宽度不足 720px 时，播放器收成顶部 64px 的一条，文字稿占下面。不要整页一起滚。
- 左侧是略深的井，画面圆角。ArtPlayer 只负责画面、解码和跳转。一条自定义控制条贴在画面下面：播放、时间、倍速、画面字幕、跳过空白。不要和 ArtPlayer 底栏各做一套。
- “跳过空白”默认关。只跳长于约 4 秒的空隙，不跳正常换人时的短停顿。
- 文字稿按段落排。段头是说话人和起始时间；段内每一句可点。悬停时出现“播放”和“引用”，不要靠用户猜这行能不能点。
- 搜索放在文字稿顶部，有 `3/12` 和上一条、下一条。命中词浅底，不整段涂黄，也不把没命中的行藏掉。
- 正文约 15px、行高 1.75。时间戳用等宽数字。不要把每段做成圆角卡片。

插件 iframe 的位置由宿主测量。视图必须跟着容器尺寸变，不能写死像素宽高。侧栏开合后如果页签没有铺满，先看是不是没响应尺寸变化，不要去改宿主布局。

## 6. 播放与字幕

ArtPlayer 已有的公开接口够用，依据是 2026-11-07 对它源码的阅读，实现时再对一次当前版本：

| 接口 | 用途 |
| --- | --- |
| `option.subtitle` | 加载 `srt` / `vtt` / `ass`，可带 `encoding` |
| `art.on('subtitleLoad', cues)` | 拿到带 `startTime`、`endTime`、`text` 的句子 |
| `art.seek` | 点句子后跳转 |
| `art.on('video:timeupdate')` | 驱动高亮 |
| `theme` | 只用来对齐强调色 |

画面上的字幕默认隐藏。用户打开“画面字幕”才显示。内置字幕不能点，第一期也不给它加点击。

ArtPlayer 底层是 `<video>`。音频文件照常播，视觉上盖住黑画面。逐词高亮内置做不到；真要做，以后再自己解析并回灌，不在第一期。

第三方库必须打进 compiled 包，不能运行时从 npm 或 CDN 加载。ArtPlayer 是 MIT，锁定实现时的版本，不改它的文件。包体积要留在插件包预算里（单文件 64 MiB，压缩包 128 MiB，展开合计 256 MiB）。

## 7. 引用到对话

声明 `composerReference`。选中一句或多句后，用通用格式引用：

- `kind`：`cue`
- `location`：`{ start, end }`，单位秒。必须落在宿主对 `location` 的限制内：有限数字、深度不超过 4 层、序列化不超过 4096 字节
- `text`：选中的文字快照，带说话人和时间，供模型和以后对账

聊天里点“定位来源”时，由同一个插件打开文件，`references.onReveal` 里 `art.seek` 到 `start`，并高亮对应句。文字才是依据：对不上当前字幕时按文字找，找不到返回 `false`，不要跳到另一句。定位时字幕可能还没加载完，要等字幕就绪，并遵守宿主给的 `signal`。

复制走 `context.clipboard.write`，需要 `clipboardWrite`。引用本身不依赖剪贴板。

## 8. 权限

只声明用到的：

| 权限 | 原因 |
| --- | --- |
| `selectedResource: "read"` | 读取当前音视频并取得可 seek 的地址 |
| `localResources` | 让用户选择字幕文件 |
| `composerReference` | 把选区引用到聊天草稿 |
| `clipboardWrite` | 复制选中文字 |

不声明 `selectedResourceWrite`。不声明 `resourceExport`，第一期不导出文字稿。

`engines.lexora` 的下限覆盖实际用到的能力，至少包括 `documents.handler` 和 `documents.reference`。身份在实现时用 `lexora_plugin_identity` 生成，本规格不预分配插件 ID。显示名待确认，工作名暂用“文字稿”。

## 9. 验收

还没做。实现后至少核对这些：

- [ ] 打开一个短 `mp4`，页签是左画面、右文字稿，没有 ArtPlayer 的弹幕、截图和设置齿轮。
- [ ] 未加载字幕时，右侧是空状态，没有“开始转写”。选择一份 SRT 后，点句子能跳到对应时间并播放。
- [ ] 播放时当前句高亮；手动滚动后停止跟随，并能回到当前。
- [ ] 搜索有命中计数，上一条、下一条能定位。
- [ ] 选中文字可以复制，也可以引用到对话；点“定位来源”后回到那一句。
- [ ] 纯音频没有黑屏。插件停用后，同一文件回到内置预览。
- [ ] 关闭页签后，ArtPlayer、字幕地址和定时器都停掉，不继续写状态。

未验证项在实现记录里写明。Windows 桌面实机如果没跑，不能写成已验收。

## 11. 第一版实现记录

2026-11-08 只实现播放和字幕跳转，源码在 `plugins/transcript-player/`。ArtPlayer 锁定 5.4.0，打进 compiled 包，不改它的源码。

- 文件入口用当前的 `fileHandlers`，不预选为默认打开方式。内置预览保持默认。
- 字幕必须由用户选择。插件先用所选编码校验资源地址，再把同一个地址交给 ArtPlayer。不能先转成 `blob:` 再让它读取：视图 CSP 的 `connect-src` 不允许 `blob:`。
- 字幕超过 8 MiB 或 20,000 句会拒绝。ASS 说话人标签这一版不保留。
- 引用到对话、搜索、分隔条拖动、跳过空白和跨页签恢复都没做。引用仍受“只调用 `getUrl` 不会形成文件哈希”的限制，下一期先解决这一点。
- 2026-11-08 起播放器改为原样启用 ArtPlayer 5.4.0 的公开控制项，不再隐藏它的底栏、设置和字幕相关按钮，也不再另做一套控制条。没有改 ArtPlayer 源码，也没有改内置播放器。
- 全屏和网页全屏不打开。视图 iframe 的 sandbox 只有 `allow-scripts allow-forms`，并且 `allow` 里把 fullscreen 设成了 `none`，按钮只会提示不支持。
- 截图不打开。当前帧画进 canvas 后不能导出，视图也不能把文件存到当前目录。
- 底栏左侧提供“加载字幕”，用 `localResources` 和 `pickFiles` 选择 SRT、VTT 或 ASS。插件先用 UTF-8、再试 GBK 校验，通过后把资源地址交给 ArtPlayer。右侧 CC 只开关画面字幕。
- 同日按用户要求去掉自写的文字稿、字幕加载和编码选择。当前只移植播放器。
