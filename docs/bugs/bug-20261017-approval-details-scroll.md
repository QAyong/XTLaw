# Bug：审批详情过长挤占聊天输入区域

日期：2026-10-17  
状态：已实现，静态检查通过，待界面验收

## 1. 背景与原因

用户截图显示，自动化审批的执行内容较长，卡片占据大部分窗口高度，聊天输入框底部超出可视区域。

代码检查确认：审批卡片位于聊天输入框上方，与输入框共用底部布局区域；详情区没有最大高度，会随文本增高。此前仅命令代码块有单独限高，不能限制自动化等审批详情的总高度。

## 2. 最小修复

仅修改审批卡片组件 `apps/buddy/src/modules/tasks/widgets/workspace/DesktopApprovalCard.vue` 的样式，为两类中间内容容器统一增加：

```css
.desktop-approval-card__details,
.desktop-approval-card__review {
  max-height: min(24rem, 40vh);
  overflow-y: auto;
}
```

- 详情高度不超过 `24rem` 与窗口高度 `40%` 中较小的值，内容超过限制时内部滚动。
- 头部与底部操作区位于滚动容器之外，不随详情滚动。
- 保留全部审批内容，不截断文本，不修改组件结构、审批逻辑或授权范围。
- 保留原有命令代码块的独立限高与滚动行为。

## 4. 边界与恢复

这次只限制单张卡片的详情高度，不限制整个审批列表。多张审批叠加、极矮窗口或异常长的头部仍可能挤占输入区域，不承诺解决所有窗口尺寸下的溢出问题。

不涉及数据、依赖或配置迁移。恢复时移除新增的共享样式规则即可。

| 原名称 | 中文含义 | 用途 |
