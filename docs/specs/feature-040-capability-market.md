# Feature-040：市场（插件市场扩展为能力市场）

**日期：** 2026-10-25
**状态：** 一期（改名与界面重构）已完成；二期“能力层”（MCP、技能、子代理能装能卸，2026-10-25）已实现，见第 8 节与 4.4；能力包 `includes`、推荐条目、CLI、法律检索示范包尚未做
**已定（2026-10-25）：** 能力包的组成件点开详情才看；市场与已安装单独成页；**现有内置的技能、MCP、子代理暂不移出安装包**；“内置助手”指子代理（NPC）。
**范围：** XTLaw 桌面端（`apps/buddy`）与 `QAyong/xtlaw-market` 市场仓库
**承接：** [Feature-032 插件市场](feature-032-xtlaw-plugin-market.md)、[Feature-030 内置北大法宝 MCP](feature-030-pkulaw-legal-retrieval.md)、[Feature-031 搜狗微信搜索](feature-031-sogou-weixin-search.md)

## 1. 背景与目标

侧栏第一项现在叫“插件”，页面里只能管理和安装插件（扩展）。但用户真正想要的是“一项能力”，而不是某个技术载体：

- 想要“法律检索”，实际需要一整套东西：`legal-research` 技能 + 北大法宝 MCP + 公众号搜索 + 负责并行检索的助手（子代理）。现在这些分散在三个地方：技能随安装包带，MCP 在“设置 → 网络”里配，助手在助手页里管。
- 技能、MCP、助手目前都跟着安装包发布，新增或更新能力就要发新版应用。Office 插件在 2026-10-21 已改成市场按需下载，证明这条路可行。
- 除了成套的能力，还要能单独上架 MCP、插件、CLI，以及站长推荐的、实际指向别人仓库的条目。

目标：把“插件市场”改造为同时容纳能力包、MCP、技能、子代理、插件、CLI 的**市场**（界面上就叫“市场”，不加“能力”二字；文档里的“能力”指其中的条目）。用户在一个地方浏览、安装、卸载所有这些东西；成套的能力一次装好配套，不必再到别处补配。

## 2. 术语：形态与来源是两个维度

**形态**（是什么）：

| 形态 | 含义 |
|---|---|
| 能力包 | 引用若干其他条目的组合，按场景命名，如“法律检索”“Office 文档” |
| MCP | 一个 MCP 连接器预设 |
| 技能 | 一个技能 |
| 子代理 | 一个 NPC 子代理定义（提示词、工具范围、文件权限）。市场里不叫“助手”，因为侧栏的“助手”页管的是伙伴（actor），会混淆 |
| 插件 | 一个扩展插件（现有机制） |
| CLI | 本机命令行工具的登记条目 |

**来源**（谁托管、谁负责）：

| 来源 | 含义 |
|---|---|
| 官方 | XTLaw 自己托管安装包，目录登记 SHA256 与大小，下载后校验 |
| 推荐 | 我们只登记元数据，内容在别人的仓库或服务里；固定到具体提交或版本，对方后续改动不会静默进入用户电脑 |

“推荐”是来源，不是第七种形态。“插件”不再是用户面对的顶层概念，退为形态之一；插件机制本身（权限审核、沙箱、扩展 API）不变。

## 4. 数据模型

仍用同一份目录 `catalog/v1/index.json`，条目增加字段（缺省值保证旧条目照常工作）：

| 字段 | 说明 |
|---|---|
| `kind` | `pack` / `mcp` / `skill` / `agent` / `plugin` / `cli`；缺省 `plugin` |
| `source` | `official` / `listed`；缺省 `official` |
| `tags` | 分类标签，如“法律”“文档” |
| `includes` | 仅能力包：引用其他条目的 id 列表。**引用，不复制**，同一个 MCP 既能单独装，也能被多个包引用 |
| `origin` | 仅推荐条目：来源仓库或服务地址、固定的提交或版本、内容哈希 |
| `installPrompt` | 仅推荐条目：推荐安装提示词（技能、CLI、包都用，见第 5 节） |
| `cli` | 仅 CLI：`command`（命令名，只用来在 PATH 里查找，**不执行**）、`homepage` |

规则：

- 卸载能力包只移除不再被其他已安装条目引用的组成件；用户自己改过的内容（填好的 Token、手改的助手）卸载前提示，不静默删除。
- 能力包里被引用的条目在目录里找不到时，该包显示为不可安装，不装半套。
- 凭据不随包分发。

### 4.1 官方组成件怎么交付

- 插件清单 `contributes` 新增 `mcpConnectors`（连接器预设：id、传输、地址、是否 deferred、需要哪类凭据）与 `subagents`（子代理定义，只允许 `kind: npc`：名称、说明、提示词、工具选择、`fileAccess`，字段对应现有 NPC 设置）。技能沿用现有 `skills`。市场暂不分发伙伴（actor）。
- **子代理的安装语义**：安装 = 往 `buddies` 表插入一行（id 加来源前缀，避免与用户自建的重名），并自动加入默认伙伴“晓晓”的 `npcIds`（已定），否则委派时看不到它；审核页明示这一点；卸载 = 删除该行并从 `npcIds` 移除。用户改过定义的，卸载前提示。
- **子代理的工具引用**：工具选择里可能引用某个 MCP 的工具（如法律检索子代理要用北大法宝）。引用的 MCP 必须随包一起装，否则该工具选择会指向不存在的工具；审核页要把这条依赖写出来。
- **内置项的对待**：条目 id 与现有内置项一致的，市场里显示“内置”，不重复安装，也不提供卸载；内置的 4 个子代理同理。能力包只补装缺少的部分。
- 单件 MCP、技能、子代理可以是不含入口代码的纯声明包（多 Shell 已证明这种形态能上架）。能力包本身只是引用列表，不携带内容。

### 4.2 推荐条目怎么装

| 形态 | 做法 | 风险 |
|---|---|---|
| MCP | 只登记地址、传输方式、凭据说明，不下载任何代码 | 低，但要在审核页明示连的是谁的服务器 |
| 技能 | 推荐提示词：Agent 把固定提交的技能目录下载到工作区，用现有的 `lexora_skill prepare`（带 `review`）发起安装预览，用户在现有的安装确认页里确认，不会自动安装。不改现有 GitHub 导入 | 中 |
| 插件 | 固定提交加哈希，走现有权限审核 | 中高，会运行代码 |
| CLI | 只展示推荐提示词，用户自己复制到输入框发送，由 Agent 经现有审批安装；应用不执行任何命令 | 最高 |

### 4.3 推荐条目示例：OfficeCLI（2026-10-25 核对）

| 项 | 内容 |
|---|---|
| 仓库 | [iOfficeAI/OfficeCLI](https://github.com/iOfficeAI/OfficeCLI)，官网 `officecli.ai`，Apache-2.0，未归档，最近推送 2026-10-23 |
| 最新发布 | v1.0.158（本机已装 1.0.157），发布资产含各平台二进制和 `SHA256SUMS` |
| 技能 | 仓库里 `skills/officecli/SKILL.md`（与根目录 `SKILL.md`、你库里的副本逐字相同，git blob `6c299f33`）；同目录下还有 docx、pptx、xlsx、财务模型、路演等细分技能，但这些也由二进制 `officecli load_skill <name>` 提供，本条目只收主技能 |
| 候选固定提交 | `5e3e26278753be846b4b0b2fb0387f42d911553a`（2026-10-25 取到的 `main` 头，**正式登记前要重新取**） |
| CLI | 命令名 `officecli`；官方安装脚本 `https://d.officecli.ai/install.ps1`（Windows）、`install.sh`（macOS、Linux）。脚本从 `d.officecli.ai` 镜像下载二进制，失败回退 GitHub Release，有 SHA256 校验时校验，装到 `%LOCALAPPDATA%\OfficeCLI` 并写入用户 PATH，首次还会把技能复制到检测到的其他 Agent（Claude Code、Cursor 等）的技能目录 |
| 形态 | 一个“推荐 · 第三方”能力包：技能（GitHub 导入）+ CLI（PATH 检测加推荐提示词） |

**决定（2026-10-25）：不改技能导入，整包用一段推荐提示词，让用户自己发给 AI，由 AI 自己装。** 下面是核对时发现的限制，说明为什么不走技能页的 GitHub 导入。

**现有 GitHub 技能导入装不了这个仓库。** `prepareSkillSource` 下载整仓压缩包，上限 32 MB，解压后总量上限 64 MB（`extractSkillArchive`）。OfficeCLI 这个提交的文件树约 95 MB（`examples` 47 MB、`assets` 31 MB、`src` 15 MB），会以 `SKILL_TOO_LARGE` 失败。所以 4.2 里“技能直接复用现有 GitHub 导入”只对小仓库成立。

**AI 怎么装技能（核对过代码）：** Agent 已有 `lexora_skill prepare` 工具（`skillAuthoringCapability.ts`），接收工作区里的一个技能目录（目录名必须与技能名一致），用安装器校验，`review: true` 时请求用户的安装预览，“绝不自动安装”。所以提示词让 Agent 把 `skills/officecli/SKILL.md` 按固定提交从 `raw.githubusercontent.com` 下载到工作区的 `officecli/` 目录，再调用它并带 `review`，最后由用户在现有安装确认页里点确认。OfficeCLI 的这个技能只有一个 26 KB 的文件。

**OfficeCLI 整包提示词（示意，以站长登记为准）：**
“请帮我安装 OfficeCLI，分两步，每步做完告诉我结果：
1. 运行 `where officecli` 检查是否已安装。没有的话，把官方安装脚本 `https://d.officecli.ai/install.ps1` 下载到临时文件，先把内容读给我看，我确认后再运行；装完运行 `officecli --version` 验证。
2. 把 `https://raw.githubusercontent.com/iOfficeAI/OfficeCLI/5e3e26278753be846b4b0b2fb0387f42d911553a/skills/officecli/SKILL.md` 下载到工作区的 `officecli/SKILL.md`，用 `lexora_skill prepare` 校验并请求安装预览，我在预览里确认。
不要做这两步以外的事。”

**待核实：** Agent 在沙箱里能不能联网下载、能不能写 `%LOCALAPPDATA%` 并改用户 PATH，还没在真机上验证；做之前要在预览里实际走一遍，失败时提示词要能让 Agent 报告原因而不是反复重试。

### 4.4 二期“能力层”的实现决定（2026-10-25）

已做的范围：技能、MCP、子代理三种单件形态能从市场安装、卸载；不含能力包 `includes`、推荐条目的 `origin`/`installPrompt`、CLI、法律检索示范包、内置内容迁出。

- **清单**：`contributes.mcpConnectors`（`id`、`name`、`transport` 只允许 `streamable-http`、`url` 只允许不带账号的 HTTPS、`deferred`、`credential` 为 `none`/`bearer`/`oauth`）与 `contributes.subagents`（`kind` 只允许 `npc`；`name`、`description`、`instructions`、`tools`、`fileAccess`），都要求 API 4，不需要入口代码。字段定义在 `shared/extensions/extensionCapabilities.ts`。技能沿用 `contributes.skills`。
- **依赖检查**：子代理 `tools` 里 `mcp` 来源的工具必须指向同一清单声明的连接器，否则清单不通过；审核页把“使用的 MCP（随本包一起安装）”列出来。
- **目录**：单件条目的 `kind` 必须与清单实际贡献的一致（`skill`/`mcp`/`agent` 至少要有一项），不一致的条目按“清单无效”显示为不可安装。
- **内置识别**：条目 `manifest.id` 点号后的名字与内置项一致，且 `kind` 对得上，就算内置（`BUILTIN_CAPABILITY_IDS`：技能 `legal-research`、`lexora-buddy-animation`、`plugin-creator`、`skill-creator`；MCP `pkulaw`；子代理 `npc-explorer`、`npc-researcher`、`npc-executor`、`npc-reviewer`）。市场卡片显示“内置”，没有安装按钮；`reviewCatalog` 对内置条目直接拒绝（`EXTENSION_CATALOG_BUILTIN`）；清单里不允许声明内置的连接器或子代理 id。内置条目只是目录里的一条登记，不带内容。有测试核对这份清单与安装包里实际带的内容一致。
- **落地方式**：不新增数据库迁移。主进程的 `ExtensionService.capabilityContributions()` 按已安装的包给出声明，服务进程的 `ExtensionCapabilitySync`（`service/src/plugins/`）收到 `extensions.capabilities.changed` 后对账，做法与技能一致：
  - MCP：只写一条连接器记录，默认关闭、无凭据；`deferred` 对应工具暴露方式 `deferred`/`direct`。不继承 Feature-030 的受信待遇（`isBuiltinPreset` 只认内置预设）。需要 Token 的连接器装完保持关闭，在设置里填 Token 后再启用，沿用原有流程。
  - 子代理：往 `buddies` 表写一行 `kind = 'npc'`，id 为 `ext.<扩展 id>.<子代理 id>`，并加入“晓晓”（`BUILTIN_BUDDY_ID`）的 `npcIds`。卸载 = 软删除这一行（沿用现有“删除”语义，历史执行记录仍引用它）并从 `npcIds` 移除。重装时复活同一行。
  - 台账：服务进程在用户数据目录写 `extension-capabilities.json`，记录每个条目的所属扩展和装入时定义的摘要，用来区分“市场装的”和“用户改过的”。台账缺失或损坏按空处理，此时不会删除任何东西。
- **用户改过的内容**：子代理定义被改过、连接器填了凭据或定义被改过，都算用户的。卸载时这些记录**保留**（脱离台账成为用户自己的，不再随包删除），卸载对话框事先列出“你修改过的内容会保留”。包更新只套用到没被改过的记录。用户自己删掉的，包不会再自动补回，除非重装。
- **启停**：包被禁用时，它的连接器和子代理被关掉；重新启用只恢复子代理，连接器保持关闭，由用户自己再开。
- **冲突**：已有同 id 的非市场连接器或子代理时不接管，只记一条诊断事件。
- **读取失败不删除**：主进程尚未就绪时 `extensions.capabilities.list` 直接报错而不是返回空列表，服务进程这一轮什么都不动。
- **已安装页**：每张卡片按贡献内容标出形态（技能、MCP、子代理、插件，一个包可有多个），页头有形态筛选。含技能、MCP 或子代理的包，卡片里列出各项及状态：连接显示“待配置”（需要 Token 或登录且尚未配置）、“已启用”、“未启用”或“已移除”，带“去配置/管理”跳到 MCP 设置页；子代理显示“已加入晓晓”、“未加入晓晓”或“已移除”，可跳到助手页；技能可跳到技能页。状态读自 MCP 连接列表和伙伴列表，安装、卸载、改设置后自动刷新。内置项不在已安装页出现，仍在各自的设置页管理。
- **市场卡片**：已安装的 MCP 条目若还有连接缺 Token 或登录，按钮位显示“待配置”标记和“去配置”（跳 MCP 设置页），配置完成后变回“已安装”。
- **插件作者文档**：`plugin-creator` 的 `api.d.ts` 加了 `McpConnectorContribution`、`SubagentContribution`，新增 `references/market-capabilities.md` 并在 `SKILL.md` 里指引阅读。
- **审核页**：标题随形态（安装 MCP / 技能 / 子代理…），来源行显示“XTLaw 市场 · 形态 · 官方”；MCP 段列出连接地址、凭据要求、“不下载任何代码，默认关闭”；子代理段列出工具范围、文件权限、使用的 MCP，并写明“安装后自动加入晓晓的可委派列表”。

### 4.5 能力包与法律检索的决定（2026-10-26）

**能力包是一份引用清单，不是安装包。** 它没有清单、没有包体、不运行代码，作用是“一组条目的集合下载”加“市场首页的推荐货架”。成员仍是各自独立的条目，同一成员可单独装，也可被多个包引用。这取代了第 4 节里“卸载按引用计数处理组成件”的设想。

- **目录**：新增文件 `catalog/v1/packs.json`（`schemaVersion: 1`，`packs: [{ id, name, description, tags, iconUrl?, source?, includes: [成员的 manifest id] }]`），不改 `index.json`。原因：`index.json` 的顶层和条目都是 `.strict()`，已发布的客户端遇到新字段会把整份目录判为无效；独立文件旧客户端不会去取，新客户端取不到它时只是不显示货架。`kind` 恒为 `pack`，`source` 缺省 `official`。
- **状态由成员推算，能力包自己不记录**：成员已安装或为内置即视为满足；全部满足显示“已安装”，否则显示“还差 N 项”；有成员在目录里找不到、与当前版本不兼容或被清单拒绝时，整包不可安装，不装半套。
- **没有能力包的卸载**：到已安装页逐个卸载成员。
- **安装**：缺的成员按 `includes` 顺序，逐个走现有的审核页，每个成员单独确认；用户取消就停在当前成员，已装的保留，再点“安装”只补缺的。汇总成一个审核页留到后面（现有审核页一次只承载一个包，合并需要拆分组件）。
- **货架与详情**：市场页顶部是能力包卡片（成员图标行），点开详情列出每个成员的形态、来源、状态，成员可单独安装。
- **首个验证包**：Office 文档，引用三个现有官方插件，不需要新内容；先用它验证整条链路。
- **北大法宝 MCP 保持内置**（沿用 Feature-030，受信待遇不变）。法律检索包里它显示“内置”。
- **子代理引用内置 MCP**：清单校验（`extensionManifest.ts`）现在要求子代理引用的连接器必须由同一清单声明，而内置 `pkulaw` 不允许声明，所以市场里的法律子代理用不了北大法宝的工具。需放宽为“同包声明或内置连接器”；写法律子代理前先核对工具选择里的连接器 id 与连接器记录 id 是否一致。
- **技能 `legal-research` 迁出安装包，由市场分发（待做，等 legal-research 重组提交后）**：
  - 市场包为纯声明包，路径 `legal-research/SKILL.md`（插件技能要求目录名等于技能名）。
  - **老用户的处理：安装包里随带一份技能压缩包（不再作为内置技能），老用户升级后自动从它装入，不依赖联网；新用户在市场里装。**
  - 需要先核对的机制限制：现有的 bundled 目录会在启动时对所有条目预装（`preinstallBundledExtensions`，以 `preinstalled.json` 记基线），不存在“随包但不预装”。所以要新增“随包但按条件预装”：只对升级用户预装，新装用户不预装。“升级用户”的判据还没定（可能看数据目录是否在本版本之前就存在，或看数据库里是否有旧的 `application:legal-research` 记录；后者在服务进程，主进程读不到）。
  - 旧记录清理：随包资源去掉后，数据库里的 `application:legal-research` 记录会一直显示为“无效”且用户删不掉（`canRemove` 只对用户安装的技能为真），迁出时一并清理资源已不存在的应用技能记录。
  - 同时从 `BUILTIN_CAPABILITY_IDS.skill` 和 `definitions.json` 的 `skills` 里去掉 `legal-research`，否则市场里的同名条目会被当成内置而拒绝安装。

## 5. 安装交互

原则：**只搬数据和文本的，一键安装；会在本机执行代码的，必须让用户看到并确认具体动作。**

| 形态 | 点击后发生什么 | 装完状态 |
|---|---|---|
| 能力包、技能、子代理、插件 | 点“安装”，弹审核页，列出将新增的内容和权限，确认后装好 | 已安装 |
| MCP | 点“安装”，审核页写明连接的地址，确认后只添加一条连接器记录，不下载代码，默认关闭 | 不需要 Token 的可直接启用；需要 Token 的显示“待配置”，进入后填 Token，保存即启用（沿用 Feature-030） |
| CLI | 不直接装：先在 PATH 里查命令；已有则显示就绪和路径；没有则展示推荐提示词，用户点“复制提示词”，粘贴到输入框自己发送，让 Agent 安装，装完点“重新检测” | 已就绪 / 未检测到 |

补充：

- **能力包含 CLI 时**：包里其他部分照常一键装好，卡片提示“还差 1 项：需要先装 pandoc”；CLI 检测到后该项自动变绿。
- **本地启动型 MCP**（用 `npx` 等命令在本机启动）本质是运行外部代码，风险等同 CLI，归 CLI 一档，不当普通 MCP 一键装。现有连接器是否支持这种传输尚未核对，实现前先查。
- **推荐条目（技能、CLI、整包）安装用“推荐提示词”（已定，2026-10-25）**：条目带一段 `installPrompt`，卡片详情里展示全文并提供“复制提示词”按钮，用户自己粘贴到输入框、自己发送，由 Agent 操作，命令照常走现有审批。应用不新增任何执行第三方命令的路径，也不做“一键安装”按钮。
  - **为什么不是按钮直接开任务**：提示词发送前用户能看到全文，目录里的文字不会在用户没看到的情况下变成对 Agent 的指令。
  - **约束**：纯文本；长度上限（暂定 800 字符）；只在详情里展示并复制，不自动填入、不自动发送；推荐条目只由站长登记，不开放自助提交。
  - **提示词写法**（建议模板）：先检查是否已装；官方安装脚本先下载到临时文件并把内容读给用户看，确认后再运行，不直接 `curl | bash` 或 `irm | iex`；装完用版本命令验证并汇报；不做安装以外的事。
  - **示例**：见 4.3 的 OfficeCLI 整包提示词。
  - **后续选项**：详情里再加“在新任务中打开”，把提示词填入新任务输入框但不发送。本期不做。
  - 检测只在 PATH 里查命令，不执行它；装完新开的终端才有新 PATH，应用可能需要重启才检测得到，卡片上提示这一句。
- 审核页按形态分组，并显示来源：
  - 能力包：列出每个组成件。
  - MCP：写明连接地址和“不下载代码”。
  - 子代理：写明可用工具范围和文件权限，不能高于用户当前授权；工具引用了哪个 MCP 也要列出。
  - 推荐技能和插件：标“第三方·未经 XTLaw 审核”，写明来源仓库和固定提交，确认按钮改为“我了解风险，安装”。
- **受信与审批**：Feature-030 中受信预设享有的待遇（审批放宽、服务端错误原文转发）是否扩展给市场能力声明的预设，需单独评估，不默认继承；其余连接器仍强制询问。
