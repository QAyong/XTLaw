# Spec-012：插件术语统一

**状态：** 已实现，自动化验证通过；未进行打包应用的人工验收

## 1. 背景

当前导航和安装入口使用“插件”，但同一管理流程还出现“工作台扩展”“重启扩展”“卸载扩展”等文案，容易让用户误以为存在两套可安装产品。

本方案统一用户可见术语，不改变插件功能、运行机制、权限边界或数据格式。

## 2. 术语与关系

| 术语 | 中文含义与使用规则 |
|---|---|
| 插件（Plugin） | 用户可以安装、启用、禁用、更新和卸载的独立功能包；用户界面统一采用此称呼 |
| 插件视图（Plugin view） | 插件提供的界面；一个插件可以提供多个视图，也可以没有视图 |
| 标签页（Tab） | 视图在资源面板中的打开实例；关闭标签页不等于禁用插件 |
| 资源面板 | 承载文件、网页和插件视图的界面容器；不是插件的所属模块 |
| 工作台扩展系统 | 管理工作台插件的内部技术机制；仅在技术说明中使用 |
| Agent 内部扩展 | 应用向 AI 运行时注入工具、策略与事件处理逻辑的机制，不属于用户可安装插件 |

插件负责提供能力，资源面板负责展示其中一部分能力。插件还可以提供独立页面、工作台控件、装饰、命令、AI 工具和后台动作，不局限于资源面板。

## 3. 需求边界

**包含：**

- 插件管理及设置分类中的中英文名称统一为“插件”与 `Plugins`（插件集合的英文名称）。
- 重启、卸载、空状态、加载及错误提示统一使用“插件”；视图错误明确称为“插件视图”。
- 核对导航、安装确认、通知和诊断等流程；已使用“插件”的文案保持不变。
- 插件开发说明及架构说明明确工作台插件与 Agent 内部扩展的区别。
- 新增术语回归测试，覆盖中英文文案与实际组件呈现。

**不包含：**

- 不全仓库替换“扩展”；“扩展授权范围”“文件扩展名”和正式扩展点等用词保持原意。
- 不改布局、路由、功能、权限、配置或生命周期。
- 不改代码标识、公开协议、安装包后缀、数据库字段或存储路径。
- 不构建或安装桌面安装包，不自动提交或合并代码。

## 4. 文案规则

| 原文案 | 统一后 |
|---|---|
| 工作台扩展 / Workbench extensions | 插件 / Plugins |
| 还没有安装工作台扩展 / No workbench extensions installed | 尚未安装插件 / No plugins installed |
| 重启扩展 / Restart extension | 重启插件 / Restart plugin |
| 卸载扩展？ / Uninstall extension? | 卸载插件？ / Uninstall plugin? |
| 正在加载扩展… / Loading extension… | 正在加载插件… / Loading plugin… |
| 扩展视图暂时不可用 / This extension view is unavailable | 插件视图暂时不可用 / This plugin view is unavailable |

操作的对象与后果保持区分：关闭标签页仅关闭当前实例；禁用插件停止整个插件；普通卸载移除代码但保留设置、私有数据与视图位置；“卸载并清理”额外删除这些数据，不删除任务内容或用户文件。本次仅统一文案，不更改这些行为。

## 5. 文件与术语说明

| 原名称 | 中文含义 | 用途 |
|---|---|---|
| `apps/buddy/src/modules/extensions/extensionLabels.ts` | 插件管理文案表 | 集中维护中英文操作与状态文案 |
| `apps/buddy/src/i18n/locales/{zh-CN,en-US}/settings.ts` | 中英文设置文案 | 统一插件设置分类和说明 |
| `apps/buddy/electron/main/extensions/runtime/view.js` | 插件视图运行入口 | 统一隔离视图加载失败提示 |
| `apps/buddy/extensions/README.md` | 插件开发说明 | 解释术语与资源面板关系，并统一操作名称 |
| `docs/architecture/overview.md` | 项目架构概览 | 区分工作台插件与 Agent 内部扩展 |
| `ExtensionService` | 插件运行管理服务 | 保留现有类名，不作为用户术语 |
| `BuddyInProcessExtension` | Agent 进程内扩展类型 | 由应用注入 AI 运行时，区别于插件包 |
| `extension.json` | 插件清单文件 | 保留公开文件名 |
| `.lexora-extension` | 插件安装包后缀 | 保留安装兼容性 |

现有的接口名、通信通道、错误代码、翻译键和目录名继续使用原标识；技术说明首次出现时解释其含义，不机械重命名。
