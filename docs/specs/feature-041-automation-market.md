# Spec-041：自动化上架市场

**日期**：2026-10-28  
**状态**：需求草案，未实现  
**承接**：[Feature-040：市场](feature-040-capability-market.md)

## 1. 背景与目标

用户新增需求：“自动化也可以上架市场”。

市场除已有规划中的能力包、MCP、技能、子代理、插件和命令行工具外，还应支持“自动化”这一形态。用户可以从市场获取可复用的自动化，在自己的环境中配置并使用，而不必从头编写任务。

本文只记录需求与建议边界，不代表功能已开发，也不提前确定技术协议。

## 2. 已确认的需求

- 自动化可以作为市场条目上架、展示，并供用户获取和使用。
- 自动化属于市场中的独立形态，不应仅以普通插件或技能的名称代替。
- 本需求扩展 Feature-040 的市场范围，不改变其他形态的既有定义。

## 3. 建议的一期范围（待确认）

### 3.1 上架与浏览

- 沿用现有市场目录与发布流程；一期不额外建设开放投稿、作者后台或交易系统。
- 市场增加“自动化”形态筛选，支持搜索、卡片和详情展示。
- 详情展示名称、说明、作者、来源、版本、用途、任务内容、触发方式，以及需要的技能、连接器、插件或工具。
- 自动化的任务内容必须可在安装前完整查看，不能只展示宣传文案。

### 3.2 安装与本地配置

- 分发的是可复用的自动化定义或模板，不是作者正在运行的任务实例。
- 安装前展示将创建的任务、触发规则、所需依赖、涉及的访问范围和待配置项，由用户确认。
- 安装后出现在现有“自动化”管理页，可继续编辑、启停和删除；市场已安装页可跳转管理。
- **建议默认停用**：不因安装、更新或应用重启而直接运行；用户补齐配置后，明确启用或手动运行。
- 发布内容不携带凭据、登录状态、会话与执行历史，也不继承作者的权限。
- 作者本机的绝对路径、空间、账号、模型及其他环境绑定应标成待配置项，或在发布时剔除；不能静默绑定到安装者的任意目标。
- 缺少依赖或必要配置时，显示具体缺项和配置入口，不把“下载完成”等同于“可以运行”。
- 执行仍遵循当前宿主的权限与审批规则；市场来源不构成额外授权。

### 3.3 更新与移除

- 记录市场来源和版本，区分市场安装与用户自行创建的自动化。
- **建议更新不静默覆盖本地修改，也不自动启用任务**；有冲突时展示差异，由用户选择保留、替换或另存。
- 删除或卸载前说明对本地任务、调度与历史记录的影响；移除任务后不能遗留继续执行的调度。
- 能力包是否可以引用自动化，留待确认；不把它作为一期上架的前置条件。

## 4. 不包含的内容

- 本次仅新增需求文档，不实现市场目录协议、安装器或界面。
- 不新增云端代跑、跨设备同步、凭据共享或自动提权。
- 不预设付费、分成、开放投稿和审核后台。
- 不要求重做现有自动化编辑器或调度系统。

## 5. 验收标准（建议，实施前确认）

- [ ] 至少一条自动化可以通过市场发布流程登记，并在客户端按“自动化”展示和筛选。
- [ ] 安装前能查看完整任务内容、触发规则、来源、版本、依赖及待配置项。
- [ ] 用户确认安装后，本地自动化管理页能看到并编辑该任务。
- [ ] 安装后默认停用；未启用前不会触发执行，应用重启也不会改变此状态。
- [ ] 缺少凭据、路径或依赖时明确提示，不静默运行；配置后可由用户手动运行并查看执行结果。
- [ ] 发布定义不含作者凭据、会话和运行历史，安装不继承作者权限。
- [ ] 更新不会静默覆盖用户修改或启用任务；移除任务后不会残留调度。
- [ ] 不破坏现有市场条目的加载与安装；旧版客户端的目录兼容策略经过验证。

## 6. 风险与实现前核对

- 自动化可能定时、持续地产生外部副作用，必须把“安装”和“授权执行”分开。
- 外部任务文本属于不受信内容；浏览和安装预览不能触发任务执行。
- Feature-040 已记录市场目录存在严格字段校验；新增形态前需验证旧客户端兼容性，不直接假定增加字段无影响。
- 实现前核对现有自动化定义、调度、权限与删除语义，再决定复用方式；本文没有对相关代码作完整核查。

## 7. 未决事项

1. 一期是否采用上述“安装为本地副本、默认停用”的方案？
2. 发布入口放在自动化详情中的“发布到市场”，还是先只由维护者在市场仓库登记？
3. 自动化是否允许被能力包引用，依赖缺失时是否提供逐项安装？
4. 更新采用“原任务确认更新”还是“安装新副本”？本地修改如何比较？
5. 允许上架哪些触发方式？具体文件格式、目录版本与兼容下限在实现时确定。
