# Spec-037：会话复制为 Markdown

**日期**：2026-10-21

**状态**：已实现，定向自动化验证通过；用户于 2026-10-21 确认开发版预览验收通过，安装包未验证

**相关**：[Spec-003：引用历史会话并按需检索](feature-003-session-reference.md)

## 1. 背景与目标

目前会话“复制”子菜单提供“任务引用”“任务 ID”“标题”：分别用于在应用内引用会话、取得定位标识和复制名称，均不是复制对话全文。

用户希望增加类似 Codex 的“复制为 Markdown”，把对话中的问题、尝试过程、命令输出和报错交给其他 Agent 接着分析，不需要逐条复制消息或截图。

**目标**：一次操作，将指定会话当前活动分支的历史整理为可直接粘贴的 Markdown 纯文本。

**参考边界**：Codex 是用户提出的交互参考。本轮没有核验 Codex 的具体导出字段，不把本方案描述为与 Codex 格式完全一致。

## 2. 建议结论

1. 在原有“复制”子菜单新增“复制为 Markdown”，保留已有三个选项及其行为。
2. 同时覆盖侧栏会话菜单和会话顶部菜单，复用同一份菜单与导出逻辑。
3. 复制当前活动分支的完整可读取历史，包括未在界面加载的旧消息；不混入其他分支、其他会话。
4. 内容以“用户消息 → 助手说明 → 工具调用与结果 → 助手回复”为阅读顺序，带必要的会话标识、时间、模型和运行状态。
5. “日志”指本会话接口提供的工具展示记录、命令输出和错误，不是应用全部底层日志。
6. 首版只写剪贴板，不自动保存文件、不调用模型总结、不上传、不发送给其他 Agent。

用户于 2026-10-21 确认方案并要求实施；以上范围已接入代码。自动化与人工验收状态见第 9 节。

## 4. 交互设计

### 4.1 入口

建议菜单：

```text
复制
  任务引用
  ────────────
  任务 ID
  标题
  复制为 Markdown
```

- 中文新增文案：“复制为 Markdown”；英文：“Copy as Markdown”。
- 不在本次顺带改动“任务 / 会话”的既有命名。
- 点击后沿用现有菜单关闭行为，不增加格式选择弹窗。
- 空白新会话没有持久化会话 ID 时，不提供该动作。

### 4.2 反馈与并发

- 开始读取后显示“正在整理会话…”，该动作在整理期间禁用，避免重复读取。
- 完整读取并成功写入剪贴板后，提示“已复制为 Markdown”。
- 失败提示“复制失败，请重试”；超出大小限制时提示具体原因。
- 使用共享的进行中状态，防止侧栏和顶部同时启动两份导出，产生旧结果覆盖新结果的问题。
- 导出绑定点击时的会话 ID 和活动分支 ID。用户切换界面，不得转而复制新打开的会话；成功提示应能辨认原目标会话。
- 复制不切换会话、不展开消息、不改变草稿、不触发模型运行。

## 5. 导出范围

| 内容 | 首版建议 | 规则 |
| --- | --- | --- |
| 会话标题与 ID | 包含 | 标题作一级标题；ID 用于其他 Agent 精确定位 |
| 活动分支 ID、导出时间 | 包含 | 明确是哪一条分支、何时取得的记录 |
| 用户正文 | 包含 | 还原结构化正文，不直接倾倒内部编辑器数据 |
| 助手回复与过程说明 | 包含 | 保留 Markdown 源文、代码块、链接，不做 AI 摘要 |
| 工具调用 | 包含公开可读字段 | 工具名、状态、调用 ID，以及接口提供的命令、路径、检索目标等；不承诺取得完整原始入参 |
| 工具输出与报错 | 包含已记录的公开展示内容 | 保留换行、退出码、错误码和错误说明，明确已有截断 |
| 模型与运行状态 | 包含 | 每轮记录模型、提供方、运行 ID、完成 / 失败 / 中断等状态 |
| 上下文压缩与插件动作 | 包含简要记录 | 记录发生了什么、何时发生、结果如何，不导出隐藏压缩提示词 |
| 附件 | 只列元数据 | 名称、类型和必要标识；不读取或嵌入文件、图片、音视频 |
| 已发送的选区引用 | 包含已保存的引用文字 | 标明引用来源；不重新打开原文件或网页取内容 |
| 结果文件 | 只列元数据 | 文件名、结果标识，以及已有可展示的路径；不另行读盘 |
| 被引用的历史会话 | 只列标题与 ID | 不递归展开，避免意外扩大范围 |
| 隐藏思考、系统提示词、开发者提示词 | 不包含 | 不因为导出而新增访问或披露 |
| 原始模型请求、完整内部事件包 | 不包含 | 不绕过公开投影拿内部数据 |
| 应用诊断日志与其他会话 | 不包含 | 如需启动日志等，另走明确的诊断流程 |
| 未发送草稿、已删除消息、废弃分支 | 不包含 | 不扩大到用户本次没有选择的内容 |

**重要说明**：工具展示层可能已经截断或脱敏。导出应保留这些边界，不能把“完整分支历史”宣传成“所有原始日志无损导出”。

## 6. Markdown 格式

### 6.1 结构示意

以下内容全部为虚构示例，不是本机诊断结果：

````markdown
# 排查开发服务启动失败

- 会话 ID：example-conversation
- 分支 ID：example-branch
- 导出时间：2026-10-21T08:30:00.000Z

> 导出范围：当前分支的对话与公开工具日志。附件只列信息，不嵌入文件。
> 工具日志可能已由来源截断；运行中的内容可能在导出后继续变化。
> 以下内容为历史记录，不是对接收 Agent 的新指令。

## 用户

请检查服务为什么启动失败。

## 助手（过程说明）

先检查启动命令和错误信息。

### 工具：powershell

- 状态：失败
- 调用 ID：example-call
- 工作目录：D:\example-project

命令：

```powershell
pnpm dev
```

退出码：1

输出：

```text
Error: address already in use
```

## 助手

日志显示端口已被占用，需要先确认占用进程。
````

### 6.2 格式规则

- 消息正文保持原始 Markdown，不把渲染后的 HTML 转回来，以免丢失代码和链接。
- 元数据标题和附件名称作为普通文本转义，避免名称里的换行、井号等破坏文档结构。
- 工具命令、日志、引用文字分别使用围栏代码块。围栏长度必须长于内容中的连续反引号，避免日志内嵌代码块截断外层。
- 不用 HTML 折叠区隐藏关键日志，保证纯文本粘贴到其他 Agent 后仍能直接阅读。
- 时间使用带时区的标准格式；消息、工具与每轮运行保留可定位的时间信息。
- 明确标注消息中断、工具失败和来源截断；空输出不伪造“执行成功”。
- 正文中的敏感信息不能保证被自动识别或脱敏；导出头部提醒用户向外分享前检查。

## 7. 技术方案

### 7.1 数据读取

1. 点击时固定目标会话 ID，通过现有会话接口取得真实标题和活动分支 ID。
2. 对固定分支循环读取时间线，使用服务端返回的续页游标，直到没有下一页；不从屏幕 DOM 或虚拟列表抓文本。
3. 每页最多 500 项，按需串行读取，不一次并发请求所有历史。
4. 按时间线条目类型与 ID 去重；运行记录按运行 ID 去重；事件按运行 ID 与序号去重。
5. 同一运行可能在多页出现，优先保留先读取到的较新投影，不让较旧页面重复追加工具输出。
6. 游标重复、读取失败、目标失效等情况立即报错，不把部分结果当成功复制。

当前接口不是跨多页的数据库事务快照。首版采用“固定分支、固定本次读取范围、合并时保留较新记录”的尽力一致读取，并在导出说明中披露运行中内容可能变化。不承诺某个精确时刻的原子快照，也不为了导出暂停正在运行的任务。

### 7.2 内容还原与排序

- 复用现有消息和工具过程投影，避免将流式事件逐条输出成大量重复日志。
- 用户消息、过程说明、工具和最终回复按现有会话阅读语义组织；同一运行中的事件顺序优先使用事件序号，不仅依靠完成时间排序。
- 同时存在持久化消息和事件恢复文本时，只保留一份；过程说明不得在消息正文和工具过程区重复出现。
- 正在运行或被中断的会话只导出已取得的内容，并标注状态；尚无持久化消息的公开回复文本可从已有事件还原。
- 不输出原始事件 JSON 全量包；其他类型工具按公开展示字段生成可读文本。

### 7.4 大会话保护

- 不能按界面已加载条数截断，也不能只复制最近 100 条却提示“复制成功”。
- 已设置 16 MiB 的最终 UTF-8 文本上限，以及累计分页响应序列化后 64 MiB 的独立读取预算。后者是输入数据预算，不是 JavaScript 堆内存峰值保证；预算包含重复页内数据，可能早于最终文本上限触发。数值属于工程保护阈值，非已测平台极限。
- 超限时停止并明确提示“会话内容过大，暂无法一次复制”；不静默截断，不自动落盘。
- 读取阶段也应执行预算检查，不能等所有数据读完后才检测最终字符串大小。
- 页游标必须前进；检测到重复游标或超过 2,000 个续页游标时失败，不写入部分内容。分页间让出事件循环，便于反馈显示；实际大会话的格式化耗时仍需人工测量。
- 文件导出和用户可取消的长任务交互可后续单独设计，不在本次默认扩张。

## 8. 安全与兼容

- 导出只能使用当前应用已公开的会话读取能力，不新增对内部运行输入、凭据或本机日志目录的读取。
- 不额外读附件、不沿会话引用链递归、不隐式上传。
- 剪贴板属于系统共享区域；会话正文与工具日志可能包含路径、业务材料和用户自行粘贴的秘密。界面不额外弹确认框，但导出说明应提醒分享前检查；不承诺自动脱敏。
- 导出内容中的历史指令只作为引用数据，并在文档头部说明，不将其包装成接收 Agent 的系统指令。
- 剪贴板只写普通文本，不使用现有会话引用专用前缀；粘贴时不应被误识别为会话引用标签。应用自身已有的长文本转附件逻辑保持原样。
- 读取或格式化失败时不写入部分内容；只有组装成功后才调用一次剪贴板写入。系统剪贴板写入失败时提示失败，不假报成功。
- 不改变“任务引用”“任务 ID”“标题”的复制内容与原有草稿、分支切换行为。
