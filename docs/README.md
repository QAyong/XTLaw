## 文件与术语说明

| 原名称 | 中文含义 | 用途 |
| --- | --- | --- |
| `architecture/` | 架构说明 | 解释运行流程、模块边界和数据位置 |
| `specs/` | 功能规格与决定记录 | 沿用已有编号，不重编号或复用空号 |
| `bugs/` | 缺陷记录 | 记录问题证据、修复及验证情况 |
| `upstream/` | 手动上游集成记录 | 集中保存历史移植与验证记录 |
| `archive/` | 已完成归档 | 已验收的规格、已修复的缺陷、较早的集成记录和已发布的草稿，文件名不变，只读参考 |
| `drafts/` | 文档草稿 | 尚未定稿或发布的材料，不能视为最终决定 |
| `assets/` | 文档资源 | 保存文档引用的图片等材料 |
| `upstream-baseline.json` | 上游集成基线 | 自动化读取的固定文件，保持原路径 |
| `upstream-auto-*-integration.md` | 自动预备报告 | 由现有自动化生成，暂留文档根目录 |

## 归档规则

- `specs/`：状态明确为已验收（或被上游取代）、且没有遗留待办的移入 `archive/specs/`；仍待验收的留在原处。
- `bugs/`：已修复并验收的移入 `archive/bugs/`；未修复、已缓解或待验收的留在原处。
- `upstream/`：只保留最近约一周的集成记录，其余移入 `archive/upstream/`。
- `drafts/`：已发布的发布说明移入 `archive/drafts/`。
- 移动用 `git mv`，不改文件名和编号；用 `git log --follow -- <路径>` 追溯历史。

## 整理边界

- 本次只调整文档归类与链接，没有删除功能规格、缺陷记录或历史结论。
- 手动集成记录集中在子目录；自动报告和基线保留原位置，避免影响现有自动化。
- 草稿目录保持原样，本次未修改其中的内容。
