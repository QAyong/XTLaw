# Spec-038：文件编辑器自动保存

**日期**：2026-10-21

**状态**：已实现；用户于 2026-10-21 明确确认开发预览验收通过，并要求更新文档、提交仓库。类型检查、定向自动化测试与改动文件 ESLint 通过；未打包，安装包未验证。默认开启，文字在前、紧凑开关在后，入口仅在编辑模式显示；验证记录见第 12 节。

**目标**：文件管理器中的每个可编辑文本文件都有“自动保存”开关；复用成熟防抖工具及现有文件保存链路，减少手动保存，同时保留冲突检测、失败反馈和草稿恢复保护。

## 1. 背景与结论

当前 Markdown 预览使用 `markstream-vue`（Markdown 渲染组件），源码编辑使用 `monaco-editor`（文本编辑器内核）。自动保存与更换编辑器无关，本期不引入 Vditor、Milkdown 或其他正文编辑方案。

实施前，编辑会更新 `WorkingCopyService`（文件工作副本服务），但只有手动保存及部分经确认的文件操作会写入原文件。本期已新增延迟自动保存；未保存内容的备份仍不等于原文件已保存。

本期实现：

1. 在每个可编辑文本文件的工具栏增加“自动保存”开关，保留手动保存和 Ctrl+S。
2. 开关默认开启，统一控制当前工作台内的可编辑文本文件，并记住选择。
3. 停止输入 1000 毫秒后自动保存；每个文件独立等待，同一文件不重复调度。
4. 复用现有 VueUse 防抖，不新写定时器框架，不新增依赖。
5. 保存仍只调用现有 `WorkingCopyService.save()`（保存工作副本的方法）；不绕过授权、版本校验和冲突处理。
6. 在保存失败、冲突、恢复草稿等待确认及关闭确认期间暂停相应文件，不能靠后台自动重试掩盖风险。

### 1.1 设置范围的准确说明

前期讨论中的“工作区共用”在本方案中明确为**当前工作台共用，而不是按空间分别设置**。

现有 `ConfigurationService`（工作台配置服务）与 `WorkbenchPersistence`（工作台状态持久化服务）不是按文件空间分别保存配置。同一工作台可以打开多个空间的文件；开启后，这些空间中已打开且符合条件的文本工作副本都受影响。

开关提示如实说明这一点，不写“仅当前空间”。不承诺多窗口之间即时同步设置。用户调整默认值和 UI 排列后要求实施，本期按上述工作台作用域落地；如果后续要求按空间独立控制，需要另行调整配置键与作用域，不暗中扩大本期范围。

## 2. 需求边界

### 2.1 包含

- 通过当前文件编辑器打开的可编辑文本资源，包括 Markdown、纯文本、代码等；以已有文件打开与可写能力为准，不另建扩展名白名单。
- 在预览、源码、编辑模式之间切换时保留相同设置；已修改内容不会因为切换模式而丢失待保存任务。
- 自动保存开关、等待/保存中/已保存/暂停/失败反馈。
- 多文件独立防抖，同一工作副本多视图共用调度与状态。
- 保存过程中继续编辑时，对最新修改补存。
- 与恢复草稿、关闭确认、文件移动/重命名/删除、资源释放和工作台退出协调。
- 中文与英文文案、键盘操作、可访问名称和现有主题适配。

### 2.2 不包含

- 更换 Monaco、增加 Markdown 所见即所得编辑或分屏实时预览。
- Office、插件自带编辑器、会话输入框、设置表单的自动保存。
- 图片、音视频、历史版本及其他只读预览资源的写入。
- 定时扫描整个目录、自动保存从未打开的文件。
- 自动格式化、整理 Markdown、调整换行符/编码；继续沿用现有文本读写契约，不新增保真承诺。
- 云同步、跨进程/多窗口协同编辑、自动合并外部冲突。
- 修改底层文件写入原子性、原生文件系统实现、授权协议或数据库迁移。
- 第一版的延迟设置面板、失焦保存模式、最长等待强制保存、每文件覆盖设置。

## 4. 现成方案选择

### 4.1 采用 VueUse，不新增依赖

使用 `useDebounceFn()`（延迟执行并合并连续调用的现成函数）：

- 1000 毫秒尾沿防抖：最后一次内容编辑后开始计时。
- `cancel()`：关闭开关、释放资源、进入保护或销毁时取消尚未开始的任务。
- `isPending`：判断是否存在等待触发的任务；不把它当作磁盘写入是否完成的依据。
- `flush()`：必要时立即触发待执行动作；调用它不等于工作副本最新内容已经保存，仍须核对保存结果及版本。

第一版不配置 `maxWait`（最长等待强制执行）：用户一直连续输入、没有达到 1 秒停顿时，不强制写盘；原有草稿备份继续运行。此规则应与提示文案一致。

VueUse 负责“何时触发”，不负责文件保存串行化、冲突处理或工作副本生命周期。

### 4.2 `p-debounce` 作为备选，不与现有队列重复叠加

`p-debounce`（支持异步函数的防抖库）官方有自动保存组合：普通防抖加 `pDebounce.promise(fn, { after: true })`（串行运行，并为保存期间的新调用补一次最新执行）。

本项目已有同一文件保存去重和版本状态，第一版不再增加独立写入队列。需要接好的缺口是：**现有保存去重只返回进行中的保存请求，并不保证自动再保存最新版本**。适配层必须在完成后检查并补存，不能把“去重”当成完整自动保存。

若实施阶段发现现有保存入口无法保持单一写入所有者，应先修正方案，不直接并列引入第二套保存机制。

### 4.3 官方参考

- [VueUse：useDebounceFn](https://vueuse.org/shared/useDebounceFn/)：防抖、取消、立即执行及等待状态。
- [p-debounce：自动保存范例](https://github.com/sindresorhus/p-debounce#autosave)：防抖与异步串行保存的组合。
- [VS Code：保存与自动保存](https://code.visualstudio.com/docs/editing/codebasics#_save-auto-save)：开关、延迟保存及默认 1000 毫秒的产品行为参考。
- [Monaco：组件定位及公开接口](https://github.com/microsoft/monaco-editor)：编辑器内核不等于 VS Code 完整工作台；本方案不依赖未核实的 Monaco 自动保存插件。

## 5. 交互设计

### 5.1 入口与布局

示意，不是运行截图：

```text
文件名 / 路径        [预览｜源码｜编辑]    自动保存 [开关]  [保存]
```

- 复用工具栏 `actions` 插槽与 `NSwitch`，文字在前、开关在后。通过组件主题参数将轨道从原小号的 32×18 像素缩为 26×14 像素，滑块为 10×10 像素，保留 22 像素高的点击区域；不新增大型设置面板或独立悬浮控件。
- 按用户修改默认开启。旧配置没有该键时也采用开启；已有显式关闭选择则继续关闭。启动恢复的未保存草稿仍暂停，不能因默认开启而静默写回。
- 仅在可写文本文件的“编辑”模式显示“自动保存”文字和开关；预览、源码模式隐藏该入口。模式切换不改变全局设置，也不取消已安排的后台保存。
- 纯只读预览页不显示可操作的开关。正在加载的编辑页可以显示禁用入口；临时文件操作保护不应把全局开关伪装成关闭。
- 同一工作台内所有入口同步。开关不是“当前文件已保存”的标志。
- 提示文案：“停止输入 1 秒后自动保存，适用于本工作台所有已打开的可编辑文本文件（包括其他空间）。”
- 自动保存开关与旁边的“保存”按钮配合：关闭时取消待触发任务、保留未保存修改，通过按钮或 Ctrl+S 手动保存；无修改时按钮置灰，有可保存修改时启用。开启时仍可手动立即保存，不必等待防抖。保存进行中、加载、冲突或文件操作保护期间保持原有禁用规则，不接管手动保存快捷键。
- 可见标签与开关使用程序化关联，支持键盘切换，不能只依靠颜色表达状态。
- 窄面板优先截断文件名，保留开关和手动保存；极窄宽度允许操作区换行，必要时调整工具栏高度，不裁掉控件或产生页面横向溢出。

### 5.2 底部状态与异常反馈

| 条件 | 中文建议文案 | 规则 |
| --- | --- | --- |
| 关闭自动保存且有修改 | 未保存 · UTF-8 | 保留原有含义 |
| 等待防抖触发 | 等待自动保存… · UTF-8 | 不提示已保存 |
| 正在写入 | 正在保存… · UTF-8 | 必须读取工作副本的真实保存状态 |
| 最新内容已写入 | 已保存 · UTF-8 | 仅当 `dirty === false` 且没有保存错误或冲突 |
| 保存中又有修改 | 正在保存，仍有新修改… | 本次完成不能错误标为全部已保存 |
| 外部版本冲突 | 自动保存已暂停：文件在外部被修改 | 使用已有版本比较与选择入口 |
| 保存失败 | 自动保存失败，修改尚未写入文件 | 提供“重试”，不展示成功提示 |
| 恢复草稿待确认 | 已恢复未保存修改，自动保存已暂停 | 提供“保存并恢复自动保存”，同时保留手动保存和原有版本处理 |
| 文件操作保护中 | 文件操作中，自动保存暂缓 | 保持全局开关的实际值 |

状态栏在有修改、正在保存或存在暂停/失败原因时必须可见，不能因切换到预览模式消失。干净状态沿用现有轻量展示，不为每次成功弹通知。错误使用就近反馈，不逐秒弹窗；中英文状态完整对应，不能复用“视图加载失败”描述保存错误。

## 6. 配置与调度设计

### 6.1 配置

拟注册 `files.autoSave`（工作台自动保存模式配置）：

- 可选值只有 `'off'`（关闭）和 `'afterDelay'`（停止编辑后保存）。
- 默认 `'afterDelay'`；开关映射这两个值，不增加未实现的失焦模式。
- 固定 1000 毫秒，第一版不增加延迟配置键或设置页。
- 通过已有配置快照持久化，不写浏览器独立缓存，不新增数据库迁移。
- 开启时，对本次运行中正常编辑、未处于暂停状态的未保存工作副本安排保存；恢复草稿不在此范围内。
- 关闭时立即取消全部待触发任务。已经进入现有保存接口的写入允许完成，不宣称可以撤销；完成后不自动补存新修改。

### 6.2 装配位置与单一所有者

拟新增 `apps/buddy/src/app/workbench/WorkingCopyAutoSave.ts`（工作台自动保存适配层）。放在应用装配层，避免将 VueUse 依赖引入原本独立于界面框架的工作副本核心服务。

由 `useDesktopWorkbench.ts` 创建一份实例，订阅工作副本与配置；每个工作副本身份维护一个防抖执行器及必要的暂停原因。不在每个 Vue 编辑组件内创建任务。

- 标识使用 `key`（含授权版本等信息的资源键）和 `incarnation`（工作副本实例标识）；不能只按文件名或相对路径分组。
- 每次触发前重新获取当前副本；不缓存旧正文、旧路径、旧授权参数作为写入目标。
- 多视图共享同一任务，切换编辑模式不影响任务寿命。
- 不做全局单线程写入队列；不同文件可独立保存，同一文件继续由现有服务协调。
- UI 通过窄接口读取开关、文件状态并触发重试；不向组件暴露定时器或可变任务集合。

拟通过 `workbenchContext.ts`（工作台组件上下文）和 `WorkbenchHost.vue`（工作台宿主组件）的既有注入链路提供窄接口；具体类型放在工作台侧公共契约中，避免核心上下文反向依赖应用装配实现。

### 6.3 允许自动写入的条件

每次实际触发前必须同时满足：

1. 工作台已完成恢复，适配层未停止，配置仍开启。
2. 资源属于现有可编辑文件链路，当前副本及其实例身份仍存在。
3. 有未保存修改，已加载且有有效版本标识 `etag`（读写冲突检查依据）。
4. 不处于加载、文件操作保护或关闭确认期间。
5. 没有冲突、读写错误、恢复确认暂停或失败暂停。
6. 未被新的目录授权版本或资源迁移替换。

实际保存使用默认保护检查，**禁止传入 `allowBlocked = true`**（绕过文件操作保护的选项）。前端判断只减少无效调用，最终授权和版本校验仍以现有可信保存链路为准。

### 6.4 正常流程与保存中继续编辑

```text
用户修改内容
  → 工作副本内容版本增加
  → 当前文件的现成防抖函数重新等待 1000 毫秒
  → 重新检查身份、配置、暂停原因与可写状态
  → 调用现有保存入口
  → 检查返回结果和最新工作副本
      → 最新内容无未保存修改：显示已保存
      → 保存期间又有修改：保持未保存，按最近一次编辑的等待条件补存
      → 失败或冲突：暂停此文件，保留内容并提示
```

具体竞争约束：

- 只由真实内容编辑重置等待时间；光标、滚动、主题、布局和保存开始通知不重新计时。
- 若防抖触发时同一文件正在手动或自动保存，等待该次保存结束后重新评估，不循环快速调用，不另建并行写入。
- 最近一次编辑尚未停满 1 秒时继续等待；已经停满且上次写入已完成时，可以开始下一次保存。
- `saved`（某次请求成功）不等于最新版本已保存。以最新 `dirty`、内容版本及 `dirtyAfter`（请求完成后是否仍有修改）为准。
- 手动保存完成后，若最新副本已干净，取消剩余待执行任务；若仍有新修改，自动保存继续遵守上述规则。
- 无变化、失败、冲突及资源不可用等保存返回分支均显式处理；捕获异步错误，避免未处理的 Promise 拒绝。

## 7. 暂停、恢复与生命周期

### 7.1 保存失败与外部冲突

- 失败后暂停该文件，不因下一次编辑或开关反复切换而偷偷恢复写入，不建立无限重试计时器；其他正常文件继续保存。
- 用户点击“重试”或手动保存后，按实际结果解除或保持暂停。失败时继续保留修改与既有备份，不把“有备份”当成“绝不丢失”的保证。
- 外部冲突沿用已有比较和“采用磁盘版本 / 保留我的更改”操作，不自动择一。
- 采用磁盘版本后，按当前副本状态重新计算；保留本地更改是明确选择，清除冲突后允许按开启状态安排保存。
- 文件被外部删除、权限撤销或加载失败时不创建替代空文件，不绕过授权重开目标；待现有文件流程恢复后再由用户确认重试。

### 7.2 启动恢复与未保存草稿

- 先订阅恢复事件以识别 `restored`（从备份恢复）副本，但在 `persistence.restore()` 与工作台初始化完成前禁止自动保存。
- 恢复副本以 `incarnation` 记录“等待用户确认”，即使磁盘校验发现版本未变化，也不因加载完成或全局开关已开启而静默写回。
- 在等待确认期间继续编辑，暂停标记仍保留；开启/关闭开关不能清除该标记。
- 用户主动点击“保存并恢复自动保存”或手动保存，且成功保存全部当前修改后才解除暂停；如仍有新修改，明确的恢复动作可授权继续按规则补存。
- 若存在外部冲突，先走冲突选择。放弃恢复内容则走现有丢弃流程，取消待保存任务，不将丢弃前的旧文本写回。

### 7.3 文件关闭

- 正常切换文件或隐藏预览不是关闭，不取消任务。
- 文件仍有修改且需要弹出关闭确认时，立即取消待执行任务并暂停该资源；不能在用户选择“放弃”之前由后台计时器抢先保存。
- 若先前已有写入在执行，按现有关闭保护等待其结果并重新检查状态；不能撤销已提交写入，也不能声称“放弃”可恢复此前磁盘内容。
- 用户选择“保存”时走现有保存及版本验证；失败或仍有修改不得误关。
- 用户选择“不保存”时，维持暂停直到丢弃及关闭完成；用户取消关闭时解除关闭原因的暂停，其他失败/冲突/恢复暂停仍保留。
- 关闭回调与多视图保留遵循现有工作台语义；不因销毁一个视图而销毁仍被其他视图使用的副本任务。

### 7.4 文件操作与资源迁移

- `blocked`（文件操作保护）生效时取消该文件待触发任务，不保存；既有进行中保存由文件操作服务等待收敛。
- 重命名或移动时取消旧资源执行器，按同一 `incarnation` 迁移暂停原因，后续只用最新资源参数调度。
- 删除、释放或新实例替换后清除旧任务；异步完成结果不得恢复旧路径任务，也不能写入同键的新实例。
- 保护解除后，仅对仍存在、未暂停且有修改的副本重新安排一次保存。

### 7.5 工作台退出

- 开始销毁时先停止适配层接收新调度并取消防抖任务，再按既有流程等待正在进行的保存和文件操作。
- 沿用现有 `copies.stop()`、工作台持久化与备份收尾，不在卸载阶段新发起“最后一次强制自动保存”。
- 待保存内容必须仍进入已有草稿备份收尾；备份失败明确报告，不标为写盘成功。
- 移除全部监听，异步保存完成后的回调不得重新建任务。不要把防抖 `flush()` 当成工作台退出或最新版本保存完成的替代方案。

## 10. 风险、回退与实施决定

### 10.1 风险与回退

- 自动保存是真实写盘，不等于自动备份；不能把关闭文件时的“不保存”解释为撤销之前已完成的保存。
- 设置开启会影响其他空间的已打开文本文件，因此作用域必须清晰可见。
- 本期不新增自动格式化或底层写入保证，依赖现有保存链路；跨窗口同时编辑仍可能产生冲突，应保留提示。
- 调度层不应成为新的存储所有者。临时回退可将开关关闭，继续使用原手动保存；退出功能实现时保留原草稿备份及文件冲突处理。

### 10.2 本期实施决定

用户修改默认值和 UI 排列后要求实施，本期按以下规则落地：

1. **作用范围**：按当前工作台统一控制，包括同一工作台中其他空间的已打开文本文件，而不是每空间独立。
2. **初始与延迟**：默认开启，停止输入 1 秒保存；第一版不提供更多模式。“自动保存”文字在开关前，开关使用紧凑尺寸，右侧保留手动保存。
3. **异常策略**：失败和恢复草稿须显式处理；关闭确认期间暂停，不自动替用户决定。

目前没有阻塞交付的未决产品选项；用户已确认开发预览通过。安装包及第 12.3 节列出的专项验证不在本次验收结论中。
